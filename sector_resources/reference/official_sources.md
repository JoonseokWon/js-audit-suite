# JS 업종별 감사 검토 설계와 공식 출처

확인일: 2026-10-23  
대상: JS전자·JS자동차·JS반도체·JS바이오의 별도 합성업무  
연결 설계: `sector_audit_checks.json` (`js-sector-audit-design-1`) / 확정 명칭: `sector_profiles.json`

## 이 자료의 사용 범위

4개 업종마다 5개씩, 총 20개 검토주제를 정리했다. 각 주제에는 필요한 자료와 필드, 회사코드를 포함한 연결키, 검토할 위험, 수동 절차, 기존 조서 ID와 공식 출처를 붙였다. 여기의 “필요자료”는 자료요청 설계다. 해당 자료를 이미 수령했거나 추가 절차를 수행했다는 뜻이 아니다.

현재 자료는 같은 검사용 모본의 금액·수량·일자·단위·계산 정책을 유지하고, 업종별 품목·자산·거래 맥락을 달리 만든 축소 합성자료다. 회사명 때문에 실제 완성차 제조, 반도체 팹, 상업의약품 제조·임상, 위탁개발 계약, 자체 연구개발을 보유한 것으로 해석하지 않는다. 해당 활동·계약이 실제 존재하는지 확인한 뒤 조건부 주제를 적용한다.

JS는 모회사 표시용 코드이고 업종별 업무 코드는 JS_ELEC·JS_AUTO·JS_SEMI·JS_BIO다. 지분율·투자관계·내부거래·연결제거는 설정되지 않았다. 회사별 데이터를 합쳐 연결재무제표 또는 그룹 합계로 표시하지 않는다.

- JS바이오의 현재 상품은 연구용 시약·배지다. 의약품 허가·임상 결과·GMP 적합성을 확인한 자료가 아니다. CDO/CDMO 수익인식과 개발비 인식은 실제 계약·프로젝트 자료가 있을 때 수동 검토한다.

IFRS 기준은 공개 About 요약을 확인했다. 로그인·구독이 필요한 기준 전문이나 현행 한국채택국제회계기준 전체를 확인·재배포한 것으로 표시하지 않는다. 공식 공개 요약으로 확인한 회계 주제와, 프로젝트가 제안하는 세부 감사절차는 구분한다. 예를 들어 IAS 2의 원가·NRV 비교를 참고해 후속판매와 재고상태 자료를 요청하도록 설계했지만, 이 절차 목록 전체가 기준서의 원문 체크리스트라는 뜻은 아니다.

삼성전자 2025 연결재무제표는 공개 PDF의 해당 주석을 업종 사례로 참조했다. 이 출처가 연결재무제표라는 사실은 JS에 연결구조나 연결계산을 도입하는 근거가 아니다. 현대자동차의 보증·제조 소개, SK하이닉스의 계측·검사 소개, 삼성바이오로직스의 서비스 소개도 JS의 실제 권리·기술·생산능력·규제 적합성을 입증하지 않는다.

이 문서는 현행 한국감사기준 전문을 검토해 모든 필수 절차를 충족했다는 확인서가 아니다. 실제 업무의 중요성·위험평가·표본·필요한 증거 및 해당 회계기준 문단 적용은 담당 회계사가 확인해야 한다.

## 자료와 조서를 연결할 때

1. 실제 해당 거래·자산·계약이 있는지 먼저 확인하고, 적용할 회사·기간·단위·모집단을 고정한다.
2. 요청 자료의 추출 조건·행 수·합계·작성자·추출시각과 원문을 보관한다. 같은 생성기에서 만든 원장과 명세가 일치하는 것만으로 독립적인 완전성 증거를 확보했다고 하지 않는다.
3. 회사코드·품목/자산/계약/로트 ID·전표 ID 등을 이용해 연결하고, 누락·중복·미일치와 미지원 조건을 남긴다. 요청 필드를 기존 앱 시트·헤더에 임의 추가하면 자동으로 처리되는 것은 아니다.
4. JSON의 `workpaper_id`와 `additional_workpaper_ids`를 이용해 기존 조서에 검토 범위·위험·자료요청을 넣는다. 계획 JSON을 실제 수행증거로 표시하지 않는다.
5. 실제 수행 내용·근거·판단·수정분개 필요성과 결론은 사람이 작성한다. 검토와 승인은 검토자가 직접 남긴다.

모든 주제의 초기 상태는 “계획·미검토”이며 `actually_performed: false`, `automatic_industry_judgment: false`다. 작성자·수행 내용·검토자·결론은 비워 두고 조정 승인도 하지 않는다. 필요한 자료가 없으면 “미수령/미확인”으로 유지하고 추가 요청한다. 빈값을 0·정상·수행완료로 바꾸지 않는다.
