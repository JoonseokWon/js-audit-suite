# 업종별 회사 선택 사용안내 — v1.6

이 안내는 내장 합성자료로 회사별 감사 연습을 시작하고 기록을 보존하는 방법을 설명한다. JS·JS전자·JS자동차·JS반도체·JS바이오는 각각 별도 합성업무다. 실제 회사 감사나 연결재무제표를 자동 완성하는 프로그램이 아니다.

## 1. 처음 시작하기

배포 압축파일을 모두 풀고 v1.6 EXE를 실행한다. 소스 이용자는 필요한 패키지를 설치한 뒤 `python app.py`를 실행한다. EXE에 Python이 필요한지와 실행 확인 상태는 해당 배포 기록을 따른다.

도구 모음 아래 **업종 더미회사**에서 연습할 회사를 고른다. 선택하면 처음 사용하는 회사는 내장자료로 새 합성업무를 준비하고, 저장한 연습이 있는 회사는 최근 업무를 다시 연다. 원장과 모듈을 읽고 계산하는 동안에는 완료 안내를 기다린다. 회사별 업무 경로와 실제 회사명·회사코드·기간이 표시되는지 확인한다.

| 표시 회사 | 회사코드 | 자료의 사업 맥락 |
| --- | --- | --- |
| JS | JS | 공통 장비·부품 |
| JS전자 | JS_ELEC | 전자부품·소재 |
| JS자동차 | JS_AUTO | 자동차부품·가공소재 |
| JS반도체 | JS_SEMI | 검사용 합성 반도체·공정소재 |
| JS바이오 | JS_BIO | 연구용 시약·배지 |

회사 이름만 바꾼 데이터가 아니라 해당 회사의 품목·자산·거래처·부서·적요를 입력·원문·조서 계획에 일관되게 연결한 자료다. 다만 검사를 재현하기 위해 동일 모본의 축소 금액·수량·날짜·단위·계산정책은 유지한다. 실제 시장가격·원가구조·생산능력을 추정한 데이터가 아니다.

준비·검사 중에는 입력 화면과 회사 선택·새 연습이 잠긴다. 중단하려면 회사 선택 옆 **준비 취소**를 누르고 중단 안내를 기다린다. 준비를 마친 뒤 실제 업무를 교체하므로 실패·취소 때 기존 업무를 유지한다. 처음 실행이라 아직 업무가 없으면 회사 선택 대기 상태로 남는다.

처음 준비하는 데 실패하면 상태와 오류 내용을 확인한다. 실패한 업무를 검사가 끝난 연습으로 간주하지 않는다. 기존 업무 기록을 지우거나 내장자료를 직접 수정해서 해결하지 않는다. 프로그램 종료를 누른 경우에는 취소·기록 처리 후 창이 닫힐 때까지 기다린다.

## 2. 저장한 회사 연습과 새 연습

회사 선택은 저장한 해당 회사의 최근 연습으로 돌아갈 때도 사용한다. 저장된 업무의 기록과 결과를 이어서 확인하고, 처음부터 반복하고 싶을 때만 선택상자 옆의 **새 연습**을 누른다. 고유한 새 폴더를 사용하므로 이전 조서·요청·검토기록을 덮어쓰지 않는다. 그보다 이전의 연습은 **업무 열기**에서 해당 업무 폴더를 선택해 연다.

회사 변경 전에 작성 중인 조서가 있으면 저장 여부를 확인한다.

| 선택 | 동작과 확인할 점 |
| --- | --- |
| 저장 후 이동 | 현재 회사의 조서에 저장한 뒤 이동한다. 새 회사에 이전 회사의 내용을 저장하지 않는다. |
| 저장하지 않고 이동 | 화면에서 바꾼 미저장 내용을 버린다. 이미 저장한 과거 기록을 삭제하는 뜻은 아니다. |
| 취소 | 현재 회사·업무에서 계속 작업한다. 회사 선택 표시도 현재 업무와 같아야 한다. |

자료요청 입력폼도 미저장 내용이 있으면 저장·버리기·취소를 확인한다. 아직 검토기록으로 저장하지 않은 검토자·검토내용이 있으면 그 입력을 버리고 이동할지 별도로 확인한다. 검토를 기록하려면 이동을 취소하고 해당 검토 버튼으로 먼저 저장한다. 회사 전환은 작성 내용을 자동으로 검토 완료하거나 증거를 다른 회사에 복사하는 기능이 아니다.

화면 상단의 회사와 업무 경로가 의도한 것인지 매번 확인한다. 일반 **업무 열기**로 다른 업무를 열었다면 선택상자보다 실제 업무 정보가 기준이다. 같은 회사의 여러 연습도 서로 다른 폴더·업무 이력을 가지므로 검토 대상 폴더를 확인한다.

## 3. 준비한 업무에서 볼 화면

| 원장·리드 | 시산표·원장·리드, 승인조정 표시, 모듈과 현재 원장의 연결 |

| 검토후보 | 규칙에 걸린 거래의 조건·원문·후속 확인과 관련 조서 |

검토후보가 있어도 계산과 원장 연결이 정상일 수 있다. 주말·월말·같은 구성의 반복은 정상 결산과 정기 거래에서도 나타난다. 후보를 없애는 것이 목표가 아니라, 해당 조건과 정상 사유·예외 원인을 원문으로 조사하는 것이 목표다.

## 5. 업종별 검토계획

4개 업종별 5개씩 총 20개 주제와 60개 요청문서 템플릿을 계획 JSON과 조서에 연결한다. 실제 자료요청 기록을 자동 저장·발송·수령 처리하지 않으므로 처음 준비한 업무에 60건의 요청이 저장돼 있는 것은 아니다. JS 공통 회사에 별도의 산업 판단을 수행한 것처럼 표시하지 않는다. 업종별 5주제·15문서 설계는 관련 기존 조서에 모아서 연결할 수 있다.

| 회사 | 검토주제 예시 | 관련 조서 |
| --- | --- | --- |
| JS전자 | 상품 진부화/사용기한·NRV, 출고/반품, 보증, 장비 상각, 실제 전자설계 R&D | A11·A04·A19·A12·A13 |
| JS자동차 | 부품/소재 NRV, 부품 보증/클레임, 부품매출, 장비/실제 금형, 실제 제어기술 R&D | A11·A19·A04·A12·A13 |
| JS반도체 | 조건부 제조 수율/공정재고, 검사용 상품 NRV, 검사장비/손상징후, 검수조건, 실제 설계 R&D | A11·A12·A14·A04·A13 |
| JS바이오 | 시약/배지 사용기한·보관, 조건부 위탁개발 수익, 실제 R&D, 장비 상각, 외주 용역 귀속 | A11·A05·A04·A13·A14·A12·A09 |

기존 수치 기능과 일부 연결되는 주제는 12개, 전용 자동 계산이 없는 수동계획은 8개다. 후자의 보증·리콜·수율·공정재고·개발비 인식·CDO/CDMO 판단을 자동으로 계산했다고 표시하지 않는다. 실제 활동·계약이 없으면 적용 여부부터 검토하고 그 사유를 기록한다.

JS반도체의 상품은 **패키지반도체(검사용 합성품)**다. 자체 메모리 제조나 실제 팹·웨이퍼 생산 자료가 아니므로 상품 검사 수량으로 제조 수율을 만들지 않는다. JS바이오는 **연구용시약키트·연구용분말배지**를 취급하는 시나리오이며 상업의약품·임상시험·허가 또는 GMP 적합성을 입증하지 않는다.

품목/자산/계약/로트 ID와 회사코드 등을 이용해 추가 자료를 연결한다. 필요한 로트·사용기한·온도·BOM·수율·프로젝트 입증자료는 향후 요청 대상일 수 있으며 현재 모두 받은 자료가 아니다. 기준·업종 출처는 공개 1차 자료를 참고한 자체 설계다. 현행 한국채택기준서 전문 확인이나 감사기준 준수 인증을 뜻하지 않는다.

## 6. 검토후보에서 증빙과 조서로

**검토후보**에서 한 행을 선택해 규칙 ID·버전·설정·원본행·후속 절차를 읽는다. **관련 조서 열기**로 이동하면 GLA는 G01, FIA는 I01, 현금분석은 H01에 연결된다. 실제로 확인한 자료, 검토 범위와 결과, 정상 사유나 예외 원인, 필요한 추가 절차를 직접 작성한다.

**자료요청 초안**은 요청 화면에 내용을 채운다. 요청처·기한·요청범위를 확인하고 **요청·수령 기록 저장**을 눌러야 기록된다. 버튼을 누르는 것만으로 외부에 메일을 발송하거나 자료를 받은 것으로 처리하지 않는다.

받은 원문은 **증거 파일 등록**으로 보존하고 해당 요청에 연결한다. 요청 상태는 요청·부분수령·수령·검토완료·취소로 관리한다. 수령 관련 상태에는 등록한 증거를 연결하고 취소할 때도 이유를 기록한다. 원래 분석 입력은 검토대상 근거이며 새로 받은 추가 증거와 구분한다.

원장·입력자료가 바뀌면 현재 연결을 다시 검사한다. **차단/재실행 필요**인 결과와 이전 조서 검토기록을 최신 결과처럼 사용하지 않는다. 관련 분석을 다시 실행하고 수행내용·조서를 다시 저장·검토한다. 다른 회사의 증거·요청·후보는 현재 회사에 섞지 않는다.

## 7. 조서 작성·검토·출력

업종계획이나 자동 계산 범위는 조서의 시작점이다. 실제 수행·결론·검토를 한 것으로 자동 채우지 않는다.

1. 작성자·실제 수행일·범위·수행내용·판단·결론과 실제 근거를 기록한다.
2. **조서 저장·개정**으로 저장한다.
3. 검토할 준비가 됐으면 **검토 요청**을 한다.
4. 작성자와 다른 검토자가 증거·범위를 확인하고 보완 의견 또는 **검토기록 완료**를 남긴다.
5. **검토중 저장** 또는 요건을 충족한 **검토완료본**으로 Excel을 출력한다.

차단 오류, 현재 원장 연결 미확인, 필수 조서 누락, 미완료 자료요청, 미해결 검토의견, 자료 변경 후 재검토가 남으면 검토완료본 출력이 차단될 수 있다. 이름 입력은 인증된 전자서명이 아니며 출력 상태가 전체 감사완료·감사의견 발행을 뜻하지 않는다.

처음 준비한 업종별 조서는 수행내용·결론·검토자가 비어 있는 미검토 초안이다. 조건부 수동계획만 추가돼 있다는 이유로 검토완료본 출력을 허용하지 않는다.

## 8. 기록 보관·백업·복구

실제 기록은 화면에 표시한 업무 경로에 있다. 기본 보관 위치는 `%LOCALAPPDATA%\JSAudit\sector-demos\v1.6`이다. Windows 파일 탐색기의 주소창에 이 경로를 넣어 보관 폴더를 열 수 있다. 내장자료·앱 실행파일의 위치와 사용자가 작업한 업무 폴더를 구분한다. 앱을 닫거나 다른 회사를 선택해도 이미 저장한 기록은 해당 폴더에 남는다.

회사 선택의 최근 연습 목록과 모든 연습을 보존하려면 기본 보관 위치 전체를 백업한다. 여기에는 `store.json`과 `companies/` 아래 회사별 고유 연습 폴더가 있다. 연습 폴더의 `session.json`, 입력·메타자료, `업무/`를 함께 유지한다. `store.json`의 경로나 ID를 직접 편집하지 않는다.

개별 업무를 옮길 때도 업무 폴더 전체를 백업한다. 특히 `업무.sqlite3`, `이력헤드.json`, `원본/`은 함께 보존한다. 이미 저장한 Excel 조서만으로 업무 DB·원문·이력 전체를 복구하는 것은 아니다. 입력과 조서를 바꾸면 Excel을 새로 출력한다. 다른 위치로 옮긴 개별 업무는 **업무 열기**로 열 수 있지만, 그것만으로 회사 선택의 최근 연습 목록에 자동 등록되는 것은 아니다.

다른 PC로 옮길 때도 전체 업무 폴더를 복사하고 **업무 열기**에서 연다. 파일 누락·변조·DB/헤드 불일치 또는 회사코드 불일치가 보이면 열기를 차단한다. 원본을 보존하고 오류 내용을 확인한다. 프로그램이 기존 기록을 조용히 초기화하지 않는다. 사용자가 **새 연습**을 선택하면 별도 업무를 만들 수 있지만 과거 기록이 복구되는 것은 아니다. 누락된 파일을 임의로 만들거나 손상된 업무를 새 연습으로 덮어쓰지 않는다.

회사가 잘못 선택됐거나 이전 자료가 보이면 상단 실제 회사코드·업무 경로부터 확인한다. 같은 회사의 새 연습은 이전 연습의 대체가 아니라 별도 기록이다.

## 9. 일반 자료 입력과 기존 연습

상단 **새 업무**는 직접 회사·기간을 등록하는 일반 업무다. 먼저 원장·리드를 실행하고 해당 회사·기간·원장과 일관된 입력을 등록한다. 바로 등록할 수 있는 입력은 모듈에 맞는 XLSX, 재무제표 JSON, 원천증빙 `.auditpack`, 독립 계정 증빙 JSON 등이다.

GLA·FIA·현금 입력은 원장 공통 7시트와 모듈 전용 시트를 함께 갖춘 XLSX다. 분해한 ERP 로그나 은행파일 하나를 그 자체로 전체 분석 입력으로 넣는 형식은 아니다. 상세 헤더·정책·제약은 [GLA·FIA·현금 사용안내](GLA_FIA_현금_사용안내.md)와 [기존 모듈 사용안내](사용안내.md)를 확인한다.

**자료 복사**에서 위치를 고르면 `통합감사_v1.6_입력자료` 폴더를 만들고 입력양식·더미자료·분석원천자료·업종별자료·사용안내를 복사한다. 같은 이름의 폴더가 있으면 다른 위치를 선택한다. 이 기능은 내장 참고자료를 복사하며 사용자가 저장한 회사별 업무를 백업하는 기능은 아니다.

**계정별 증빙연습**의 9개 계정군·33개 사례는 별도 독립 연습이다. 이를 회사별 통합업무 TB에 합산하지 않는다. 기존 버전의 업무를 열어 볼 때는 원본을 백업하고 실제 회사·자료·결과를 확인한다.

## 10. 검증 기록과 포트폴리오 설명

v1.6 소스의 화면 없는 회귀 검사는 기존 332개 파일 사례·1,949개 확인 항목과 업종별 1,343개 확인 항목을 통과했다. 업종 검사는 5개 회사의 75개 모듈 실행, 175개 현재 원장 대사 일치, 다른 회사 자료 혼합 120개 차단을 포함한다. 상세 기록은 `검증/headless_1/report.json`과 그 아래 `sectors/headless_sectors.json`이다. 회사 연습 생성·재열기 단위 검사 24개도 통과했으며 `sector_verification/unit_tests.json`에 있다.

처음 생성한 조서 초안 수는 JS 46개, JS전자·JS자동차·JS반도체 각 48개, JS바이오 49개다. 실제 수행·결론·검토가 끝난 수치가 아니다. 회사 재선택 시 업무 ID·저장 이력·파일이 유지되는지, 원본·미검토 상태와 검토완료본 차단도 확인했다. 이 수치는 실제 화면이나 EXE에서 확인한 건수가 아니다.

전체 단위 검사, 실제 회사 선택·미저장 처리·준비 취소·입력잠금의 소스 UI 결과, EXE 용량·SHA256·독립 실행 결과는 최종 배포의 `검증/` 및 빌드 기록을 확인한다. 소스, EXE, 다른 PC, 원격 CI는 서로 다른 검증 범위다. 소스 검사만으로 다른 PC의 EXE 실행까지 확인했다고 표현하지 않는다.

소스에서 화면 없는 검사를 재현하려면 프로젝트 폴더에서 다음을 실행한다. 출력은 새 폴더 또는 빈 폴더를 사용한다.

```powershell
python -m unittest discover -v
python tools/verify_headless_v16.py --output-dir 검증/직접재현_v16_headless
```

원격 결과와 게시 상태는 해당 태그의 [GitHub Actions](https://github.com/JoonseokWon/for-ax-node-project/actions) 및 [v1.6.0 릴리스 기록](https://github.com/JoonseokWon/for-ax-node-project/releases/tag/audit-suite-v1.6.0)을 확인한다. 비공개 저장소는 접근 권한이 필요하다.

포트폴리오에서는 “회계 요구사항과 검증 관점을 직접 설계하고 AI의 도움으로 구현한 로컬 감사 지원 프로그램”으로 설명할 수 있다. 합성 입력의 수치·원장·증빙 연결과 검토 흐름을 보여 주되, 실제 고객자료 검증·감사의견·업종 전체 판단을 자동 수행했다는 표현은 사용하지 않는다.
