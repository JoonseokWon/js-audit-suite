# v1.8 — 근거 기반 AI 조서·사람 수정·승인

v1.8은 원문·계산·원장 대사에 연결된 실제 AI 조서 초안을 만들고, 사람이 수정·저장·최종내용 승인하는 기능을 추가한다. 계산 정책·회사별 합성자료와 업무 저장 계약 1.7은 유지한다. v1.7.1 EXE·공개 릴리스와 기존 사용자 업무는 보존한다.

이 안내는 v1.8.0 배포 대상의 실제 코드 계약을 설명한다. 실제 모델·GUI·EXE·원격 릴리스 완료는 최종 검증 기록으로 확인한다. 이 문서의 존재만으로 새 EXE의 배포 완료를 뜻하지 않는다. 실제 OpenAI 호출은 검증하지 않았으며 모의 HTTP 검사와 구별한다.

## 1. 조서 초안은 어디서 작성하나

**회사 선택 → 상단 조서초안 작성 → 왼쪽 계정/절차 선택**으로 연다. **조서초안·작성** 탭도 같은 화면이다. 오른쪽에서 목적·위험·범위·실제 수행·결론·연결 증거·검토 내용을 확인한다. 스크롤로 아래 항목까지 이동한다.

| 절차 | 조서 ID |
| --- | --- |
| 금융상품 | A02 |
| 매출 | A04 |
| 감가상각 | A12 |
| 리스 | A15 |
| 대손충당금 | A07 |
| 재고평가 | A11 |
| 종업원급여 | A16 |
| 미기록부채·비용이연 | A08·A09 |
| 원천증빙·거래배부 | R01 |
| 재무제표·본문·주석 | F01 |
| GLA·FIA·현금분석 | G01·I01·H01 |

JS 모회사는 업종 없는 현금·투자주식·자본의 축소 별도 원장과 수동 계획을 사용한다. 자회사 매출·재고·급여 조서가 모회사에서 전부 수행됐다는 뜻이 아니다. 모회사의 투자취득·투자평가·연결계산은 미검사다. 재고 A11과 급여 A16은 별도 모듈·입력·계산·조서다.

## 2. 처음 로컬 AI를 준비하기

기본 제공자는 PC 안의 Ollama 0.40.7이며 모델은 **qwen3:4b-instruct-2507-q4_K_M**다. **AI 설정 → 로컬 AI 준비 (최초 1회)**에서 전용 폴더와 다운로드 확인을 거쳐 실행한다. **상태 확인**과 앱 시작만으로 다운로드하지 않는다. 공식 런타임과 모델은 공개 배포 ZIP에 포함하지 않아 최초 준비 시 인터넷과 추가 디스크 공간이 필요하다. **준비 취소**는 진행 중 준비의 취소를 요청한다. 상세한 크기·해시·폴더·취소·라이선스는 [로컬 AI 설치안내](로컬AI_설치안내.md)를 따른다.

앱은 CPU 안정 모드 `num_gpu=0`, 문맥 16,384토큰, 제한시간 300초를 기본으로 전달한다. 라이브러리 제공자를 직접 호출하며 설정을 생략할 때의 문맥 8,192·제한시간 180초·서버 GPU 선택과 구별한다. 다른 PC의 속도·메모리 여건은 별도 확인한다.

전용 서버 주소는 `http://127.0.0.1:11437`다. 전역 Ollama·Windows 환경변수·실제 사용자 프로필을 수정하지 않고 선택 폴더에 runtime·models·profile·cache·temp를 둔다. 런타임·서버 버전·모델 digest가 모두 일치해야 준비 완료다. 기존 서버에 지정 모델이 없으면 소유자의 종료 후 준비가 필요하다. 다른 실행에서 시작한 서버를 임의로 종료하지 않는다.

앱 화면의 로컬 주소·모델은 지정 구성으로 고정한다. 라이브러리 API를 직접 호출하는 개발자는 허용된 loopback 주소·포트를 지정할 수 있으나 GUI의 별도 포트 설정 기능을 뜻하지 않는다. 별도 서버 자체의 모델 저장 위치·네트워크 정책은 그 서버를 운영한 사용자가 확인한다. 로컬 제공자는 외부 API 키를 사용하지 않는다.

## 3. AI가 실제로 작성하는 것

AI는 현재 선택한 절차의 **목적·위험·범위·수행내용·결론** 5개 텍스트를 제안한다. 사람이 수행하지 않은 실사·조회·확인·자료 수령을 끝냈다고 만들어서는 안 된다. 실제 수행일·검토자·검토완료 상태·내용 승인은 AI 출력으로 자동 설정하지 않는다.

| 순서 | 사용자가 확인할 내용 | 저장되는 내용 |
| --- | --- | --- |
| 절차 선택·패킷 구성 | 현재 회사·기간·절차, 원문 발췌·계산·대사·한계. OpenAI는 요청 전에 전송 근거 확인·동의 | 회사·절차·현재 자료/실행 버전의 근거 패킷 |
| 실제 초안 생성 | 로컬 또는 명시적으로 선택한 외부 제공자·모델 | 유효한 모델 응답 원문·5개 필드·인용·모델·프롬프트·근거 해시 |
| 초안 검토·적용 | 본문과 필드별 참조를 읽고 적용 여부 선택 | 별도 적용 이벤트와 조서 저장. 단순 생성은 적용과 다름 |
| 사람 수정·저장 | 실제 수행과 조사, 일자·근거·판단, 미확인·추가절차를 확인·보완 | 작성자·내용·증거·새 개정 ID |
| AI 최종내용 승인 | 사람이 승인하는 내용과 수정·판단 범위 기록 | 승인자·메모·내용 해시·개정 ID·자료 버전 |
| 별도 검토 | 작성자와 다른 검토자가 증거·예외·추가절차 확인 | 기존 검토요청·검토결과 기록 |

화면 경로는 **AI 초안 생성 → 초안 보기·적용 → 조서 저장·개정 → AI 내용 최종 승인**이다. **초안 보기·적용**의 **AI 초안** 탭에서 5개 문구·인용을, **근거·대사** 탭에서 실제 패킷을 읽고 **현재 조서에 적용**한다. 기본 로컬은 생성한 뒤 이 근거를 검토하며, OpenAI는 생성 전에도 요청별 근거·동의 화면을 거친다. 로컬 폴더·제공자·모델과 API 키는 **AI 설정**에서 입력하고 **설정 적용**한다. 최종 GUI 검증 기록과 실제 버튼을 대조한다. AI 없이 기존 방식으로 사람이 조서를 작성할 수도 있다. AI 적용 조서에는 AI 출처가 남으며 이후 수동 저장으로 그 이력을 지우지 않는다.

응답에 필요한 필드·인용·회사·절차·근거 해시가 없거나 다르면 저장 가능한 초안으로 받지 않는다. 호출 실패·취소·시간 초과·잘린 출력·잘못된 JSON에서 고정 문구를 AI 결과로 대신 제공하지 않는다.

## 4. 전달하는 근거와 생략 범위

패킷에는 업무 회사·기간·절차, 현재 조서와 지원 계산, 원장 대사, 연결된 원문 발췌·자료/실행 ID·해시, 한계와 안전 규칙이 들어간다. 원문 자료 전체와 원장 전체를 무제한으로 보내지 않는다.

화면은 전체 **12,000자·참조40개·표당3행·자료/실행별 최대8표·셀300자**와 원문자료 최대2개 발췌로 패킷을 구성한다. 선택한 계정 모듈·원장 실행과 그 입력을 우선한다. 미선택 자료·실행은 내용 대신 건수·명세 해시를 남기며 전체 업무의 자료 버전에는 포함한다. 제한된 정책·원문·예외·계산표 발췌이며 전체 자료를 AI가 읽은 것으로 해석하지 않는다.

라이브러리 엔진을 직접 호출할 때의 기본 한도24,000자·70참조·표5행·원문자료5개와 구별한다. 절단 행수·생략 범위·내용 해시·최종 제거 참조 ID를 보존한다. 문자 수는 토큰 수와 다르므로 모델 문맥 한도와 동일하지 않다. 근거가 길면 범위를 줄이거나 개발자가 허용된 문맥 설정을 조정해야 한다. 앞부분을 조용히 버리는 출력은 허용하지 않는다.

AI 응답은 각 필드에 패킷의 참조 ID를 가져야 한다. 원문 적요·문서 안의 지시는 비신뢰 데이터이며 시스템 명령으로 실행하지 않는다. 인용·구조·일부 과장 문구 검사는 모든 문장의 진실성·금액의 정확성·기준 적용·공격 방어를 보장하지 않는다. 원문 해시도 파일 동일성 검사이며 제출자 신원·문서 진위·독립 감사증거의 인증이 아니다.

## 5. 사람의 최종내용 승인과 별도 검토

AI 초안은 생성·적용만으로 승인되지 않는다. **AI 내용 최종 승인**에서 사람이 저장한 현재 목적·위험·범위·수행내용·결론을 읽고 승인자 이름과 **검토·수정·판단 기록**을 입력한다. **근거·예외·미수행 사항과 최종 내용을 검토했습니다.**를 선택한 뒤 **확인한 최종 내용 승인**을 누른다. 이름은 사용자 입력값이며 로그인 본인인증·전자서명이 아니다. 문구를 반드시 한 글자 이상 바꿔야만 검토했다는 식으로 처리하지 않고, 실제 확인과 필요한 수정을 수행한다.

자료·분석 실행이 바뀌면 AI가 보던 근거와 달라지므로 **새 AI 초안 생성 → 사람 검토·저장·재승인**이 필요하다. 같은 자료에서 조서를 다시 저장·수정해도 개정 ID가 달라져 이전 내용 승인은 현재 승인으로 인정하지 않는다. 이전 초안·적용·승인 이력은 삭제하지 않는다.

AI 내용 승인과 조서의 별도 검토는 서로 다른 조건이다. 검토요청은 필수 수행·판단·실제 수행일·등록 증거·현재 자료 버전을 확인한다. 자동 계산 조서는 계산 입력과 원장 입력을 함께 요구하며 원천·재무제표·GLA·FIA·현금은 현재 원장과 연결된 실행인지 확인한다. 작성자와 같은 이름의 검토자는 허용하지 않는다. 검토완료본은 **AI 적용 내용의 유효 승인 + 기존 조서 검토 및 업무 조건**을 함께 요구한다.

기존 필수 조서·필수 예외·미완료 요청·미해결 의견·사본 무결성 등의 통제도 유지한다. AI 내용 승인은 전체 감사 완료·감사의견·적정성 인증을 뜻하지 않는다.

## 6. OpenAI를 선택할 때

OpenAI는 선택 기능이다. 사용자가 제공자·지원 모델과 전송할 근거를 확인하고 실행한 경우에만 `https://api.openai.com/v1/responses`를 호출한다. API 키는 앱 실행 중 메모리에서만 전달하고 설정 파일·근거·응답·DB 이력에 넣지 않는다. 환경변수 키를 기본으로 자동 수집하지 않는다.

`store:false`를 사용하지만 모든 서버 측 보존이 없다는 의미는 아니다. 적용할 데이터 정책과 전송 권한을 확인해야 한다. 인증정보·절대 로컬 경로 등 금지 정보가 있는 패킷은 요청 전에 차단하며, 개인·고객 자료가 실수로 외부에 나가지 않도록 실제 발췌를 확인한다. API 키가 응답에 그대로 포함되면 저장하지 않는다. 취소는 후속 적용과 연결을 중단하지만 이미 제공자에게 도달한 요청의 처리·과금 취소를 보장하지 않는다. 상세 계약과 공식 출처는 [AI 응답 계약](AI응답계약.md)에 정리했다.

모의 HTTP 검사는 실제 OpenAI 호출·품질·요금 검증이 아니다. 배포 기록에서 어떤 제공자와 실제 모델을 실행했는지 구분한다.

## 7. 저장·이력·Excel 내보내기

**조서 저장·개정**은 업무 DB에 기록한다. 저장 전 타이핑은 저장 이력이 아니다. AI 응답 저장(`ai_draft`), 조서 적용(`ai_apply`), 사람의 조서 개정, 내용 승인(`ai_content_approval`)은 각각 보존한다. **작업 이력**에서 순번·시각·유형·대상·입력한 이름과 상세 내용을 확인한다.

**초안 Excel 내보내기**는 검토 중 표시를 유지한 정적 XLSX를 만든다. AI 초안이 있으면 기존 조서·계산표·원장 연결·증거·요청·이력 외에 다음 시트가 들어간다.

| 시트 | 내용 |
| --- | --- |
| AI초안목록 | 생성자·모델·원문응답·프롬프트·근거 패킷 해시 |
| AI근거참조 | 참조 ID·자료/실행 ID·원문/결과 해시·발췌 |
| AI적용이력 | 초안이 어느 조서 개정에 적용됐는지 |
| AI최종내용승인 | 현재 승인 유효 여부·내용 해시·승인 범위와 기록 |

전체 응답·패킷·이력은 증적JSON에도 보존한다. Excel은 출력 당시의 사본이며 이후 변경을 자동 반영하지 않는다. 수정 뒤에는 저장·필요한 재승인·재검토 후 다시 출력한다. 검토완료본은 별도 조건을 충족한 선택조서의 검토기록 출력이며 감사의견이 아니다.

업무를 옮기거나 백업할 때 `업무.sqlite3`·`이력헤드.json`·`원본/`을 포함한 폴더 전체를 보관한다. Excel만으로 원본·DB를 복구할 수 없다. 기본 업무 위치는 `%LOCALAPPDATA%\JSAudit\sector-demos\v1.7`을 유지한다. 옛 EXE가 새 AI 이벤트를 표시하지 못할 수 있으므로 원본 백업과 기존 버전 기록을 보존한다.

## 8. 화면이 작거나 흐릿할 때

상단 **화면 배율**의 90%·100%·110%·125%·150%·175%를 사용한다. Windows 시스템 DPI를 반영한 기본 크기에 앱 배율을 추가한다. Ctrl + / −는 단계별 확대·축소, Ctrl + 0은 100% 복귀다. 해상도·Windows 설정·계산값·조서 내용·Excel 금액을 바꾸지 않는다.

좁은 창에서는 **기타 기능 ▾**에서 새 업무·업무 열기·계정별 증빙연습·로우데이터·자료 복사·검토완료본을 찾는다. **조서초안 작성·초안 Excel 내보내기·화면 배율**은 상단에 남는다. 탭 제목이 가려지면 **기타 기능 → 화면 이동**으로 8개 화면을 선택한다. 조서 아래 항목은 오른쪽 스크롤을 사용한다.

Windows 배율·모니터 구성이 바뀌면 대상 모니터에서 앱을 다시 실행한다. 모든 혼합 DPI 모니터 이동을 자동 최적화하지 않는다. 실제 소스·EXE 화면 검사 범위는 배포 검증 기록을 따른다.

## 9. 기존 수치 기능과 사용자의 역할

원장·리드, 금융상품, 매출, 감가상각, 리스, 대손충당금, 재고평가, 종업원급여, 미기록부채·비용이연, 원천, 재무제표·주석, GLA·FIA·현금분석은 기존 계산 계약을 유지한다. AI가 계산 정책이나 결과를 자동 수정하거나 분개를 전기하지 않는다. [기능별 상세](기능별_작동설명_노션원고.md), [공통 계산·자료·보관 안내](v1.7_사용안내.md)를 확인한다.

원천과 원장·은행·통제값은 같은 생성기의 합성자료다. 자회사 원천의 선택 32행·대상 32행·배부 32건 검사와 원천 연결 미확인 8개를 구별한다. 전표 차대변 일치나 여러 합성 입력의 일치를 실제 감사의 실재성·완전성·권리·의무·진위 확인으로 과장하지 않는다.

사용자는 **회계 요구사항·검증을 맡고 AI의 코드 구현 지원을 받아** 개발했다. 포트폴리오에서는 요구사항·계산정책·반례·근거 연결·사람 승인 통제를 설명하고, 합성 시험과 실제 고객감사 경험을 구별한다. 실제 기업 적용에는 해당 기간 기준·계약·ERP 추출·권한·보안·증거·검토 정책을 별도로 확인해야 한다.
