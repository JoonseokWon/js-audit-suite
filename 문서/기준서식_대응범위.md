# 2026 예시 서식 참고 연결의 대응 범위

v1.9.0은 공식 예시 ZIP의 **파일명·시트명·해시 메타데이터와 자체 절차의 설계상 참고 연결**을 제공한다. 프로그램에서 참고 항목을 표시하거나 자체 Excel 조서에 참고목록을 내보낼 수 있다. 공식 예시 파일의 모든 셀을 채우거나, 필수 감사절차 충족·회계감사기준 준수·실제 감사 완료를 인증하는 기능은 아니다.

## 확인한 원본과 실제 검증 수량

원본 이름: `2026 감사조서서식(예시)-엑셀 260827.zip`

- ZIP SHA-256: `0be87ba0ce6db247e75a1b70b8d2f2a20fa021cadf701ee32ae8f7d44dd66740`
- ZIP 크기: 11,180,722 bytes
- ZIP 항목 119개: 폴더 3개, 실제 파일 116개
- 실제 파일: XLSX 80개, XLSM 2개, DOCX 28개, PDF 2개, DOC 2개, HWP 2개
- Excel 통합문서 82개, 시트명 435개
- 서식계열별 파일: KIFRS 52개, 일반기업 42개, 소규모기업 22개

원본 ZIP과 116개 멤버의 SHA-256·bytes 및 82개 통합문서의 시트명·VBA 포함 여부·외부 링크 XML 수를 읽기 전용으로 대조했다. 검증 전후 원본 ZIP 해시가 같았다. **435는 시트명 목록을 확인한 수량**이며, 435개 시트의 모든 문항·셀·수식·감사절차를 내용상 전수 검증했다는 수량이 아니다. DOCX/PDF/DOC/HWP는 이 라이브러리에서 이름·크기·해시만 관리한다.

기존 48개 카탈로그 절차와 추가 6개 `FS01/R01/W01/G01/I01/H01`, 합계 **54개 자체 절차**를 세 서식계열별로 명시했다. 총 162개 상태 중 설계상참고 93개, 수동판단 60개, 미연결 9개이다. 참고 항목은 228개이며 서로 다른 참고 파일은 86개이다. 나머지 30개 파일은 메타데이터 목록에 보존하며 현재 절차에 연결하지 않았다. 같은 파일이 여러 절차에 연결될 수 있으므로 228을 서로 다른 공식 서식 수로 읽지 않는다.

검증 근거는 `test_audit_forms.py`에 있다. 2026-10-25 프로젝트 전용 Python 3.14.8 환경에서 17개 테스트를 실행해 모두 통과했으며, 로컬 공식 ZIP에 대한 테스트도 실제 실행했다. 공개 소스에 원본 ZIP이 없을 때에는 해당 한 개의 원본 대조 테스트를 명시적으로 건너뛰고 나머지 메타데이터·스키마 검증을 실행한다.

## 서식계열·적용 회계체계·감사기준과 ID 구분

| 구분 | 값과 의미 |
| --- | --- |
| 앱 절차 namespace | `app.procedure`; 예: `A01`, `F01`, `FS01` |
| 원본 참고 namespace | `official.example.2026:<서식계열>:<파일의 서식번호>:<확장자>:<파일해시 앞 12자리>` |
| 원본 서식번호 | 파일명에 표시된 번호를 별도 `form_code`로 보존; 앱 절차 ID와 다름 |
| KIFRS | ZIP의 `1. K-IFRS_2026` 안의 파일만 연결 |
| 일반기업 | ZIP의 `2. 일반기업회계기준_2026` 안의 파일만 연결 |
| 소규모기업 | ZIP의 `3. 소규모기업용 감사조서서식(예시)_2026` 안의 파일만 연결 |

참고 namespace는 앱이 파일을 구별하기 위해 부여한 식별자이다. 한국공인회계사회가 새로 부여한 공식 번호를 의미하지 않는다. 같은 번호의 XLSX·DOCX·XLSM도 다른 파일 ID를 갖는다. **세 선택지는 예시 ZIP의 서식계열이며, 소규모기업은 별도의 회계체계가 아니다.** 서식계열 선택은 회사에 적용할 회계체계나 감사기준의 적용성 판단을 대신하지 않는다.

실제 적용 회계체계는 업무 기본정보 `engagement['회계체계']`에 별도로 기록한다. 감사계획의 `audit_framework`는 감사기준 선택이며 `KSA_200_720`과 `KSA_1200`을 구분한다. **감사기준 1200은 회계기준이 아니며**, 소규모기업 예시 서식계열을 고른 것만으로 그 감사기준의 적용 요건을 충족하지 않는다. 각 선택과 적용성 근거는 사람이 판단해 입력한다. 감사계획의 참고 계열은 `form_framework`로 기록한다.

레지스트리 내부의 `framework`, `frameworks` 키와 Python API의 `framework` 인수명은 기존 메타데이터 계약을 유지하기 위한 이름이며 여기서는 모두 **원본 파일의 서식계열**을 뜻한다. 표시·Excel 내보내기 열 이름은 `서식계열`이다.

다른 서식계열에서 없는 서식을 가져와 보충하지 않는다. 예를 들어 소규모기업 ZIP에는 `2302`, `3650`, 그룹감사 서식들이 없으므로 해당 항목을 KIFRS·일반기업 파일로 대체하지 않는다.

앱의 **`F01`은 후속사건**이다. 재무제표·본문·주석 대사는 **`FS01`**이다. 구형 업무에서 모호한 `F01`을 발견한 경우 이 레지스트리가 자동 재분류하거나 과거 이력을 고치지 않는다.

## 연결 상태와 읽는 방법

| 상태 | 의미 |
| --- | --- |
| 설계상참고 | 파일명·확인한 시트명·계정 주제 등을 근거로 설계한 참고 연결. 공식 일대일 적합성 또는 실제 수행 표시는 아님 |
| 수동판단 | 관련 파일은 제시하지만 세부 절차·시트·계정·적용 범위는 사람이 확인하고 선택해야 함 |
| 미연결 | 이 버전에서 특정한 참고 파일이 없음. 절차가 불필요하거나 완료되었다는 의미는 아님 |

각 항목은 `scope`, `exclusions`, `reference_scope`를 함께 가진다. 전체 시트 목록인 `sheet_names`와 실제 참고 범위인 `linked_sheets`는 구별한다. `linked_sheets=[]`는 **파일 수준 참고**이며 파일 안의 모든 시트·셀을 대응했다는 뜻이 아니다. 예컨대 현금·예금 `A01`은 `4000` 통합문서 중 `A` 시트명을 연결하며 같은 파일의 다른 30여 개 시트를 자동 적용하지 않는다.

## 개발용 조회 계약

```python
from audit_forms import (
    load_registry, forms_for_procedure, registry_rows,
    verify_local_reference_zip, procedure_ids_validation,
)

registry = load_registry()
references = forms_for_procedure('FS01', 'K-IFRS')
excel_rows = registry_rows('일반기업', ['FS01', 'A01', 'C06'])
catalog_check = procedure_ids_validation(catalog)
local_check = verify_local_reference_zip(user_selected_local_zip)
```

- `load_registry(path=None) -> dict`: 크기 제한·중복 JSON 키·비유한 수·알 수 없는 필드·필드 유형·ID·서식계열·시트 참조를 검증한 새 dict. EXE에서는 `_MEIPASS/form_registry.json`을 읽는다. 런타임 캐시는 없으며 반환값 변경이 다음 조회에 전파되지 않는다.
- `forms_for_procedure(pid, framework='일반기업') -> list[dict]`: 원본 파일 메타데이터와 `app_id`, `linked_sheets`, `reference_scope`, `mapping_status`, `scope`, `exclusions`. 명시적 미연결은 빈 목록이다. 알 수 없는 절차·서식계열은 `FormRegistryError`이며 임의 추정하지 않는다.
- `registry_rows(framework='일반기업', procedure_ids=None) -> list[dict]`: 자체 Excel·UI 표시용 평면 한국어 행. `절차ID/절차명/서식계열/공식서식ID/서식번호/파일/서식명/시트/참고단위/연결상태/대응범위/참고범위/제외범위/원본ZIP_SHA256/파일_SHA256/주의`를 제공한다. 미연결도 상태를 숨기지 않고 1행을 낸다. `procedure_ids=None`이면 54개 기본·추가 절차를 모두 표시한다.
- `procedure_ids_validation(catalog) -> dict`: 기존 카탈로그의 `modules` 또는 ID 목록과 연결표를 대조한다. `ok/errors/registry_only/catalog_only/supplemental_ids`를 반환한다. 여섯 추가 절차는 기존 48개 카탈로그 밖에 있어도 명시적으로 허용한다. `X-...`, `B-...`와 같은 업무별 동적 예외 ID는 원본 서식 ID와 연결하지 않는다.
- `verify_local_reference_zip(path) -> dict`: 사용자가 명시적으로 선택한 로컬 ZIP의 원본 크기·SHA-256을 먼저 확인한다. 일치할 때만 같은 메모리 내 바이트에서 ZIP 멤버를 읽어 116개 파일 해시와 82개 통합문서·435개 시트명 메타데이터를 대조한다. `ok/errors/sha256/counts/member_hashes_verified/workbooks_verified/sheets_verified`를 반환한다. 다른 ZIP은 내부를 읽지 않고 거절한다. 원본 ZIP을 공개 배포에 넣을 필요가 없다.

지원 서식계열은 `KIFRS`, `일반기업`, `소규모기업`이다. 호환 별칭 `K-IFRS`, `일반기업회계기준`, `소규모`도 각각 서식계열 선택값으로 정규화한다. 이 정규화가 업무의 적용 회계체계나 감사기준을 변경하지는 않는다. 원본 파일을 받는 UI나 파일선택기는 이 라이브러리에 포함하지 않는다. 네트워크·프로그램 실행·ZIP 추출·파일 수정은 수행하지 않는다.

## 공개 배포 및 검증에서 제외한 내용

공개 소스에는 `audit_forms.py`, `form_registry.json`, 검증 코드, 이 설명만 포함한다. 원본 Excel/PDF/DOCX/DOC/HWP, VBA 바이너리, 문서 전문·질문 문항·서식 셀 본문을 넣지 않는다. XLSM은 목록과 해시만 보존하며 참고 연결에는 비매크로 2302 XLSX를 사용한다. 수식 계산·VBA 실행·외부 링크 갱신을 하지 않았다.

앞서 확인한 21쪽 PDF는 `회계감사기준 전문(前文)`이다. 이를 전체 회계감사기준 `全文`으로 사용하지 않았다. 별도 보관한 2026년 7월 개정 全文 자료의 존재와 이번의 예시 서식 메타데이터 검증은 구분한다. 이 작업은 법규·기준서의 모든 필수조항에 대한 해석·적용·준수 검토가 아니다.
