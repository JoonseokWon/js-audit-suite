# v1.8.1 한글 본문 입력 수정

조서의 목적·위험·범위·수행내용·결론과 AI 내용 승인 메모를 Windows Rich Edit 일반 텍스트 편집기로 교체했습니다. 조합 중 한글을 별도 IME 창에 맡기던 Tk 본문 편집기 대신 Windows가 한글 입력·선택·실행 취소를 처리합니다. 작성자·승인자 등 짧은 단일행 입력란은 기존 Tk 입력란입니다.

기존 v1.8.0 EXE와 원본 업무는 보존했습니다. 계산 엔진과 저장 계약, AI 생성 근거, 사람의 최종 내용 승인 및 독립 검토 통제는 바꾸지 않았습니다.

## 실행파일·자료 위치

`For ax node Project/통합감사 프로그램/` 아래에 실행파일·데이터·소스·문서·검증·보관 폴더를 둡니다.

- `실행파일/통합 회계감사 v1.8.1.exe`를 실행합니다. `portable-config.json`을 EXE와 함께 둡니다.
- 포터블 설정이 지정한 회사별 업무는 `데이터/회사별업무/`에서 보관합니다. JS전자 AI 시연의 별도 사본은 `데이터/AI조서_시연/`에 있습니다.
- `소스/v1.8.1/`은 현재 코드와 내장 합성 모본이며, 기존 버전·이전 작업 자료는 `보관/`에 둡니다.
- `문서/`에서 사용 순서를, `검증/`에서 해당 버전의 실제 검사·이관 기록을 확인합니다.

기존 업무의 AppData 원본과 새 폴더의 사본을 단순히 같은 업무로 추정하지 않습니다. 업무 이관은 원본 위치와 해시·이력 검증을 함께 확인한 기록을 따릅니다. 이동이 제한된 이전 자료는 원본 백업을 남기고 보관 사본을 검증합니다. 원본 업무를 삭제하거나 오류가 있는 사본을 새 더미자료로 덮어쓰지 않습니다.

새 아이콘은 내장 ImageGen으로 만든 문서·체크 표시의 독자적인 이미지이며 사용자 첨부 stock 이미지를 사용하지 않았습니다. Windows ICO에는 16·20·24·32·40·48·64·128·256px의 9개 해상도를 포함하고 생성·포맷 변환 기록을 함께 보관합니다. 이 아이콘은 법적 인증·감사의견을 뜻하지 않습니다.

## JS전자 조서 검토

1. `실행파일/통합 회계감사 v1.8.1.exe`를 실행하고 창 제목의 버전을 확인합니다.
2. 상단 회사 선택에서 `JS전자`를 선택하면 현재 저장 연습을 다시 엽니다. 실제 보관 위치는 `데이터/회사별업무/companies/JS_ELEC/e5abf99579424fe4bf30c6c82d300e93/업무`입니다. 이 업무에는 v1.8.0에서 실제 로컬 AI로 생성한 매출 A04 초안과 수정·저장한 더미 결론이 들어 있습니다. 이번 한글 편집기 변경에서 모델 재추론은 하지 않았고 A04는 AI 내용 미승인 상태로 남겼습니다. `데이터/AI조서_시연/JS전자_AI조서_한글검증`은 예전 별도 사본이므로 현재 회사 선택으로 다시 여는 업무와 구분합니다.
3. `조서초안·작성`에서 A04를 선택합니다. `초안 보기·적용`에서 최초 AI 문장과 근거를 확인할 수 있습니다. 이미 적용된 초안을 다시 적용하면 현재 수정본이 교체되므로, 현재 본문을 계속 검토할 때는 닫기를 사용합니다.
4. 오른쪽 본문에서 직접 수정합니다. `조서 저장·개정`을 누른 뒤 `AI 내용 최종 승인`을 엽니다.
5. 승인자, 검토·수정·판단 기록을 작성합니다. 근거·예외·미수행 사항을 확인한 뒤 체크하고 `확인한 최종 내용 승인`을 누릅니다. 이 내용 승인은 별도 검토자의 검토기록이나 전체 감사 완료를 뜻하지 않습니다.
6. `초안 Excel 내보내기`를 누르고 저장할 `.xlsx` 경로를 지정합니다. 조서_A04와 AI초안목록·AI근거참조·AI적용이력·AI최종내용승인에서 본문 및 이력을 확인합니다. 승인 후 내용을 수정·저장하거나 근거를 바꾸면 재승인이 필요합니다.

## 검증 범위

숨긴 시험 창의 한글·영문·이모지·줄바꿈·긴 본문·수정·저장·재열기·Excel 출력과 글꼴 배율 변경 검사는 실제 키보드의 IME 조합 검증과 구분합니다.

최종 EXE의 JS전자 A04 결론란에서 실제 Windows 한글 입력을 확인했습니다. 사용자가 한글 모드로 전환한 뒤 `r/j/a` 키로 `ㄱ → 거 → 검`이 본문 안에서 조합되는 것을 확인했고, Backspace로 받침을 지운 `거`에 다시 받침을 넣었습니다. 이어 `x/h`로 `검토`를 완성하고 공백·줄바꿈·숫자 및 `가`를 입력했습니다. 마지막 `가`를 조합하는 상태에서 저장해도 음절이 빠지지 않았으며 앱 화면의 Excel 내보내기를 실행했습니다.

이 실제 IME 검증 범위는 **본문 결론란**입니다. **승인 메모**는 네이티브 단위·통합검사 범위이며, 승인 메모에서 실제 IME 키 입력을 시험한 것으로 표시하지 않습니다. DB·Excel의 별도 대조와 파일 해시 등 최종 결과는 해당 검증 기록을 확인합니다. 검증한 EXE의 SHA-256은 `660615ae0bffd08c4b9db853fb713b746409b26ddd378fcb9560455eb47f3071`입니다.

Windows 네이티브 편집기는 기본 텍스트 편집 동작을 사용합니다. 본문 안 Tab은 탭 문자를 입력할 수 있고, 본문에 포커스가 있을 때 앱의 Ctrl +/- 단축키는 전달되지 않을 수 있습니다. 배율은 상단 선택창으로 조절합니다.

로컬 AI 런타임·모델은 공개 ZIP에 포함하지 않습니다. 전용 폴더에 최초 준비하거나, 기존에 준비한 로컬 AI 폴더를 앱의 AI 설정에서 명시적으로 선택합니다. 포터블 실행 환경에서는 `실행파일/` 아래의 전용 로컬 AI 폴더를 사용할 수 있습니다. 기존 v1.8 실행 환경의 런타임을 이관할 때는 이관 기록과 설정 경로를 확인합니다. API 키를 채팅이나 검토 메모에 적지 않습니다.
