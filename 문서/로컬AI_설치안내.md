# 로컬 AI 최초 준비와 설치 폴더

이 문서는 v1.8의 `LocalAIRuntime` 설치·실행 관리 모듈을 설명한다. 실제 AI 조서 기능의 GUI·모델 추론·EXE 검증 결과는 해당 버전의 최종 검증 기록으로 확인한다. 모의 HTTP 테스트만으로 실제 모델 실행에 성공했다고 판단하지 않는다.

## 언제 다운로드하는가

앱을 시작하거나 설치 상태를 확인하는 것만으로 런타임·모델을 다운로드하지 않는다. 사용자가 AI 설정에서 최초 준비를 실행할 때만 공식 배포 파일을 내려받고 모델을 준비한다. 최초 준비에는 인터넷과 충분한 디스크 공간이 필요하다. 준비한 모델의 조서 추론은 PC의 전용 로컬 서버를 사용한다.

기본 구성은 **Ollama 0.40.7 + qwen3:4b-instruct-2507-q4_K_M**다. 공개 EXE·소스 ZIP에는 약 2.5GB의 모델 가중치와 Ollama 실행환경·캐시를 포함하지 않는다. 다른 PC에서는 최초 준비가 다시 필요하며, 설치된 전역 Ollama에 의존하지 않는다. 앱의 기본 추론 설정은 CPU 안정 모드 `num_gpu=0`, 문맥 16,384토큰, 제한시간 300초다. 런타임의 서버 기본 문맥 8,192와 별개로 앱 요청에 16,384를 명시한다.

## 폴더와 PC 설정

EXE 실행 시 기본 설치 폴더는 EXE 옆의 `로컬AI`, 소스 실행 시 프로젝트의 `배포/로컬AI`다. 사용자가 지정한 전용 폴더도 사용할 수 있다. 쓰기 권한이 있는 일반 폴더를 사용한다. 드라이브 루트, 심볼릭 링크·Windows 재분석 지점이 있는 경로는 지원하지 않는다.

| 하위 경로 | 저장 내용 |
| --- | --- |
| `runtime/` | 검증한 Ollama 실행 파일과 종속 라이브러리 |
| `models/` | 내려받은 모델 계층·매니페스트 |
| `profile/` | 이 실행환경 전용 사용자 프로필·클라우드 비활성화 설정 |
| `cache/` | 크기와 SHA256이 일치하는 공식 배포 ZIP |
| `temp/` | 이 실행환경 전용 임시 파일 |
| `runtime-install.json` | 설치 파일 크기·해시·런타임 버전 기록 |

Windows의 전역 환경변수, 기존 Ollama 설치, 실제 사용자 프로필은 수정하지 않는다. 자식 프로세스에만 전용 프로필·모델 경로를 전달한다. 서버 창은 숨김으로 실행하며 주소는 **`127.0.0.1:11437`**로 고정한다. 원격 PC에서 접속하도록 주소를 공개하지 않는다. `OLLAMA_NO_CLOUD=1`과 전용 프로필 설정으로 Ollama의 클라우드 기능을 끈다. 관련 설정은 [Ollama 공식 FAQ](https://docs.ollama.com/faq)에 따른다.

같은 포트에서 지정 버전의 서버가 이미 실행 중이고 지정 모델이 준비돼 있으면 재사용한다. 이 모듈이 직접 시작한 서버만 모델을 내려받거나 종료할 수 있다. 기존 서버의 모델 저장 경로는 API로 확인할 수 없으므로 지정 모델이 없는 기존 서버에는 다운로드하지 않는다. 기존 사용자 서버나 다른 실행에서 시작한 프로세스는 임의로 종료하지 않는다. 기존 서버가 실행 중인 동안 런타임 파일 교체나 모델 최초 준비가 필요하면 먼저 그 서버의 소유자가 종료해야 한다.

## 저장공간과 하드웨어

| 구성 | 다운로드 크기 | 해제·모델 크기 |
| --- | ---: | ---: |
| 기본 Windows AMD64 ZIP | 1,582,514,985바이트, 약 1.58GB | 런타임 약 2.22GB |
| 지정 Qwen3-4B Instruct-2507의 주요 가중치 계층 | 2,497,293,803바이트, 약 2.50GB | 추가 설정·라이선스 계층 포함 |
| 선택 ROCm ZIP | 256,506,971바이트, 약 0.26GB | 추가 약 1.02GB |

최초 설치 또는 런타임 교체 전 여유 공간을 기본 **10GiB**, 선택 ROCm 포함 **14GiB** 이상 확인한다. 캐시·설치 대기 폴더·이전 런타임을 함께 보존하므로 실제 잔여 공간은 설치 이력에 따라 달라진다. 이 수치는 RAM 또는 VRAM 최소 요구사항을 뜻하지 않는다. CPU/GPU·메모리와 입력 길이에 따라 추론 속도와 실행 가능 여부가 달라진다. 특정 GPU가 없으면 작동하지 않는다고 단정하지 않으며, 다른 PC의 속도·안정성은 별도 검증해야 한다.

ROCm은 선택 구성이다. AMD GPU가 있다고 반드시 이 옵션을 설치해야 하는 것은 아니다. 런타임의 지원 장치·백엔드에 따라 실행 방식이 달라진다. GPU 지원 범위는 [Ollama 공식 GPU 문서](https://docs.ollama.com/gpu)를 확인한다.

## 무엇을 검증하는가

런타임은 `github.com/ollama/ollama/releases/download/v0.40.7/`의 공식 HTTPS 주소에서만 받으며, 승인된 GitHub 배포 호스트로의 HTTPS 리디렉션만 허용한다. ZIP 전체의 정확한 바이트 수와 SHA256을 확인한 후 해제한다. 경로 탈출, 절대 경로, 링크, 중복 이름, 암호 ZIP, 지원하지 않는 압축 방식, 과도한 크기·압축률을 거부한다. 설치 파일별 해시와 크기도 기록한다.

| 파일 | 고정 SHA256 |
| --- | --- |
| `ollama-windows-amd64.zip` | `e6527768c53e85ec4596495fb0f035ef07f437b4b591ebc3581684699a4668f4` |
| `ollama-windows-amd64-rocm.zip` | `3910a28c107655c0b2c9d5d3f3ae95dc1f9e5f2e798b381d6b91d86f3ad99b41` |

모델 준비는 `/api/pull`의 스트림을 읽어 진행률·취소를 처리한다. 유효한 마지막 `success` 응답에 이어 `/api/tags`에서 모델 이름과 **`sha256:0edcdef34593eac1aa2be9c7d06c432dcf81945adca5eca2f27662c18f168ba0`** digest까지 일치해야 준비 완료로 인정한다. 다른 모델, 동일 이름의 다른 digest, 중단된 다운로드는 준비 완료가 아니다. [공식 API](https://github.com/ollama/ollama/blob/v0.40.7/docs/api.md), [모델 정보](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M), [공식 모델 manifest](https://registry.ollama.ai/v2/library/qwen3/manifests/4b-instruct-2507-q4_K_M)

상태의 `runtime`, `server`, `model`은 별도 값이다. 서버만 실행되고 모델이 없을 수 있으므로 하나의 존재 여부만으로 AI가 준비됐다고 표시하지 않는다. 지정 런타임의 설치 검증·서버 버전·모델 digest가 모두 맞을 때 `ready=true`다. 해시 일치는 파일 동일성 검사이며 감사 증거의 독립성이나 AI 판단의 정확성을 인증하지 않는다.

## 취소·오류·재실행

진행 중 취소하면 미완료 다운로드를 준비 완료로 기록하지 않는다. 런타임의 현재 작업이 만든 `.part` 파일만 정리하고, 기존 캐시와 사용자 파일은 임의로 삭제하지 않는다. 모델 취소는 전용 연결을 닫아 처리하며 서버에 부분 계층 파일이 남을 수 있다. 다음 최초 준비에서 재시도한다. 응답을 기다리는 다운로드는 네트워크 타임아웃까지 취소 반영이 지연될 수 있다.

기존 ZIP의 크기·해시가 다르면 덮어쓰지 않고 오류를 알린다. 사용자가 파일을 보존·확인한 뒤 캐시를 정리하고 다시 시도한다. 설치 중 실패하면 `install-*` 폴더가 남을 수 있으며, 교체 전 실행환경은 `runtime-previous-*`로 보존한다. 자동으로 전체 폴더를 삭제하지 않는다. 공간을 정리할 때는 앱과 해당 서버를 종료하고 필요한 모델·기록을 백업한 뒤 경로를 확인한다.

포트 충돌, 다른 버전 서버, 저장공간 부족, 손상 ZIP, 모델 digest 변경은 완료 상태를 만들지 않는다. 공식 모델 태그가 나중에 바뀌어도 현재 지정 digest와 다르면 중단한다. 버전·모델 변경은 새 검증과 배포가 필요한 변경으로 취급한다.

## 라이선스와 감사 업무에서의 역할

Ollama는 [MIT 라이선스](https://github.com/ollama/ollama/blob/v0.40.7/LICENSE), 지정 Qwen3-4B 모델은 모델 페이지에 표시된 [Apache 2.0 라이선스](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M)를 따른다. 별도로 받은 런타임·모델을 재배포할 때에는 해당 배포본의 라이선스·고지와 포함된 종속 구성요소의 조건을 확인하고 보존한다.

AI는 선택한 조서와 근거 패킷을 바탕으로 초안을 제안한다. 사람은 원문과 계산 결과를 대조하고 내용을 수정한 뒤 최종 내용을 승인한다. 실사·조회·자료 수령·독립 검토가 실제로 끝났다는 사실을 AI가 대신 만들거나 승인하지 않는다. AI 내용 승인과 조서 검토완료는 별개의 통제다. 외부 API 사용은 로컬 준비와 별도이며, 사용자가 제공자를 선택하고 전송할 근거를 확인해 실행한 경우에만 진행한다.

이 프로그램은 사용자가 **회계 요구사항·검증**을 맡고 **AI의 코드 구현 지원**을 받아 개발한 감사 지원 포트폴리오다. 합성 더미데이터의 재현 가능 검증과 실제 기업 감사에서 충분하고 적합한 증거를 확보하는 절차를 구별한다.
