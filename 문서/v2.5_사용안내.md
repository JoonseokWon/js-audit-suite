# v2.5.0 사용 안내

기존 업무를 보존하고 새 시연 업무에서 사용법을 확인하세요. 더보기·검토후보·조서·감사계획에서 **왜곡표시 집계**, **위험·절차 연결**을 열 수 있습니다.

## JS전자 자료와 AI 초안

더보기 → 새 JS전자 감사 시연은 별도 폴더에 원장·매출 오류/정상 입력과 원천증빙·빈 검토표를 만듭니다. 기존 업무의 파일을 바꾸지 않습니다. 시연 진행 안내의 기본 단계와 추가 절차를 따라 원본을 확인하고 검사를 직접 실행하세요.

로컬 AI 실행환경·모델 준비는 AI 설정에서 별도로 진행합니다. 기존 서버를 임의 종료하거나 모델 원응답을 고치지 않습니다. AI 생성은 선택된 원문·계산·예외·대사와 현재 절차에 연결한 사람 기록의 발췌를 사용합니다. 어떤 표·기록을 생략했는지 명세와 해시를 확인하세요. 기록이 많은 경우 제공되지 않은 내용을 모델이 읽었다고 해석하면 안 됩니다.

생성 결과의 **프로그램 근거 기록**과 **미검증 AI 제안**은 별도입니다. 선택 예외와 인용은 생성 단계에서도 제한하지만, 응답은 다시 검증하며 틀리거나 빠진 인용은 저장 전에 거부합니다. 미검증 제안을 자동으로 조서에 합치지 않습니다. 실제 수행·판단·결론은 사람이 원문을 확인해 직접 수정·작성합니다.

생성 근거 보기와 AI 생성은 같은 발췌 정책을 사용합니다. 기본은 24,000자·최대 70개 참조·표당 3행·최대 8개 표·셀당 300자와 문맥 32,768 토큰이며 하드웨어는 자동 선택합니다. 명시한 사용자 설정은 보존합니다. 이 한도는 AI에 전달하는 발췌이며 원장 계산·저장·Excel 전체 행 보존과 구분합니다.

AI 서술의 완료 전 단계·완료 여부 미확인은 실제 완료 단정과 구분합니다. 다른 절에 근거 없는 수행·실사·수령·완료 단정이 있으면 계속 거절합니다. 이 검사는 문장 전체의 회계적 정확성이나 증거 충분성을 인증하지 않습니다.

## 왜곡표시 집계

1. 자동검토후보를 고르고 원본 행·실행·계산/대사 결과를 살펴봅니다. 행수 차이와 금전 차이는 다른 단위이며 자동후보는 오류 확정이 아닙니다.
2. 왜곡표시 해당 여부·원인·금액·분류·기초/당기·수정/미수정·회사 수용/이견·정성적 영향·세효과를 기록합니다. 미입력 값은 0이나 승인으로 바꾸지 않습니다.
3. 계정영향을 행별로 입력하고 원본 증거와 A04 등 관련 조서, F03 집계조서를 연결합니다. 화면의 계정행 편집 중인 값을 표에 추가하지 않은 채 저장하면 보완 안내가 나옵니다.
4. 같은 오류가 여러 검사에서 발견됐다고 판단한 경우에만 동일오류 그룹·대표기록·사유를 직접 지정합니다. 개별 기록의 계정영향과 원래 기록은 보존하고 대표금액은 한 번 집계합니다. 연결을 잘못했다면 사유와 함께 해제합니다.
5. 회사가 수정을 수용한 사실과 GL 반영은 다릅니다. 새 원장을 검사하고 기존 기록을 명시적으로 재확인한 뒤, 실제 수정전표·계정별 변동·증거·수행일·판단 근거로 수정 반영 대사를 기록합니다. 감사조정 표시만 바꾼 것을 실제 GL 반영으로 보지 않습니다.

양수·음수 절대금액과 세효과를 나눠 보여주며 상반된 오류를 무조건 상계하지 않습니다. 세효과 미확인 건수를 별도 표시합니다. 사소기준 미만도 자동으로 삭제하지 않으며 정성적 중요성·전체 왜곡표시 평가·회사 이견과 감사결론은 사람이 판단합니다.

## 위험·절차·조서 연결

1. 감사계획에서 적용 기준·중요성·절차 범위를 정하고 위험과 기존 대응계획을 기록합니다.
2. 위험·절차 연결에서 기존 위험의 경영진주장을 분류하고 고유위험·통제위험의 등급·근거, 유의적위험 여부와 근거를 직접 기록합니다. 별도 공시 묶음은 탐색을 위한 분류이며 기준서 전수 준수 인증이 아닙니다.
3. 대응절차의 성격·시기·범위를 적고 원본별 회사·기간·위치·관련성, 실행ID·결과 해시를 연결합니다. 같은 금액·파일명·해시만으로 관련성이나 증거 충분성을 확정하지 않습니다.
4. 실제 수행내용·일자·수행자와 증거 충분성·적합성 판단을 별도로 기록합니다. 자동검사 종료나 파일 보유는 사람의 실제 수행과 다릅니다.
5. 현재 기준으로 조서를 저장·수정하고 내용을 승인합니다. 별도 검토자는 검토 요청에 대해 검토기록을 남깁니다. 그 뒤 현재 조서 개정과 수행기록을 연결합니다. 필요하면 F03·왜곡표시ID·검토의견을 함께 연결합니다.

평가·대응·수행·자료 변경은 기존 조서와 AI 내용 승인을 다시 확인하게 만듭니다. 조서 본문을 바꾸면 연결한 본문 개정도 다시 확인해야 합니다. 연결 갱신 자체가 감사판단·내용 승인·별도 검토를 자동 생성하지 않습니다.

## Excel과 검증 범위

초안 Excel에는 왜곡표시 검토대장·상세·금액집계·동일오류 그룹·계정영향·실제 GL 수정 대사와 위험평가·대응·수행·조서 연결을 별도 표로 출력합니다. 모델 원응답·프로그램 근거·미검증 제안·인용·사람 내용 승인도 구분합니다. 전체 원문과 이력은 증적 JSON에서 복원할 수 있습니다.

긴 본문은 계속 행으로 나누며 숫자는 최초 행에만 기록합니다. 보관 잠금과 검토완료본 점검은 미완료 연결·현재 버전·사람 기록을 확인하지만, 전체 감사완료 또는 감사의견을 인증하지 않습니다.

자동검사의 가상 기록은 SYNTHETIC ONLY로 표시합니다. 실제 사람 승인·실제 한글 조합키·혼합 DPI·실제 Office 화면·실제 모델 호출과 서로 바꿔 보고하지 않습니다. 정확한 범위는 릴리스의 validation-report.json에 따릅니다.
