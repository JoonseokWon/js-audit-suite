# v2.0.0 화면 개선 및 감사업무 진행관리 사용안내

Windows에서 실행하는 회계감사 지원 프로그램입니다. 업무 요약 화면을 카드 형태로 구성해 등록 자료, 검사 결과와 조서 작성·검토 상태를 확인하기 쉽게 바꿨습니다. 기존 계산 정책과 작성·검토 이력은 유지하며 이전 실행파일과 저장 업무도 보존합니다.

업무는 **감사계획 수립 → 위험평가 → 감사증거 관리 및 계정별 검사 → 감사조서 작성·검토 → 감사파일 보관**의 흐름으로 확인합니다. 이 순서는 프로그램에서 기록을 정리하는 안내이며, 각 감사절차의 적용 여부와 실제 수행·결론은 사용자가 판단합니다.

## 실행과 화면 이동

`실행파일/통합 회계감사 v2.0.0.exe`를 실행합니다. 옆의 `portable-config.json`을 함께 두면 업무 위치가 `데이터/회사별업무`로 유지됩니다. 실행파일만 옮기기보다 폴더 전체를 보관하세요.

처음에는 **업무 요약**이 열립니다. 자료 수, 검사 결과, 원장 대사와 수행·검토 기록이 필요한 항목을 카드에서 확인합니다. 회사 선택 또는 업무 열기로 저장 업무를 연 다음, 왼쪽 메뉴에서 자료·검사, 원장·리드, 결과 상세, 검토후보, 감사조서, 감사증거·검토의견, 자료요청, 작업 이력, 감사계획·완료점검으로 이동합니다.

업무 요약의 계정 모듈을 누르면 자료·검사 화면에서 해당 모듈을 선택합니다. 이 이동만으로 더미 업무를 만들거나 자료를 등록·검사하지 않습니다. 자료를 선택하고 실행 버튼을 눌러 진행하세요. 저장하지 않은 작성 내용이 있으면 이동 전에 저장 여부를 확인합니다.

## 선명도와 화면 크기

Windows의 실제 모니터 배율과 프로그램 안의 글자 배율은 서로 다른 값입니다. OS 배율은 물리 픽셀 밀도에 대응하고, 프로그램 배율은 글자와 조작 영역의 크기를 바꿉니다. 화면이 흐리다고 느낄 때는 현재 EXE 버전과 실행한 모니터를 함께 확인하세요. 프로그램은 Windows 디스플레이·레지스트리·호환성 설정을 바꾸지 않습니다.

화면 배율 선택 또는 `Ctrl +`, `Ctrl -`, `Ctrl 0`으로 글자 크기를 조절할 수 있습니다. 작은 창에서는 카드와 버튼이 다시 배치되고 표·긴 양식은 스크롤로 확인합니다. 행을 선택하면 원본 행과 상세 근거를 확인할 수 있습니다. 표의 숫자는 비교하기 쉽도록 오른쪽에 정렬합니다.

수학적 DPI/레이아웃 검사와 실제 모니터에서 확인한 결과는 구분합니다. 다양한 DPI 값을 넣은 단위검사는 실제 Windows 배율을 바꾼 검사가 아닙니다. 현재 버전의 실제 화면·모니터 확인 범위는 배포 `validation-report.json`과 로컬 검증 기록을 따릅니다.

## 감사조서 작성·검토와 감사파일 보관

계정별 계산 결과와 원장 대사를 확인한 뒤 감사조서에 실제 수행내용과 결론을 기록합니다. AI 초안을 사용했다면 내용을 확인·수정하고 승인하며, 조서 검토는 별도로 진행합니다. 자료나 계획·본문이 달라지면 다시 확인할 항목을 표시합니다.

검토를 마친 조서는 **검토완료본 수정 제한**으로 실수로 바뀌지 않게 할 수 있습니다. 수정이 필요하면 **조서 수정 다시 시작**에서 사유를 남깁니다. **검토중 감사파일 저장** 또는 **검토완료 감사파일 저장**으로 원본자료·감사조서·작성 및 검토 이력을 하나의 ZIP 파일에 저장합니다. **저장 파일 확인**에서는 내용 변경이나 누락이 있는지 점검합니다. 검토완료 파일 저장에는 현재 자료와 작성·검토 기록의 요건 충족 및 사용자의 확인이 필요합니다.

이 기능은 프로그램에 기록한 범위의 파일 저장과 수정 관리입니다. 감사보고서 발행이나 실제 감사업무 완료를 대신 판단하지 않습니다. 감사기준서 230 문단 14~16의 ‘최종감사파일의 취합’과 프로그램의 ZIP 저장 버튼을 같은 의미의 완료 선언으로 보지 않습니다. [기준서 원문 안내](https://www.kicpa.or.kr/board/read.brd?bltnNo=11786004332051&boardId=acc0102)

감사기준 적용, 중요성 비율, 위험 평가, 실제 수행·조회·실사, 결론, 승인과 검토는 사람이 기록합니다. 카드의 숫자와 원장 대사 일치는 전체 감사를 완료했다는 뜻이 아닙니다. 회사명이 **JS**이면 업종 없는 모회사이며, JS전자·JS자동차·JS반도체·JS바이오는 각각 별도 합성업무입니다.

AI 응답 생성·조서 적용·최종내용 승인·별도 검토는 서로 다른 단계입니다. 이름 입력은 로그인·본인인증·전자서명이 아닙니다. 이번 UI 변경 검증에서 실제 AI 모델을 호출했는지, 실제 한글 조합 키 입력을 새로 확인했는지는 검증보고서에 별도로 표시합니다.

## 참고와 적용 범위

명확한 버튼 문구, 간결한 설명, 정보 위계와 논리 크기/에셋 밀도의 구분은 [앱인토스 UI/UX 가이드](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide)를 참고했습니다. 해당 문서의 모바일 전용 해상도·탭바·입점 규정은 이 Windows 프로그램의 요구사항이 아닙니다. 토스의 로고·아이콘·일러스트는 복제하지 않고 자체 구성 요소를 사용합니다.

공식 예시서식의 메타데이터와 절차 참고 연결은 v1.9의 범위를 유지합니다. 공식 원본 서식의 모든 셀 자동작성, 전체 감사기준 준수 인증, 감사의견을 제공하지 않습니다. 원본 PDF·공식 예시 ZIP·실제 회사 자료·업무 DB·모델·API 키는 공개 배포에서 제외합니다.

## 현금흐름표 독립 도구

더보기에서 현금흐름표 도구를 열거나 EXE에 `--tool cashflow`를 지정하면 별도 창으로 실행합니다. 이 도구는 기존 현금흐름표 엔진·Excel 입력 계약을 유지하며, 통합 프로그램의 16개 분석 모듈과 다른 입력 양식을 사용합니다. 화면에 표시되는 자체 예제와 입력 양식을 확인하고 자료를 선택하세요.

현재 통합 업무의 원장·회사·증거·조서를 자동으로 가져오거나 대사·조서에 연결하지 않습니다. 결과를 조서 근거로 사용할 때는 적용 범위와 입력·분류를 사람이 검토한 뒤 필요한 업무에 별도로 등록해야 합니다. 창을 여는 것만으로 실제 업무를 만들거나 수정하지 않습니다. 구형 독립 EXE와 계산 원본은 보존합니다.

## 코드 구조

| 위치 | 역할 |
| --- | --- |
| `app.py` | 작은 실행 진입점과 기존 import API |
| `desktop/shell.py` | 창, 헤더, 탐색과 전체 화면 조합 |
| `desktop/design.py` | 색, 글자, 간격과 공통 테마 |
| `desktop/views/` | 업무 요약·자료·결과·조서 등 기능별 화면 |
| `desktop/actions/` | 업무 열기·검사·조서·요청·출력 등의 작업 |
| `desktop/widgets/` | 벤토 카드·배치·버튼 묶음·표·탐색 |
| `desktop/ai/` | AI 초안·설정·사용자 확인 화면과 작업 |
| `desktop/workflow/` | 감사계획·위험평가·절차·조서 검토·감사파일 보관 화면과 작업 |
| `dpi_support/` | Windows DPI와 화면 지표 처리 |
| `desktop/tools/cashflow/` | 별도 입력 계약의 현금흐름표 도구와 보존한 계산 모듈 |
| 기존 엔진 모듈 | 계산·대사·저장·감사기록 계약 |
| `tools/release_v20/` | 공개 범위·증거·첨부·Git·CI·게시의 작은 모듈 |

현금흐름표의 `engine.py`·`excel_io.py`·`samples.py`는 기존 계산 계약을 보존한 도메인 복사본입니다. 이 원문 보존 파일은 새 UI 모듈의 줄 수 제한과 구분하며, 화면·이벤트·배치 코드는 별도 작은 모듈로 나눴습니다.

구형 단독 금융상품·매출 EXE는 당시 화면과 배포 이력을 보존한 별도 실행파일입니다. 최신 UI는 통합 v2의 해당 계정 모듈에서 확인하세요. 보관 원본을 현재 버전으로 오인하지 않도록 실행파일 이름과 창 버전을 확인합니다.
