# 통합 회계감사 v1.7 사용안내

v1.7은 JS 모회사와 4개 업종별 자회사의 합성자료로 원장·계산·원천 연결과 조서 작성·검토를 연습하는 Windows 로컬 프로그램이다. 현재 입력과 구현 범위는 이 문서를 우선하며, 구형 공통 모본과 이전 버전 검증 기록은 별도로 읽는다.

## 1. 회사 선택과 모회사 범위

배포 압축파일을 풀고 해당 버전 EXE를 실행한다. 소스 이용자는 프로젝트 폴더에서 필요한 패키지를 설치한 뒤 `python app.py`를 실행한다. 상단 **모회사·자회사**에서 회사를 고르면 처음에는 내장자료로 새 업무를 준비하고, 이후에는 해당 회사의 최근 저장 연습을 연다. 실제 회사명·코드·기간·업무 경로를 확인한다.

| 회사 | 코드 | 이번 자료 범위 |
| --- | --- | --- |
| JS | JS | 업종 없는 모회사. 현금·자회사투자주식·자본의 축소 별도 원장 |
| JS전자 | JS_ELEC | 전자부품·소재의 합성 자회사 업무 |
| JS자동차 | JS_AUTO | 자동차부품·가공소재의 합성 자회사 업무 |
| JS반도체 | JS_SEMI | 검사용 합성 반도체·소재의 합성 자회사 업무 |
| JS바이오 | JS_BIO | 연구용 시약·배지의 합성 자회사 업무 |

모회사 JS에는 판매 품목이나 제조업종을 부여하지 않는다. 축소 원장은 가상 자본 납입 1,000만원에서 자회사별 200만원씩 총 800만원을 투자하고 현금 200만원이 남는 가정이다. 자회사라는 역할 명칭과 지분율 설정은 구분한다. 지분율·실제 취득증빙·투자주식 평가·연결제거·연결재무제표는 미설정 또는 미검사다. 원장 합계만으로 이 범위를 수행했다고 표시하지 않는다.

JS는 원장·리드 1개 모듈을 준비하며 자회사 제조·판매·재고·급여 자료를 가져오지 않는다. 그 외 모듈이 자동 실행되지 않는 것은 모회사 자료 범위를 명시한 결과다. 투자·자본 등 조서 계획이 있어도 실제 수행·판단·검토가 끝난 것은 아니다.

4개 자회사는 각각 15개 모듈을 준비한다. 업종별 품목·자산·거래처·적요를 맞췄지만 동일 검사용 모본의 금액·수량·날짜·단위·계산정책을 유지한다. 실제 시장가격·제조원가·생산능력·수율을 추정하지 않는다. JS반도체는 실제 팹·웨이퍼 생산을, JS바이오는 의약품 임상·허가·GMP 적합성을 모사하지 않는다.

## 2. 로우데이터를 확인하는 방법

회사를 선택해 준비가 끝나면 상단 **로우데이터**를 누른다. 회사 선택으로 만든 v1.7 연습의 최초 더미 입력과 확인용 원천 Excel이 있는 폴더를 연다. EXE 내부 임시 리소스나 구형 공통 더미를 직접 찾는 대신 현재 회사·업무 경로를 기준으로 확인한다. 일반 수동 업무·구버전 업무는 이 버튼의 대상이 아니므로 등록 원본 위치를 확인한다.

| 자료 | 의미와 확인할 점 |
| --- | --- |
| `inputs/`의 XLSX·JSON·`.auditpack` | 처음 연습을 만들 때 사용한 더미 입력. 이후 별도로 등록한 최신 입력과 구분한다. |
| `원천엑셀/01_현재프로그램입력/`, `원천엑셀/02_절차별원천자료/` | 자회사 원천팩에 들어 있는 16권을 안전하게 추출한 확인용 자료. 문서·시트·행과 금액을 결과 상세와 비교한다. |
| `metadata/` | `master.json`·`profile.json`·`plan.json`의 회사·역할·품목·범위와 검토계획. 수령 증거나 실제 감사 결론을 뜻하지 않는다. |
| `업무/원본/` | 검사·증거 등록 때 해시와 함께 고정해 보관한 실제 사본. 다시 등록한 자료와 개별 실행 근거는 해당 자료 ID로 확인한다. 일반 업무에서는 선택한 업무 폴더 바로 아래의 `원본/`이다. |
| `sector_resources/companies/<회사코드>/` | 회사별 내장 모본. EXE에서는 내부 리소스로 포함될 수 있다. 연습 기록과 구분한다. |
| `samples/`, `raw_input_seed/`, `testdata/` | 과거 공통 모본·오류 반례·회귀 검사 또는 독립 사례. 현재 회사 입력을 의미하지 않는다. |

자회사 원천에는 계산용 9권과 절차별 원천 7권이 포함되며 전체 114표를 보존한다. 인사·급여, 매출·매입·재고, 자금·금융, 자산·손상, 세무·자본, 결산·공시 등 여러 후속 검토용 원문이 있다. 과거·후속기간·별도 참고자료까지 모두 현재 회사의 검증 모집단으로 간주하지 않는다. JS 모회사에는 자회사 원천팩을 붙이지 않는다.

원천 파일·시트·실제 Excel 행과 결과의 연결은 **결과 상세 → 원천증빙**의 `원천자료목록`, `원천자료범위`, `거래배부`, `원천대사`, `현재원장연결`에서 확인한다. 같은 금액이라는 이유만으로 거래 관계를 추정하지 않고 명시한 연결키·배부를 읽는다.

최초 입력·확인용 원천·회사 설정이 누락되거나 바뀌면 로우데이터 열기를 차단한다. 수정 연습은 원본을 다른 위치에 복사해 수정하고 그 파일로 다시 검사한다. 이미 저장한 검사 결과와 조서는 자동으로 갱신되지 않으므로 조서를 다시 저장·검토한다. 내장 모본이나 `원본/`을 직접 덮어쓰지 않는다. 자료가 바뀌거나 원장 검사를 다시 실행하면 예전 연결·검토 상태가 유효한지도 다시 확인한다.

## 3. 차대변 검사와 원장 대사의 차이

원장 검사에는 전표별 차대변 일치가 포함된다. 그 외 독립 통제값·GL/TB 연결·계정별 계산과 원천 배부 검사도 있다. 각 단계는 서로 다른 주장과 범위를 다룬다.

| 단계 | 계산·연결 예시 | 결과를 읽는 방법 |
| --- | --- | --- |
| 독립 추출 통제 | 제출한 추출 행수·차대 총액과 읽은 원장 비교 | 전표 전체가 빠져 차대가 함께 줄어도 통제값과의 차이를 찾을 수 있다. 통제값 자체의 독립성은 별도 확인한다. |
| GL → TB | 계정 기초와 원장 차변·대변 변동을 합쳐 TB 기말과 비교 | 총합만 같아도 계정이 잘못 연결되면 계정별 차이를 확인한다. |
| 계산 → 연결 계정 | 이자·매출·감가상각·리스·충당금·재고·급여·비용이연의 지원 지표와 TB 비교 | 원장 기대금액·계산값·차이·비교 계정·부호·기준을 확인한다. |
| 원천 → 대상 | 명시한 원천행·대상행·부호 금액을 배부하고 중복·미배부·과배부 검사 | 선택한 두 모집단의 관계다. 회사 전체 거래를 자동 연결한 것으로 읽지 않는다. |
| 원천팩 → 현재 GL/TB | 원천팩의 GL 행·TB 계정과 현재 업무 원장 입력을 비교 | 예전 원장 또는 다른 회사 자료가 섞였는지 확인한다. |
| 재무제표 → TB·주석 | 합계·소계·계정 매핑·선택 본문·주석 금액 비교 | 조정전·미마감 TB와 선택한 재무제표 입력 범위다. |

**원장·리드**에서 현재 원장 연결, **결과 상세**에서 해당 모듈의 계산표·원본행·대사표를 함께 확인한다. 일치 수치가 있다는 사실과 실제 수행·판단이 끝났다는 사실은 구분한다. 의심 후보가 있어도 원장 연결은 일치할 수 있다.

자회사 정상 모본은 회사별 15개 모듈·35개 원장 연결을 검사하도록 구성한다. 원천팩은 선택 원천 32행·대상 32행에 대한 명시 배부 32건을 다룬다. 같은 거래가 단계마다 반복될 수 있으므로 배부액·차이·연결 건수를 모두 합쳐 전체 왜곡표시나 검사 거래 수로 계산하지 않는다.

같은 생성기의 합성 원장·은행·원천·통제값은 수치 연결 기능을 시험하는 자료다. 실제 감사의 독립 증거가 아니다. 원문 진위·추출의 전체 완전성·실제 거래 실질·감사기준 충족은 이 일치 검사만으로 확정하지 않는다.

## 4. 원천 연결에서 미확인으로 남는 8개 범위

**결과 상세 → 원천증빙 → 연결범위**에서 미확인 항목을 읽는다. 정상 원천팩에서도 아래 8개가 남는다. 일치로 바꾸기 위해 없는 회사·기간·단위를 임의로 채우지 않는다.

| 범위 | 미확인 이유 |
| --- | --- |
| 은행거래 ↔ 은행장부의 원천 | 원문 회사·기간 열이 일부 없어 패키지 선언 문맥만 확인 |
| 은행거래 ↔ 은행장부의 대상 | 원문 회사·기간 열이 일부 없어 패키지 선언 문맥만 확인 |
| 은행장부 ↔ 현금계정 원장의 원천 | 원문 회사·기간 열이 일부 없어 패키지 선언 문맥만 확인 |
| 매출 송장 공급가액 ↔ 매출보조원장의 원천 | 원문 회사·기간 열이 일부 없어 패키지 선언 문맥만 확인 |
| 송장 총액 ↔ 채권계정 원장의 원천 | 원문 회사·기간 열이 일부 없어 패키지 선언 문맥만 확인 |
| 입고·출고·재고 수량 및 취득원가 | 일부 거래별 원가·공통 연결키 부족. 수량×단가·단위환산은 이 열합산 배부 범위 밖 |
| 후속 회수·급여 지급·리스 월별 지급 ↔ 개별 은행거래 | 일부 후속기간 자료·연간 집계를 개별 당기 은행거래로 간주하지 않음 |
| 토지 권리·자산 취득증빙 및 나머지 계정군 | 원문은 보존하지만 거래별 상호 대사와 권리·평가 등의 판단은 별도 절차 |

미확인 범위 8개는 업종별 전용 계산이 없는 수동계획 8개와 다른 집합이다. 재고평가 모듈이 수량×확정 원가단가를 계산하는 기능과 원천팩 배부에서 수량·단위환산이 미확인인 사실도 서로 다르다. 판매 포장품 EA와 벌크 보관품 KG를 자동 환산·일치시킨 것으로 해석하지 않는다.

## 5. 재고와 급여의 분리

두 계정은 별도 모듈·입력 파일·계산 결과·조서로 관리한다.

| 구분 | 재고 | 급여 |
| --- | --- | --- |
| 모듈 | 재고평가 | 종업원급여 |
| 조서 | A11 | A16 |
| 입력 예시 | 품목·로트·수량·확정 원가단가·단위 NRV·평가손실/환입 | 인사·월급·승인 수당/공제·지급·미지급·단기 누적연차·약정 DC |
| 별도 판단 | 실사·진부화 근거·원가배부·수율·단위환산 | 세액·최저요율·DB 계리·퇴직정산·개별 지급 진위 |

모듈별 원장 연결도 각각 확인한다. 구형 공통 파일의 묶음 이름·과거 적요나 여러 시트가 한 원천책에 있다는 이유로 두 감사절차를 합치지 않는다. 현재 회사는 회사 선택에서 준비한 해당 입력과 조서를 기준으로 읽는다.

## 6. 자료요청과 로그가 남는 시점

**자료요청**에서 요청자료·요청처·기한·요청범위·상태를 입력하고 **요청·수령 기록 저장**을 눌러야 로컬 업무 이력에 남는다. 상태를 바꾼 뒤 다시 저장하면 같은 요청의 새 개정 이벤트가 남으며 이전 저장 내용도 보존한다.

**검토후보 → 자료요청 초안**은 입력폼만 채운다. 초안을 보는 것 또는 저장 전 타이핑은 저장 이벤트가 아니다. 요청 저장은 이메일 실제 발송을 뜻하지 않으며 프로그램이 외부 수신자에게 메일을 보내지 않는다. 처음 연습을 만들 때 업종별 60개 문서 템플릿을 실제 자료요청으로 자동 생성·발송·수령하지 않는다.

자료를 받았다면 **증거 파일 등록**으로 사본을 보관하고 요청과 연결한다. 요청 상태는 요청·부분수령·수령·검토완료·취소다. 부분수령·수령·검토완료에는 등록한 증거가 필요하며 취소 사유도 기록한다. 상태 목록을 눌렀다는 사실과 저장 완료는 구분한다.

**작업 이력**에서 업무별 저장 이벤트를 확인한다. 현재 화면에 보이는 최종 상태 외에 이전 개정 내용을 조회할 수 있다.

| 이벤트 | 저장되는 내용 |
| --- | --- |
| 업무 생성 | 회사·기간·작성자 등 업무 기본정보 |
| 자료 등록 | 사본 경로·자료명·자료유형·원래 경로·등록 시각·SHA256·크기 |
| 검사 실행 | 입력자료 ID·실행 시각·결과·결과 해시·취소 여부 |
| 자료요청 저장 | 요청 ID·요청처·기한·범위·상태·연결 증거·갱신 시각 |
| 조서 저장·개정 | 조서 ID·작성자·실제 수행일·수행내용·판단·결론·증거·기준 자료 버전 |
| 검토요청·검토결과 | 조서 상태·입력한 검토자·검토내용·검토 시각 |
| 검토의견 | 제목·의견·입력한 이름·해결 상태·시각 |

자료요청에는 인증된 요청자 계정 필드가 없다. 조서 작성자·검토자·의견 작성자도 사용자가 입력한 문자열이다. 이름이 같으면 검토를 차단하는 정책은 있지만 서로 다른 이름이 실제 서로 다른 사람인지는 인증하지 않는다. 실행·저장 시각은 로컬 환경 시각에 의존한다.

이력은 로컬 SQLite 이벤트의 순서·이전 해시·현재 해시와 별도 헤드를 검증하며 등록 사본도 해시로 확인한다. 누락·일반 변경을 검출하는 통제다. 로그인 본인인증·인증 전자서명·외부 불변 감사로그를 제공하지 않는다. DB·헤드·코드에 모두 접근할 수 있는 관리자를 상대로 독립된 제3자 증명으로 표현하지 않는다.

## 7. 조서 작성·검토·출력

처음 생성한 조서는 미검토 초안이다. 업종별 위험·목적·요청문서 계획과 계산 결과가 연결돼도 실제 수행·결론·검토자를 자동 완료하지 않는다.

1. **절차·조서**에서 관련 절차를 고른다. 재고는 A11, 급여는 A16이다. GLA·FIA·현금 후보의 연결 조서는 G01·I01·H01이다.
2. 실제 작성자·수행일·검토한 자료·범위·수행내용·판단·결론을 기록하고 증거를 연결한다.
3. **조서 저장·개정**으로 저장한다. 현재 자료 버전을 근거로 새 개정이 남는다.
4. 준비가 끝나면 **검토 요청**을 누른다. 필수 수행·결론·증거·현재 자료 연결을 확인한다.
5. 작성자와 다른 검토자가 확인하고 검토의견 또는 **검토기록 완료**를 남긴다. 이름 입력은 비인증이다.
6. 진행 중에는 **검토중 저장**, 요건을 충족했을 때는 **검토완료본**으로 Excel을 출력한다.

차단 오류·원장 연결 미확인·필수 조서 누락·미완료 자료요청·미해결 검토의견·자료 변경 후 재검토가 남으면 검토완료본 출력이 차단될 수 있다. 출력 상태는 선택한 조서의 검토기록 상태이며 전체 감사 완료나 감사의견 발행을 뜻하지 않는다.

조서 저장은 새 개정이다. 이전 검토가 있었더라도 새로 저장하면 작성중으로 돌아가 현재 자료·내용을 다시 검토한다. 저장 전 입력은 이력으로 남지 않으므로 중요한 내용은 명시적으로 저장한다. 이미 출력한 Excel은 그 시점의 정적 사본이다.

## 8. 회사 전환·새 연습·백업

다른 회사를 고를 때 미저장 조서와 자료요청이 있으면 저장·버리기·취소를 확인한다. 아직 저장하지 않은 검토자·검토내용도 확인한다. 취소하면 기존 회사에서 계속하며 전환 실패·준비 취소 때도 기존 업무를 유지한다. 준비·검사 중에는 입력이 잠기므로 완료 또는 취소 안내를 기다린다.

같은 회사를 다시 선택하면 최근 저장 연습을 연다. **새 연습**은 고유한 새 폴더를 만들어 과거 기록을 보존한다. 더 이전 연습은 **업무 열기**에서 해당 폴더를 골라 연다. 일반 업무 열기로 연 경로와 회사 선택의 최근 연습 목록은 별개다.

기본 보관 위치는 `%LOCALAPPDATA%\JSAudit\sector-demos\v1.7`이다. Windows 탐색기의 주소창에 넣으면 열 수 있다. 실제 선택한 업무 경로는 화면에서 다시 확인한다. 이전 v1.6 사용자 업무는 다른 보관 위치에 있으며 자동 덮어쓰기하거나 모회사 새 원장으로 교체하지 않는다.

회사별 최신 연습 목록과 과거 연습 전체를 보존하려면 보관 위치 전체를 백업한다. `store.json`, `companies/` 아래 연습별 `session.json`, 입력·메타자료·업무 폴더를 함께 보존한다. 목록의 ID나 경로를 임의 편집하지 않는다.

개별 업무를 옮길 때는 업무 폴더 전체를 복사한다. 특히 `업무.sqlite3`, `이력헤드.json`, `원본/`을 함께 보존한다. DB 하나나 출력 Excel만으로 원문과 이력 전체를 복구할 수 없다. 다른 PC·다른 위치에서는 **업무 열기**로 연다.

파일 누락·변조·DB/헤드 불일치·회사코드 오류가 있으면 열기를 차단한다. 기존 폴더를 보존하고 오류 내용을 확인한다. **새 연습**은 별도 업무를 만드는 기능이며 손상된 과거 업무의 복구 기능이 아니다.

## 10. 검증 기록과 공개 배포

소스 검사를 재현하려면 프로젝트 폴더에서 실행한다. 출력 폴더는 새 폴더 또는 빈 폴더를 사용한다.

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -v
python tools/verify_headless_v17.py --output-dir 검증/직접재현_v17_headless
```

현재 버전의 통과 수치·모회사/자회사 범위·혼입 반례·이력 보존·미검토 출력 차단은 이 배포의 검증 보고서로 확인한다. 소스에서 화면 없이 실행한 검사, 실제 창을 사용한 소스 검사, EXE 독립 실행, 원격 CI는 서로 다른 범위다. 이전 v1.6의 75개 모듈·175개 연결을 JS 모회사 분리 후 새 검증 결과로 사용하지 않는다.

EXE 용량·SHA256·빌드와 실행 기록은 해당 배포 기록을 따른다. [공개 저장소](https://github.com/JoonseokWon/js-audit-suite), [Actions](https://github.com/JoonseokWon/js-audit-suite/actions), [v1.7.0 릴리스](https://github.com/JoonseokWon/js-audit-suite/releases/tag/v1.7.0)에서 소스·원격 검사·배포 상태를 확인한다. 기존 개인 프로젝트 저장소의 메일·지원 처리 이력은 이 공개 저장소의 대상이 아니다.

포트폴리오에는 “회계 요구사항과 검증 관점을 설계하고 AI의 도움으로 구현한 로컬 감사 지원 프로그램”으로 설명할 수 있다. 합성 자료의 입력 통제·원장/증빙 연결·예외 검토·저장 이력을 보여 주되 실제 고객 감사를 수행하거나 감사의견·업종 전체 판단을 자동 완성했다고 표현하지 않는다.
