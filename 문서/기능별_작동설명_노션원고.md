# JS 통합 회계감사 프로그램 — 기능별 작동 설명

이 문서는 v1.7 계산·저장 계약과 v1.7.1 화면을 유지하면서 v1.8의 실제 AI 조서·사람 수정·내용 승인을 추가하는 포트폴리오·사용설명 원고다. 회사 선택부터 로우데이터, 15개 통합 모듈, 자료요청, 조서 작성·검토, 작업 이력, Excel 출력까지 설명한다. 9개 계정군의 독립 증빙연습은 15개 통합 모듈과 구분한다. v1.8.0 배포 대상의 코드 기능을 설명하며 AI의 실제 모델·GUI·EXE 검증과 공개 릴리스는 최종 검증 기록으로 확인한다. 실제 OpenAI 호출은 미검증이며 모의 HTTP 검사와 구별한다.

개발자의 역할은 **회계 요구사항과 검증 관점 설계**이며, **AI가 코드 구현과 자동 검사 실행을 지원**했다. 명시한 입력·정책·규칙에 따라 수치 계산·대사를 수행한다. v1.8에서는 실제 로컬 AI가 근거 기반 조서 초안을 제안하고, 사람이 수정·저장·내용 승인한다. 선택 OpenAI API는 사용자가 제공자와 전송 근거를 확인한 경우에만 실행하며 키를 파일·조서·로그에 저장하지 않는다. 실제 수행과 판단의 책임·별도 검토는 사람에게 있다.

이 문서의 기능 설명과 최종 빌드·릴리스 게시 상태는 구분한다. 검증 통과 수치, EXE SHA256, 원격 자동검사와 배포 완료 여부는 해당 버전 검증 기록을 확인한다.

## 조서 초안 작성 위치와 화면 배율

**회사 선택 → 상단 조서초안 작성 → 계정/절차 선택**으로 작성 화면을 연다. **조서초안·작성** 탭도 같은 화면이다. 목적·위험·범위·계산근거를 확인하고 실제 수행·판단·결론을 작성하거나 AI 제안을 검토·적용한 뒤 **조서 저장·개정**으로 업무에 저장한다. AI 적용 조서는 사람이 **AI 내용 최종 승인**하고 별도 조서 검토를 거친다. **초안 Excel 내보내기**는 저장한 업무의 XLSX 초안 출력이며 v1.7.0의 **검토중 저장**에 대응한다.

오른쪽 조서 입력영역은 세로 스크롤로 아래 항목까지 이동하고 저장·검토요청 버튼은 하단에 둔다. 하단 초안 출력은 폭이 충분할 때 표시되며 좁은 창에서도 **상단 초안 Excel 내보내기**는 사용할 수 있다. 상단 **화면 배율**은 90%·100%·110%·125%·150%·175%를 제공한다. Windows 시스템 DPI 인식과 기본 11pt 글꼴도 보완하며, 앱 배율은 계산값·합성자료·저장한 조서 내용을 바꾸지 않는다. 해상도·Windows 설정을 변경하는 기능은 아니다. 기존 v1.7 사용자 업무를 이어서 사용한다. 자세한 조작은 [v1.8 사용안내](v1.8_사용안내.md)를 따른다.

좁은 창·큰 배율에서는 보조 기능을 **기타 기능 ▾** 메뉴로 모은다. 새 업무·업무 열기·계정별 증빙연습·로우데이터·자료 복사·검토완료본은 이 메뉴에서 찾고, **조서초안 작성·초안 Excel 내보내기·화면 배율**은 상단에서 사용한다. 탭 제목이 가려지면 **기타 기능 → 화면 이동**에서 전체 8개 화면을 선택한다.

## 전체 흐름과 읽는 순서

**회사 선택 → 자료 확인 → 원장 통제 → 계정별 재계산·원천 연결 → 예외 조사·자료요청 → 조서 작성 → 검토 → Excel 출력** 순서로 사용한다.

| 용어 | 이 프로그램에서의 의미 |
| --- | --- |
| GL | 총계정원장. 전표·행 ID, 계정, 날짜, 차변·대변 등의 상세 기록 |
| TB | 시산표. 계정별 기초·차변·대변·기말잔액 |
| 리드스케줄 | TB 계정을 감사 계정군에 매핑하고 조정 전후 금액을 정리한 표 |
| 대사 | 서로 다른 입력의 금액·범위·식별자·기간 등을 비교하는 것. 차대변 일치 검사는 그 일부 |
| 차단 | 필수자료·형식·회사·기간·통제 등에 문제가 있어 해당 결과를 정상 분석으로 사용할 수 없는 상태 |
| 검토·후보 | 조사할 차이나 조건이 있다는 뜻. 오류·부정 확정이나 발생확률이 아님 |
| 미확인 | 필요한 정보나 검사가 부족한 범위. 조건 불해당·안전·금액 0으로 바꾸지 않음 |
| 조서 | 목적·위험·모집단·실제 수행·판단·증거·작성/검토 기록을 담는 업무 문서 |

원장·은행·명세·통제값은 같은 생성기로 만든 합성자료다. 입력 간 연결 기능을 시험하지만 실제 감사에서 요구되는 독립 증거의 확보·진위 확인을 대신하지 않는다. **같은 생성기의 자료끼리 일치하는 것과 독립 감사증거로 검증하는 것은 다르다.**

## v1.8 추가 — 실제 AI 근거 초안과 사람의 내용 승인

**목적·입력**  
선택한 회사·절차의 목적·위험·범위·수행내용·결론을 현재 원문·계산·대사에 연결해 제안한다. 업무·절차·원본/결과 해시, 자료·실행 버전, 제한된 원문·표 발췌와 미확인 범위를 사용한다. 실제 수령·실사·조회·검토완료를 지어내는 도구가 아니다.

**실제 처리**  
**AI 설정 → AI 초안 생성 → 초안 보기·적용 → 사람 수정·조서 저장·개정 → AI 내용 최종 승인 → 별도 검토**의 흐름이다. 미리보기의 AI 초안·근거·대사 탭에서 인용과 실제 패킷을 읽고 현재 조서에 적용한다. 기본 로컬은 Ollama 0.40.7의 `qwen3:4b-instruct-2507-q4_K_M`이며 앱은 CPU0·문맥16384·제한300초를 전달한다. 모델·런타임은 **AI 설정 → 로컬 AI 준비 (최초 1회)**가 필요하며 앱 시작만으로 다운로드하지 않는다. 선택 OpenAI는 제공자·모델을 지정하고 요청 전에 전송 근거를 확인·동의한 경우에만 호출한다.

**근거와 응답 검사**  
화면은 12,000자·40참조 이내, 표당3행·자료/실행별 최대8표·셀300자·원문자료 최대2개 발췌와 절단/생략 정보를 보존한다. 선택 계정 모듈·원장 실행을 우선하고 미선택 자료/실행은 건수·명세 해시만 남기며 전체 업무 버전에 포함한다. 엔진 직접 호출의 기본 한도24,000자·70참조·표5행·원문자료5개와 구별한다. 실제 응답의 5개 필드마다 현재 참조ID가 있어야 하며 회사·절차·근거 버전도 일치해야 한다. 구조·인용·과장 문구·금지정보 검사를 통과하지 못한 응답은 저장 가능한 초안으로 보지 않는다. API 실패 때 고정 문구를 AI 결과로 대체하지 않는다. 문서의 지시는 비신뢰 데이터로 취급한다.

**예외·조서/로그**  
AI 응답 생성은 `ai_draft`, 적용은 `ai_apply`, 사람 수정은 조서의 새 개정, 최종내용 승인은 `ai_content_approval`로 각각 보존한다. 실제 수행일은 AI가 설정하지 않는다. 자료·검사 실행이 달라지면 새 AI 초안이 필요하고, 조서를 다시 저장·수정하면 내용 재승인이 필요하다. 기존 작성자와 다른 검토자 조건 등도 유지하며 두 승인 통제를 모두 충족해야 검토완료본을 출력한다. 초안에는 AI초안목록·AI근거참조·AI적용이력·AI최종내용승인 시트와 증적JSON을 포함한다.

**한계**  
인용·해시가 있다는 사실은 모든 문장의 정확성·기준 적용·원문 진위·독립성을 인증하지 않는다. 내용 승인자는 입력한 이름이며 인증된 전자서명이 아니다. AI 내용 승인은 전체 감사 완료·감사의견이 아니다. 모의 HTTP·실제 모델·GUI·EXE·실제 외부 API 검증을 따로 기록한다. 상세한 [AI 응답 계약](AI응답계약.md)과 [로컬 AI 설치안내](로컬AI_설치안내.md)를 함께 읽는다.

## 01. 모회사·자회사 선택과 회사별 업무 보관

**목적**  
회사별 자료와 작업 이력을 섞지 않고, 저장한 연습을 다시 이어서 사용한다. JS는 업종 없는 모회사이고 JS전자·JS자동차·JS반도체·JS바이오는 각각 업종 맥락을 가진 합성 자회사다.

**필요 로우데이터**  
회사코드·명칭·기간, 회사별 내장 입력, 품목/자산 마스터, 회사 설정, 업종 검토계획을 사용한다. JS 모회사는 현금·자회사투자주식·자본의 축소 별도 원장 1권만 사용한다. 자회사는 각각 15개 모듈 입력을 사용한다.

**실제 검사·계산**  
처음 선택하면 내장자료 해시를 확인하고 별도 사용자 업무 폴더로 복사한 뒤 원장부터 해당 모듈을 실행한다. 정상 준비와 원장 연결 확인을 마친 다음 화면의 업무를 교체한다. 같은 회사를 다시 선택하면 최근 업무 ID와 저장 이력을 유지한다. **새 연습**은 새 고유 폴더를 만든다.

**예외 결과**  
내장자료 누락·해시 불일치, 다른 회사 업무, DB/헤드 손상, 준비 중 실패·취소는 정상 준비로 처리하지 않는다. 기존 업무를 조용히 초기화하거나 실패한 새 업무로 덮어쓰지 않는다. 전환 전 미저장 조서·요청·검토 입력을 확인한다.

**조서·원장 연결**  
생성한 회사의 실제 원장 실행을 바탕으로 조서 초안을 만든다. 회사별 기록은 서로 다른 DB에 저장한다. JS 모회사의 가상 원장은 자본 납입 1,000만원, 자회사별 투자 200만원씩 총 800만원, 잔여 현금 200만원인 축소 예시다.

**한계**  
모회사에 업종·판매 품목·재고·제조자료를 부여하지 않는다. 역할상 자회사라는 명칭이 지분율·지배력 평가를 뜻하지 않는다. 투자취득 근거·투자주식 평가·은행조회·내부거래 제거·연결재무제표는 미검사다. 모회사·자회사의 합계를 연결재무제표로 제시하지 않는다.

## 02. 로우데이터 확인·입력 등록·공통 입력 통제

**목적**  
검사에 사용한 입력과 확인용 원문을 눈으로 확인하고, 원본 위치와 계산 결과의 관계를 추적한다.

**필요 로우데이터**  
계산용 XLSX, 구조화 재무제표 JSON, 원천증빙 패키지인 .auditpack, 일반 증거 파일을 사용한다. 모듈별 필수 시트·헤더·ID·날짜·통화·독립 통제값을 준비한다.

**실제 검사·계산**  
**로우데이터**는 회사 선택으로 만든 v1.7 연습 폴더를 연다. inputs/는 최초 더미 입력, metadata/는 회사 설정·계획, 자회사의 원천엑셀/은 패키지에서 검증 후 추출한 원문 16권이다. 실제 검사·증거 등록은 업무/원본/에 별도 사본을 저장하고 SHA256·크기·자료 ID를 기록한다. XLSX는 물리 행과 열을 읽어 시트·헤더·한도·수식/오류 셀·외부연결 등을 검사한다.

**예외 결과**  
필수값 공란·중복 ID·형식 오류·수식·미지원 외부연결·행 한도 초과 등을 차단한다. 빈 금액을 0으로 바꾸거나 Excel에 적힌 작은 범위만 믿고 나머지 행을 무시하지 않는다. 최초 입력·원천 열람사본이 누락·변경돼도 정상 원본처럼 열지 않는다.

**조서·원장 연결**  
모든 검사 실행은 등록한 사본의 자료 ID와 결과 해시를 가진다. 재등록·재검사 이후의 최신 근거는 최초 inputs/와 구분하고 업무/원본/의 해당 자료 ID로 확인한다. 조서에 실제 사용한 원본 사본을 연결한다.

**한계**  
해시는 등록 이후 변경 여부를 확인하는 장치이며 제출자 신원·실제 문서 진위·모집단 완전성을 입증하지 않는다. 일반 새 업무·구버전 업무는 로우데이터 버튼 대상이 아니므로 등록 원본 위치를 확인한다. 지원 행수는 모듈마다 다르며 대부분 10,000행, 기존 금융상품·매출·감가상각 등의 통합 입력은 더 작은 한도를 적용한다. 원문 내용은 분석 대상이며 프로그램에 대한 실행 지시로 취급하지 않는다.

## 03. 원장·리드 — 추출 통제, GL/TB 대사, 리드스케줄

**목적**  
후속 분석이 사용할 원장의 회사·기간·계정 범위를 정하고, 단순 차대변 일치 외에 추출 행수·총액·계정별 잔액을 검증한다.

**필요 로우데이터**  
설정, 시산표, 총계정원장, 계정매핑, 독립통제, 감사조정, 모듈연결의 7개 시트가 필요하다. GL에는 회사·전표 ID·행 ID·전기일·계정·차변·대변·적요·작성자를 넣는다. 독립통제에는 계정별 추출 행수·차대합계·기초/기말·추출근거·추출시각을 넣는다.

**실제 검사·계산**  
전표별 차대합계, GL 복합키 중복, 기간 밖 전표, 동일 행 차대 동시 양수를 검사한다. 각 계정의 GL 행수·차변·대변을 독립통제와 비교하고, TB의 기초+차변−대변=기말과 GL/TB 변동을 대사한다. 계정 집합과 매핑·독립통제·추출범위가 맞는지도 본다. 승인 상태이며 차대가 맞는 감사조정만 조정후 리드에 반영하고 초안은 별도 표시한다.

**예외 결과**  
전표 전체가 빠져도 독립 행수·차대 총액과 다르면 누락을 탐지할 수 있다. TB/매핑/통제의 계정 누락, 잘못된 계정 변동, 중복 조정, 조정 상태·차대 불일치가 결과에 남는다. 주말 전기·적요 공란은 검토후보이며 부정 확정이 아니다.

**조서·원장 연결**  
계정별·리드별 기초, 변동, 조정전·승인조정·조정후 금액을 출력한다. 모듈연결에 선언한 계정·비교기준·부호로 계정별 계산의 기대금액을 만든다. 원장 관련 C04·C05·P07 및 예외 조서에서 수행·판단을 기록한다.

**한계**  
제출된 독립 통제값의 진짜 독립성은 프로그램이 증명하지 않는다. 원장과 같은 입력을 다시 합산한 값을 외부 증거처럼 사용하면 안 된다. 승인조정 상태는 입력값이며 외부 승인권한을 인증하지 않는다. 리드의 조정후 금액과 재무제표 모듈의 조정전 비교 범위도 구분한다.

## 04. 금융상품 — 명세·원장·회신과 단순이자 기간

**목적**  
동일 계약의 금융상품 명세·원장·회신 금액과 지원 단순이자를 비교하고, 이자 계산기간의 누락·중복을 확인한다.

**필요 로우데이터**  
설정, 명세, 조건, 원장, 회신, 이자기준, 이자구간이 필요하다. 기관코드+계약 ID, 기준일, 원금·이자, 고정금리, 계약기간, ACT/365F 또는 ACT/360, 시작·끝 포함 규칙, 직전 정산서/계약의 이자기산일과 근거문서를 넣는다.

**실제 검사·계산**  
명세·원장·회신·조건의 계약키와 원금/이자를 비교한다. 원금×연이율×실제 일수÷365 또는 360으로 단순이자를 재계산한다. 독립 이자기준부터 기준일까지의 기대기간과 조건의 계산기간, 구간별 날짜가 빠짐없이 이어지는지 확인한다. 구간 겹침·공백·기준일 초과가 있으면 이자 재계산의 일치 판단을 차단한다.

**예외 결과**  
계약 누락·중복, 필수값 오류, 기간 역전·빠진 날·중복된 날, 미지원 복리·변동금리·원금변동 등이 남는다. 원금 허용오차는 0원, 이자는 0원 또는 1원만 허용하며 0원이 아닌 허용범위 차이도 반올림차이로 보존한다.

**조서·원장 연결**  
명세의 원금·미수이자 합계를 TB 연결 계정과 비교한다. 관련 조서 A02에는 계산 실행·입력자료·정책·원장 대사 상세가 연결된다. 검토요청 시 해당 계산 입력과 현재 원장 입력의 두 증거를 함께 요구한다. 이 연결 보완의 최종 소스·EXE 검증 상태는 배포 기록을 따른다.

**한계**  
단순 정기예금·고정금리 대여·차입의 제한된 모형이다. 유효이자율·할인할증·수수료·복잡한 평가·인식 판단을 자동 수행하지 않는다. 이 기존 입력은 회사코드가 없는 부분이 있어 현재 업무에 귀속시키는 판단이 필요하다. 회신 파일을 넣었다는 사실이 조회 발송·회수통제를 수행했다는 뜻은 아니다.

## 05. 매출 — 주문·납품·청구와 매출원장 양방향 대사

**목적**  
주문에서 납품·검수·청구·매출전기까지의 수치 연결과 매출원장 모집단을 확인한다.

**필요 로우데이터**  
orders, deliveries, invoices, ledger, control의 5개 시트가 필요하다. 주문/행·납품/행·송장/행 ID, 품목·거래처, 수량·단위·단가·세율·공급가액·세액·총액, 매출계정·전표/행·전기일을 사용한다. 통제에는 회사·시작/종료일·대상계정·원장 기대 행수·차대 총액·추출근거를 넣는다.

**실제 검사·계산**  
명시된 주문·행·품목 등의 키로 납품·검수·청구를 연결하고 수량·단가·공급가액·세액·총액 및 날짜·단위·통화를 비교한다. 송장 공급가액과 매출원장 대변−차변을 부가세 제외 기준으로 양방향 대사한다. 원장 행수·차변합계·대변합계를 독립 통제와 정확 비교해 상계되는 누락을 숨기지 않는다. 통합 앱은 금액·수량·단가 허용오차를 0으로 실행한다.

**예외 결과**  
누락된 주문·납품·송장, 중복 식별자, 수량·가격·세액 차이, 송장만 있는 거래·원장만 있는 거래, 다른 회사·계정·기간, 모집단 통제 실패를 표시한다. 독립 원장 모집단이 확인되지 않으면 겉보기 수치 일치를 정상 일치로 확정하지 않는다.

**조서·원장 연결**  
순매출 합계를 TB의 매출 연결 계정과 비교하고 원장양방향대사·원장통제·원본행을 제공한다. A04에 계산 실행·입력자료·정책·TB 대사 상세를 연결하며, 검토요청 시 계산 입력과 현재 원장 입력의 두 증거를 요구한다. 최종 소스·EXE 검증 상태는 배포 기록을 따른다.

**한계**  
청구·검수 날짜만으로 IFRS 15 통제 이전이나 수행의무 충족을 결론내리지 않는다. 반품·리베이트·변동대가·복합계약·수익인식 시점은 계약과 실질을 추가 검토해야 한다. 명시한 키를 사용하며 이름·금액이 비슷하다는 이유로 임의 연결하지 않는다.

## 06. 감가상각 — 자산대장·원장·월별 재계산

**목적**  
유형자산과 유한내용연수 무형자산의 지원 원가모형 상각을 재계산하고 자산대장·원장과 비교한다.

**필요 로우데이터**  
설정, 자산, 변경, 생산량, 원장, 통제의 6개 시트가 필요하다. 회사+자산 ID, 취득일·사용가능일, 원가·잔존가치·내용월수·상각방법·상각률, 처분일, 전기말 원가/누계·당기상각·기말 원가/누계를 넣는다. 변경근거와 생산량비례법의 월별 생산량도 필요하다.

**실제 검사·계산**  
정액법·정률법·이중체감법·연수합계법·생산량비례법의 지원 정책으로 월별 계산한다. 개시월 당월/익월, 처분월 포함/제외, 잔여내용연수·잔존가치·추가원가 등의 명시 변경을 적용한다. 대장−원장과 재계산−대장의 각 지표를 비교하고 독립 통제 행수·각 총액을 확인한다. 원가에는 0원, 지원 상각/누계 지표에는 설정한 0원 또는 1원 허용오차를 적용하되 차이는 보존한다.

**예외 결과**  
자산대장/원장 키 누락·중복, 회사·기간·통제 차이, 월별 생산량 누락, 미지원 변경·자산모형, 금액 차이가 남는다. 완전상각 후 보유나 잔존가치가 원가 이상인 자산도 추정 검토후보로 표시한다.

**조서·원장 연결**  
기말원가·기말누계·당기상각을 TB 연결 계정과 비교하고 월별 계산행·원본 위치를 남긴다. A12에 계산 실행·입력자료·정책·TB 대사 상세를 연결하며, 검토요청 시 계산 입력과 현재 원장 입력의 두 증거를 요구한다. 최종 소스·EXE 검증 상태는 배포 기록을 따른다.

**한계**  
토지·비한정 무형자산·재평가·손상·매각예정은 이 상각 모형 범위 밖이다. 사용가능 상태·내용연수·잔존가치·생산량 추정이 합리적인지는 사람이 검토한다. 처분일을 상각기간에 반영하는 기능과 처분 회계처리 전반을 검증하는 기능은 구분한다.

## 07. 확장검사 — 은행·채권·매입·실사 수치

**목적**  
은행거래 대사, 채권 연령/후속회수, 매입 3자대사, 기준일 재고실사의 제한된 수치 검사를 한 입력 묶음에서 제공한다.

**필요 로우데이터**  
설정, 은행장부·은행거래, 채권·후속회수, 발주·입고·매입송장, 장부재고·실사, 독립통제가 필요하다. 거래/발주/채권 ID, 계좌·참조·날짜·금액, 품목·수량·단가·창고·단위·실사일을 넣는다.

**실제 검사·계산**  
은행은 계좌+일자+참조+부호 금액의 정확한 1:1만 대사한다. 채권은 기준일−만기일로 연령구간을 만들고 채권 ID로 후속회수를 합산한다. 매입은 발주수량=입고수량=송장수량과 단가×송장수량=송장금액을 확인한다. 실사는 같은 창고·품목·단위의 장부수량과 기준일 당일 실사수량을 비교한다. 자료별 행수·부호합계·절대합계를 독립 통제와 비교한다.

**예외 결과**  
중복·모호한 은행 매칭, 연결 채권 없는 회수·초과회수, 발주/입고/송장 누락·차이, 다른 실사일·단위·수량 차이가 남는다. 임의 첫 행을 골라 맞추거나 중복 키를 자동 합산해 숨기지 않는다.

**조서·원장 연결**  
A01·A06·A08·A10 등의 수동 조서에서 원문·범위·결과를 기록한다. 확장검사는 이 네 절차의 개별 결과를 제공하며, 각 결과 전체가 별도의 계산 지표로 TB에 자동 연결되는 구조는 아니다. 원천증빙의 명시 배부 연결과 함께 확인한다.

**한계**  
은행의 분할·합산 매칭, 실제 조회 회수통제, ECL 평가, 실사 입회 결론, 실사일과 결산일 사이 이동은 이 기능만으로 끝나지 않는다. 재고실사 수량 검사와 별도 재고평가 모듈의 NRV 평가도 구분한다.

## 08. 리스 — 고정 월납 부채·사용권자산

**목적**  
지원하는 임차인 고정 월납 계약의 리스부채·이자·사용권자산·상각을 월별 재계산한다.

**필요 로우데이터**  
설정, 리스계약, 리스원장, 독립통제가 필요하다. 리스 ID·월초 개시일·개월수·월지급액·월말후급/월초선급·연/월 유효할인율, 선급금·직접원가·복구원가·인센티브·내용월수와 계약/할인율 근거를 넣는다.

**실제 검사·계산**  
연 유효이율은 월 유효이율로 변환한다. 미지급 월납금의 현재가치를 최초 리스부채로 계산하고 사용권자산에 지원 조정항목을 반영한다. 매월 기초부채+이자−지급=기말부채와 기초사용권+신규−상각=기말사용권을 확인한다. 다음 12개월의 부채 감소분으로 유동/비유동을 구분하고 계약별 원장과 비교한다.

**예외 결과**  
계약·원장 ID 불일치, 통제 실패, 개시·결산월 조건 위반, 원장 유동+비유동 합계 오류, 계산금액 차이가 남는다. 변경·옵션·손상 등 지원하지 않는 조건은 계산이 되는 척하지 않고 차단한다.

**조서·원장 연결**  
A15에 계산 실행·입력·원장 증거를 연결한다. 기말리스부채·기말사용권자산·당기리스이자·당기사용권상각의 4개 합계를 TB와 비교하고 월별리스·리스원장대사 표로 내려간다.

**한계**  
고정 동일 월납, 월초 개시·월말 결산의 원가모형이다. 계약변경·연장/해지 옵션·변동리스료·외화·손상 등은 별도다. 0~1,000원 설정 허용오차 안의 계약별 차이가 표에서 일치로 표시될 수 있어 실제 차이 열도 읽어야 한다. TB 연결의 0원 정확 비교와는 다르다.

## 09. 대손충당금 — 매출채권 전체기간 ECL

**목적**  
유의적 금융요소가 없는 매출채권의 명시 충당률표와 시나리오로 전체기간 기대신용손실을 재계산한다.

**필요 로우데이터**  
설정, 채권, 시나리오, 충당률표, 충당금원장, 충당금변동, 독립통제가 필요하다. 채권 ID·분류군·발생/만기일·잔액·집합/개별구분, 시나리오 확률·전망근거, 연체구간·과거손실률·전망배수·가산조정과 근거를 넣는다.

**실제 검사·계산**  
연체일수를 구한 뒤 분류군·시나리오별 충당률을 단일 매칭한다. 조정후 손실률=과거손실률×전망배수+가산조정이며, 시나리오 확률로 가중한다. 채권잔액×가중손실률을 채권별 원 단위로 반올림한다. 개별평가 채권은 명시 개별손실률을 사용해 집합평가와 중복하지 않는다. 기말 필요충당금−기초충당금−비용외증감으로 당기비용을 산출한다.

**예외 결과**  
확률 합계가 정확히 1이 아님, 연체구간 공백·중복·마지막 상한 누락, 손실률 0~1 초과, 분류군 누락, 제각 부호·변동 명세·원장 롤포워드 차이를 표시한다. 범위를 벗어난 손실률을 자동으로 0 또는 1에 맞추지 않는다.

**조서·원장 연결**  
A07에 채권별ECL·적용충당률표·원장대사와 근거를 연결한다. 기말채권잔액·기말대손충당금·당기대손상각비 3개 지표를 TB와 비교한다.

**한계**  
과거손실률·전망·개별평가근거의 적정성은 사용자가 판단한다. 할인은 손실률에 포함하거나 할인효과 비유의라는 명시 정책만 지원한다. 금융기관 3단계 모형·일반 대여금·담보 현금흐름 모형 전반은 구현하지 않았다. 설정 허용오차와 실제 차이를 함께 확인한다.

## 10. 재고평가 — 품목/로트 원가와 NRV

**목적**  
판매목적 상품·제품의 평가 ID별 원가와 순실현가능가치(NRV)를 비교하고 평가충당금·손실/환입을 재계산한다. 급여와는 별도 모듈이다.

**필요 로우데이터**  
설정, 재고명세, NRV근거, 재고원장, 평가변동, 독립통제가 필요하다. 평가 ID·창고·품목·단위·기말수량·확정 원가단가, 예상판매단가·완성필요단가·판매필요단가·근거일·판단·가격근거, 기초충당금과 손익외 변동을 넣는다.

**실제 검사·계산**  
원가=기말수량×확정 원가단가, 단위NRV=예상판매단가−완성필요단가−판매필요단가로 계산한다. 총 NRV는 0 미만이면 재고 장부금액에 대해 0으로 제한하고 별도 의무 검토후보를 남긴다. 평가충당금=max(0, 원가−NRV), 당기평가손실=필요 기말충당금−기초충당금−손익외증감이다. 단위별 수량 통제를 나눠 KG와 EA를 더하지 않는다.

**예외 결과**  
명세/NRV/원장 평가 ID 누락·중복, 수량·단위 차이, 평가변동 부호·롤포워드 오류, 오래된 가격근거, 음수 NRV, 계산/원장 차이를 확인한다.

**조서·원장 연결**  
재고는 **A11**에 작성한다. 기말재고원가·기말재고평가충당금·기말재고순액·당기재고평가손실 4개 지표를 TB와 비교하고 재고평가요약·재고원장대사 표를 연결한다.

**한계**  
확정된 원가단가를 재계산하는 기능이며 원가배부·제조원가 산출·공정 수율·원재료/재공품 평가 모형은 구현하지 않았다. 판매가능성·진부화·후속판매 가격의 합리성은 별도 판단이다. EA↔KG 자동환산이나 실제 실사를 완료한 것으로 표시하지 않는다. 설정 허용오차와 실제 차이를 함께 읽는다.

## 11. 종업원급여 — 월급·지급·DC·연차부채

**목적**  
명시된 인사·급여 정책으로 단기급여, 약정 확정기여(DC), 단기 누적연차와 지급/미지급을 재계산한다. 재고와 별도 계산·입력·조서로 관리한다.

**필요 로우데이터**  
설정, 인사명부, 급여명세, 급여원장, 급여지급, 연차명세, 급여잔액, 독립통제가 필요하다. 사번·입퇴사일·급여/DC 계좌·퇴직제도, 귀속월·월기준급여·무급일수·시간외시간·단가·배수·상여·수당·공제·DC율·자산배부율, 이체 참조, 연차 일수·정산비율·일단가·기초부채를 사용한다.

**실제 검사·계산**  
재직 사번별 필요한 월을 만들고 급여 누락·중복을 검사한다. 기본급은 달력일 재직일수에서 무급일수를 뺀 비율로 일할하고, 시간외·상여·수당을 더해 총급여, 공제 후 실지급대상, 총급여×약정 DC율을 계산한다. 급여/DC의 비용과 자산배부를 분리한다. 지급의 사번·급여 ID·수취계좌·기초참조·초과지급을 확인한다. 미지급은 기초+발생−당기지급, 연차는 잔여일수×일단가×예상정산비율과 부채 순증감으로 계산한다.

**예외 결과**  
재직 월 급여 누락, 인사·연차·잔액 모집단 불일치, 다른 사번 지급 참조, 수취계좌 차이, 초과지급·음수 미지급, 원장 배부/롤포워드 오류가 남는다. 여러 사번의 동일 급여계좌는 실제 명의·권한을 추가 확인할 후보로 표시한다.

**조서·원장 연결**  
급여는 **A16**이다. 급여·DC·연차 각각의 비용, 자산배부원가, 기말미지급/부채 등 9개 지표를 TB와 비교한다. 월별급여계산·급여지급대사·연차계산·급여원장대사를 조서 근거로 사용한다.

**한계**  
세액·법정 최저요율·노동법 적정성·DB 계리·퇴직정산·복잡한 선급급여는 구현하지 않았다. 제출한 계좌가 실제 직원 계좌인지 인증하지 않는다. 후속지급을 조회하는 기능과 실제 은행 이체 원문과의 독립 대사는 구분한다. 설정 허용오차와 차이 열을 함께 본다.

## 12. 미기록부채·비용이연 — 후속자료 검색과 미지급/선급 귀속

**목적**  
기준일 이후 송장·지급에서 기말 귀속 가능성을 찾고, 지원 확정 용역의 미지급비용과 선급비용 배분을 재계산한다.

**필요 로우데이터**  
설정, 용역계약, 비용원장, 후속송장, 대금지급, 독립통제가 필요하다. 비용 ID·거래처·용역 시작/종료·총공급가액·일할/월할·비용/잔액 계정, 기초/발생/결제/기말, 송장일·귀속기간·지급일·은행참조, 후속검색종료일·비교계정 범위를 넣는다.

**실제 검사·계산**  
시작/종료일 포함 일할 또는 완전한 달 월할로 누적 귀속액을 원 단위 반올림하고 전기 누적액을 빼 당기비용을 구한다. 미지급은 누적 귀속−누적 결제, 선급은 지원하는 총액 1회 지급에서 미귀속분으로 계산한다. 후속 송장·지급의 귀속·거래처·계약 연결을 확인하고 연결되지 않은 후속자료를 별도 검색결과로 남긴다. 기초+발생/지급−결제/상각=기말을 검사한다.

**예외 결과**  
미분류 후속 송장·지급, 계약 범위 밖 귀속, 중복 송장/은행참조, 계약초과 청구·지급, 기초/당기/기말 차이, 선언한 계정범위 불일치를 확인한다. 미분류 항목은 부채 누락 확정이 아니라 조사 대상이다. 허용오차 안의 비영 차이도 검토사항으로 남긴다.

**조서·원장 연결**  
A08·A09에 미기록부채·비용귀속/선급 관련 수행을 기록한다. 기말미지급비용·당기발생비용·기말선급비용·당기선급상각 4개 지표를 선언 계정·비교기준·부호까지 확인해 TB와 비교한다. 수정분개검토 표는 기초·지급 등 조건이 맞을 때만 검토 초안을 제시한다.

**한계**  
확정 KRW 용역 공급가액, 단순 일할/월할과 총액 1회 지급 선급의 제한된 범위다. 부가세·외화·재고/자산취득·변경/환불·추정충당부채는 별도다. 수정분개 초안은 자동 전기·회계처리 승인 기능이 아니다. 후속검색 원천 자체가 충분히 추출됐는지도 사람이 확인해야 한다.

## 13. 원천증빙 — 원문 보존·선택 거래 배부·현재 원장 연결

**목적**  
원천 파일·표·행과 선택된 거래배부를 추적하고, 원천팩의 GL/TB가 현재 업무 원장과 같은지 확인한다.

**필요 로우데이터**  
.auditpack 안의 파일 명세, 카탈로그, 선택 모집단·배부표, 원본 명세와 XLSX를 사용한다. 자회사 정상팩은 원문 16권·114표를 보존하고 선택 원천 32행·대상 32행·명시 배부 32건을 포함한다. 회사·기간·통화·별도/연결 문맥, 원문 파일·시트·행·금액 열과 부호 산식이 필요하다.

**실제 검사·계산**  
파일 크기·해시·경로와 ZIP 구조를 확인하고 원본 Excel에서 카탈로그를 다시 산출한다. 선택한 원천/대상 행의 금액 열을 +1/−1 산식으로 읽어 명시 배부합계와 비교한다. 다대다·부분배부를 허용하되 중복·고아 참조·반대 부호·과배부·미배부를 구분한다. 원천팩의 GL 복합키/값과 TB 계정/값을 현재 원장 입력과 비교하고 사용한 원장 실행 ID·결과 해시를 고정한다.

**예외 결과**  
파일/카탈로그 변조, 경로 이탈·중복 파일·비정상 ZIP, 회사·기간·통화 오류, 배부 중복·과배부·미배부, 현재 원장과 다른 GL/TB를 표시한다. 정상팩에도 미확인 범위 8개가 별도 연결범위 표에 남는다. 일반 예외 건수가 0이어도 이 8개가 자동 해소되지 않는다.

**조서·원장 연결**  
R01에 원본 사본·선택범위·배부·개별 대사표를 연결한다. 현재 원장을 다시 실행하면 이전 R01 분석의 연결은 재확인이 필요하다. 선택 거래의 차이는 반복 단계가 있을 수 있어 왜곡표시 총액으로 단순 합산하지 않는다.

**한계**  
114표 보존은 모든 거래 전수 대사를 뜻하지 않는다. 미확인 범위는 회사/기간 열이 없는 은행·송장 관련 5개 연결, 수량·취득원가·단위환산, 후속회수/급여/리스월납과 개별 은행거래, 토지권리/취득증빙 및 나머지 계정군이다. 실제 문서 진위·권리·모집단 완전성·조회통제는 검증하지 않는다.

## 14. 재무제표·주석 — 합계·소계·TB·본문·선택 주석

**목적**  
재무제표 내부 합계가 맞는지와 별개로 현재 원장의 조정전 TB가 본문·선택 주석에 일관되게 반영됐는지 확인한다.

**필요 로우데이터**  
정상 실행된 현재 원장 7시트와 구조화 financial.json이 필요하다. JSON에는 설정·TB 문맥·문서·금액 항목·합계관계·계정매핑·주석연결이 있어야 한다. 각 금액의 원/천원/백만원 단위, 문서 ID·페이지·위치, BS/PL 구분과 표시부호를 명시한다.

**실제 검사·계산**  
보관된 리드를 그대로 믿지 않고 실제 원장 입력으로 통제·리드를 다시 계산해 비교한다. 합계관계를 그래프로 검사해 구성항목 합계와 보고금액, 자산=부채+자본 등을 비교한다. TB 계정의 누락·중복 매핑과 BS/PL/표시부호를 검사하고 본문 반영금액을 구한다. 선언한 필수 본문항목과 주석 연결도 대사한다. 단위는 원 단위로 환산하되 abs로 부호를 맞추지 않는다.

**예외 결과**  
순환 합계·누락된 항목/관계·중복 계정매핑·주석연결 누락·잘못된 단위·회사/기간/버전 불일치·본문/TB 차이를 표시한다. 합계가 맞아도 TB와 다르면 차이를 남긴다. 원장 통제 차단·실제 입력 누락·오래된 리드면 재무제표 비교 자체를 차단한다. 허용오차 안의 비영 차이도 미해결 검토사항이다.

**조서·원장 연결**  
F01에 재무제표대사·TB본문매핑·원장리드연결·JSON 원천위치를 연결한다. 현재 원장 실행 ID·해시가 바뀌면 다시 실행한다. 승인조정이 있어도 이 비교는 조정전이며 그 한계를 검토사항으로 남긴다.

**한계**  
KRW 별도 업무·미마감 PL·조정전 TB·BS/PL과 선택 주석만 지원한다. 조정후 마감본, PDF/OCR/XBRL 추출, 현금흐름표·자본변동표 본문, 모든 공시 완전성·적정성 판단은 포함하지 않는다. 표시금액을 입력한 사실이 실제 공시 원문을 자동 추출·확인했다는 뜻은 아니다.

## 15. GLA — 총계정원장 집계와 설명 가능한 전표 후보

**목적**  
검증한 현재 원장의 전체 입력행을 월·계정·작성자·전표 구성으로 살펴보고 조사할 후보를 찾는다.

**필요 로우데이터**  
공통 원장 7시트와 GLA설정이 필요하다. 주말/월말/고액/반복 규칙의 사용 여부, 월말 범위일, 고액기준원, 반복 최소횟수를 명시한다. 원장의 전기일·작성자·계정·차대 금액을 사용한다.

**실제 검사·계산**  
입력 원장을 재검사하고 현재 업무 원장 7시트·리드와 비교한 뒤 월별·계정별·작성자별 차대량과 전표 수를 집계한다. 주말, 설정 월말 범위, 전표 차변합계 이상 고액, 같은 회사의 계정·차대 금액 구성이 반복되는 전표를 찾는다. 차대 금액을 더해 두 배로 만들지 않는다. 계정집합 1:1과 실제 개별 행 1:1을 구분하고 복합분개는 임의 대응을 만들지 않는다.

**예외 결과**  
현재 원장 불일치면 후보 산출을 정상 완료하지 않는다. 후보에는 규칙 ID·조건·사유·원본행·우선순위·후속절차가 있다. 반복 전표의 전체 구성은 반복그룹색인으로 추적한다. 없는 입력시각·수동/자동·승인 메타의 규칙은 미확인으로 표시한다.

**조서·원장 연결**  
G01과 검토후보 화면을 연결한다. 후보 선택 후 관련 조서·자료요청 초안으로 이동할 수 있다. 현재 원장 실행 ID·해시를 고정하므로 원장 변경 후 예전 후보를 최신 결과로 사용하지 않는다.

**한계**  
주말·월말·고액·반복은 정상 결산·정기거래에서도 발생한다. 작성자 문자열은 인증된 사용자 식별이 아니며 전기일로 심야입력이나 수동 여부를 추정하지 않는다. 우선순위는 부정확률이 아니다. 월별 차대량이나 복합 계정조합을 현금흐름으로 바꾸지 않는다.

## 16. FIA — 입력·승인 메타와 마감·업무시간 정책

**목적**  
실제 제출한 전표 메타를 활용해 원장 전기일만으로 확인할 수 없는 입력·승인·정책 조건을 분석한다.

**필요 로우데이터**  
공통 원장 7시트, FIA설정, 전표메타가 필요하다. 원장 복합키별 시간대 포함 입력시각·입력자·수동/자동/미확인·승인상태·승인자/시각·부서·시스템·명시 재분류그룹을 넣는다. 마감시각·로그 추출시각·고정 시간대·업무 시작/종료·선승인 정책과 집중/반복 기준도 필요하다.

**실제 검사·계산**  
모든 원장행과 메타를 정확히 1:1 연결하고 같은 전표 내 메타 충돌을 차단한다. 명시한 마감 이후 과거기간 전기, 입력자별 수동 전표 수·차변합계·비율 집중, 입력자=승인자, 추출/입력/승인 시각 모순, 업무시간 밖 입력, 명시 그룹의 반복 재분류, 수동전표 승인대기/반려를 검사한다. 시간대가 다른 동등 시각은 절대시각으로 비교한다.

**예외 결과**  
키 누락·중복·타회사·메타 필수값/시각 오류·현재 원장 불일치는 차단이다. 메타가 명시적으로 미확인이면 관련 규칙을 미확인으로 남긴다. 규칙별 대상·후보·미확인 수와 원장/메타 원본행을 제공한다. 익년 입력이라는 이유만으로 명시 마감 이전의 정상 결산분개를 마감후 입력으로 분류하지 않는다.

**조서·원장 연결**  
I01에 현재 원장 연결, 전표메타대사, 규칙적용·검토후보를 연결한다. 후보에서 조서·자료요청 초안·로컬 검토맥락 JSON으로 이동한다.

**한계**  
제출 메타의 사실성·로그 추출 완전성·실제 권한분리를 인증하지 않는다. 휴가·공휴일·의도·개인 행동을 추정하지 않으며 자정을 넘는 근무시간·일광절약시간 자동정책은 지원하지 않는다. 동일 입력/승인자나 업무시간 밖 입력도 실제 정상 사유를 확인해야 한다.

## 17. 현금분석 — 은행·GL 배부와 지급 검토후보

**목적**  
명시한 계좌의 은행·현금원장 연결과 미대사를 확인하고 반복지급·상대계좌 집중·계좌변경 직후 지급을 조사 대상으로 제시한다.

**필요 로우데이터**  
공통 원장 7시트, 분석설정, 현금계좌, 은행거래, 은행독립통제, 현금원장선택, 현금배부, 거래처계좌, 지급근거, 계좌변경이 필요하다. 계좌별 기초/기말·입출금·행수·추출근거, 거래처/상대계좌·소유구분·근거 ID·승인총액·일회/분할/정기/자금이체 구분을 사용한다.

**실제 검사·계산**  
현재 원장 연결 후 선언 현금계정의 GL행을 빠짐없이 한 번씩 선택했는지 확인한다. 은행 기초+입금−출금=기말과 독립 행수·총입출금을 대사하고 TB 기초/기말과도 비교한다. 은행행과 GL행 사이 명시 배부의 부호·계좌·거래처·상대계좌·근거·거래구분을 확인한다. 은행·장부 양쪽 잔여를 남기고, 명시 일회 반복지급·승인총액 초과·외부 상대계좌 집중·변경 직후 지급을 분석한다.

**예외 결과**  
중복·고아·다른 계좌·반대 부호·과배부·양쪽 명시 메타 모순은 차단한다. 미배부·부분배부·은행/TB 차이는 조사 항목이다. 변경 이력 미제출·소유 미확인은 변경 없음이나 외부거래로 임의 분류하지 않는다. 합법 정기·분할지급·자금이체는 필요한 양쪽 근거를 확인하는 대조군으로 구분한다.

**조서·원장 연결**  
H01에 현금검사통제·계좌잔액대사·현금배부표·은행장부잔여·규칙미확인·검토후보를 연결한다. 후보는 원문 행과 후속 확인을 포함하고 현재 원장 실행에 고정된다.

**한계**  
제출한 선택 계좌 범위다. 완전히 미제출된 계좌는 이 입력만으로 찾을 수 없으므로 독립 계좌목록·조회·ERP 추출범위가 필요하다. 실제 수취인·거래 실질·은행원문 진위는 검증하지 않는다. 금액이 같다는 이유로 자동 매칭하지 않으며 외화·은행수수료 자동분개·차기 미결제 변환을 지원하지 않는다.

## 18. 계정별 증빙연습 — 9개 계정군의 독립 사례

**목적**  
통합 TB와 별개로 특정 원천문서와 계산을 작은 합성 거래 사례에서 연습한다.

**필요 로우데이터**  
합성·독립연습 표시가 있는 전용 JSON, 회사·기간·KRW 별도 문맥, 사례 ID와 문서 ID·문서유형·거래 ID·원문 필드가 필요하다. 현금/금융, 매출/채권, 재고/매입, 고정자산, 리스, 급여, 차입/세무, 자본/공시, 재무보고의 9개 계정군·33개 사례를 제공한다.

**실제 검사·계산**  
선택 계정군의 고정 계산기를 실행해 원문 필드의 계산·관계를 비교한다. 기대 결과는 검사기에 주입하지 않고 사례의 문서 필드로 다시 계산한다. 계정별검사·원천증빙원문과 원본 JSON 위치를 제공한다.

**예외 결과**  
입력형식·회사/기간·문서 ID 오류는 차단한다. 계산별 PASS·EXCEPTION·INPUT_BLOCKED를 구분하고 사유·차이·후속절차를 남긴다.

**조서·원장 연결**  
W01에 연결하지만 현재원장연결은 false다. 통합 TB에 합산하거나 대사하지 않으며 검토중 출력 범위로 다룬다.

**한계**  
일반 사용자의 임의 모든 자료를 처리하는 범용 계산기가 아니다. 독립 사례를 통합 그룹·연결감사·계정 전체 감사 완료로 표현하지 않는다. 여러 계정군을 한 사례 라이브러리에 담아도 재고와 급여 절차가 합쳐지는 것은 아니다.

## 19. 검토후보에서 조서·자료요청으로 이동

**목적**  
GLA·FIA·현금에서 발견한 규칙 후보를 원문·후속절차·사람의 판단으로 이어준다.

**필요 로우데이터**  
현재 원장에 연결된 최신 분석 실행과 후보의 규칙 ID·원본행·자료 ID·원문 SHA256을 사용한다.

**실제 검사·계산**  
후보를 공통 목록으로 모아 모듈·우선순위·사유·연결상태·조서 ID를 보여준다. **관련 조서 열기**는 G01/I01/H01로 이동한다. **자료요청 초안**은 후보 사유·원문·후속확인·자료 ID를 요청 입력폼에 채운다. **검토맥락 저장**은 업무·현재 자료 버전·필요자료·후보를 JSON으로 저장한다.

**예외 결과**  
옛 실행의 후보, 변경된 원장, 차단·재실행 필요 상태에서는 정상 요청 초안으로 쓰지 않는다. 원본 사본 변경·누락도 확인한다.

**조서·원장 연결**  
후보 키는 해당 실행에 연결된다. 원장·분석을 다시 실행한 뒤 최신 후보로 수행·판단을 업데이트한다. 후보를 눌렀다는 사실이 조서를 수행 완료로 바꾸지는 않는다.

**한계**  
이 기능의 검토맥락 JSON은 로컬 규칙 결과이며 uses_ai_inference는 false다. 파일 저장만으로 AI를 실행하거나 외부 서비스에 자료를 전송하지 않는다. v1.8의 명시적인 AI 조서 생성은 별도 기능이다. 후보가 여러 규칙에 반복되므로 금액을 왜곡표시 합계로 합산하지 않는다.

## 20. 자료요청·수령 상태 관리

**목적**  
어떤 자료를 누구에게 요청했고 무엇을 받았는지, 무엇이 남았는지 기록한다.

**필요 로우데이터**  
요청자료명·요청처·기한·요청범위/처리내용, 요청 상태, 받은 자료의 등록 증거 ID가 필요하다.

**실제 검사·계산**  
**요청·수령 기록 저장** 시 요청 ID를 만들거나 같은 요청의 새 개정을 저장한다. 요청·부분수령·수령·검토완료·취소 상태를 관리한다. 수령 관련 상태에는 등록 원본 사본을 연결하고 무결성을 확인한다. 요청처·기한·내용은 필수다.

**예외 결과**  
필수값 누락·잘못된 기한·알 수 없는 상태·미등록/중복 증거 ID·증거 없는 수령처리는 저장하지 않는다. 미완료 요청이 남으면 검토완료본 출력이 차단된다.

**조서·원장 연결**  
요청에 연결한 증거를 조서 근거로 선택하고 실제 검토내용을 기록한다. 요청을 수정·저장한 이전 상태도 업무 이력에 남는다. 실제 수령 자료를 등록하면 자료 버전이 바뀌므로 기존 조서의 재검토 필요 상태를 확인한다.

**한계**  
저장 전 타이핑·초안 생성은 이력이 아니다. 저장은 실제 이메일 발송이나 상대방 수신확인이 아니다. 인증된 요청자 계정은 없으며 요청처는 입력값이다. 업종별 요청문서 60개 템플릿을 실제 요청·수령으로 자동 처리하지 않는다.

## 21. 증거 등록·독립 ID 통제·검토의견

**목적**  
검사와 수동 판단에 사용한 원문 사본을 보존하고 추가 요청·보완 의견을 추적한다.

**필요 로우데이터**  
받은 증거 파일과 자료명, 독립 추출 전체 ID CSV와 식별자 열, 검토의견의 제목·내용·입력한 작성자·후속조치가 필요하다.

**실제 검사·계산**  
증거 파일은 업무 폴더에 사본으로 저장하고 원래 경로·자료 ID·해시·크기·등록시각을 남긴다. **독립 ID 통제값**은 CSV의 식별자 개수·중복 여부와 정렬한 ID 집합의 SHA256을 구해 독립통제 입력에 쓸 수 있게 한다. 검토의견은 신규 등록과 해결 상태 개정을 기록한다.

**예외 결과**  
증거 파일 크기 한도, 등록 중 원본 변경, ID 열 누락·중복·CSV 오류를 차단한다. 미해결 검토의견이 있으면 검토완료본 출력이 차단된다.

**조서·원장 연결**  
조서마다 하나 이상의 실제 근거 사본을 선택하고 수행내용에 범위를 설명한다. 계산 조서는 연결한 계산 입력과 원장 입력 증거를 요구한다. 원본 추가·분석 변경 후에는 자료 버전과 조서 재검토 상태를 확인한다.

**한계**  
파일을 등록했다는 사실은 그 내용이 맞다는 뜻이 아니다. ID 통제값은 별도 ERP 추출 범위를 신뢰할 수 있을 때 의미가 있으며 같은 계산 입력을 다시 세어 만든 값은 독립 증거가 아니다. 클립보드로 계산한 ID 통제값 자체는 증거 자동 등록이 아니므로 CSV·추출근거를 별도로 등록한다.

## 22. 조서 작성·개정·검토

**목적**  
자동 결과와 실제 감사인의 수행·판단을 구분하고, 자료 버전에 맞는 작성·검토 기록을 남긴다.

**필요 로우데이터**  
절차 ID·제목·목적/주장·위험/기준·모집단/선정범위·실제 수행내용·판단/결론·작성자·실제 수행일·근거 ID, 검토자·검토내용이 필요하다. 범위 제외를 기록할 때는 사유가 필요하다.

**실제 검사·계산**  
상단 **조서초안 작성** 또는 **조서초안·작성** 탭에서 계정/절차를 선택한다. 오른쪽 스크롤 입력영역을 확인하고 하단 **조서 저장·개정**으로 현재 자료·분석 전체의 버전 해시와 내용을 저장하면 작성중이 된다. **검토 요청**은 필수 수행·판단·날짜·증거와 자료 버전을 확인한다. 자동 연결된 계산 조서는 계산 입력과 원장 입력을 함께 요구하고, 원천/재무제표/GLA/FIA/현금은 현재 원장 실행에 연결됐는지도 확인한다. 검토자는 보완 의견 또는 검토기록 완료를 남긴다.

v1.8에서 AI를 선택하면 현재 근거로 실제 초안을 생성하고 인용을 확인한 뒤 적용한다. 적용은 목적·위험·범위·수행·결론을 조서에 저장하지만 실제 수행일·내용 승인·별도 검토완료를 자동 설정하지 않는다. 사람은 내용을 확인·수정·저장한 뒤 승인자와 판단 기록으로 최종내용 승인을 남긴다. 이후 작성자와 다른 검토자의 조서 검토를 수행한다.

**예외 결과**  
공란 필수값·증거 없음·옛 자료 버전·변경된 사본·계산/원장 근거 누락은 검토요청을 막는다. 작성자와 같은 이름의 검토자는 허용하지 않는다. 수정 후에는 이전 검토를 유지하지 않고 다시 저장·검토요청한다. 실행 예외와 TB 연결차이에 대한 별도 조서도 필요할 수 있다.

AI 응답 생성 도중 자료·실행·조서가 바뀌면 그 초안을 적용하지 않는다. 자료·실행 변경 뒤에는 새 AI 초안과 사람 검토가 필요하며, 조서 재저장·수정 뒤에는 내용 재승인이 필요하다. AI 적용 조서에서 유효한 내용 승인이 없으면 검토완료본을 만들 수 없다. 기존 수동 조서는 AI 미적용으로 구분한다.

**조서·원장 연결**  
금융상품 A02, 매출 A04, 감가상각 A12, 리스 A15, 대손 A07, 재고 A11, 급여 A16, 비용 A08/A09, 원천 R01, 재무제표 F01, GLA G01, FIA I01, 현금 H01 등에 계산 상세가 연결된다. 자동 생성된 조서의 목적·계획은 실제 수행기록이 아니다. 각 절차가 같은 수준의 자동계산을 가진 것은 아니므로 수동계획만 제공하는 절차와 구분한다.

**한계**  
이름은 문자열이며 로그인 본인인증·인증 전자서명이 아니다. 필드를 채우고 검토 버튼을 눌렀다는 사실이 충분·적합한 감사증거와 전문가적 판단을 보장하지 않는다. 필수 예외 조서를 범위 제외로 처리해 전체 검토를 우회할 수는 없지만, 그 사유의 회계적 타당성은 사람이 검토해야 한다.

## 23. 작업 이력 — 무엇이 언제 저장되는가

**목적**  
현재 최종 상태만 보는 대신 자료·검사·요청·조서·검토의 저장 순서를 확인한다.

**필요 로우데이터**  
업무 생성, 자료 등록, 검사 실행, 자료요청 저장, 조서 개정·검토, 검토의견, 실제 AI 초안·적용·내용 승인의 로컬 이벤트를 사용한다.

**실제 검사·계산**  
**작업 이력** 탭은 이벤트 순번·KST 시각·종류·대상·상태·입력한 작성/검토 이름을 보여준다. 행을 선택하면 해당 저장 내용의 상세 JSON을 읽는다. 로컬 SQLite는 이전 해시와 현재 이벤트 해시를 연결하고 별도 이력헤드와 끝을 비교한다. 스키마·순서·결과 해시·원본 사본도 확인한다.

**예외 결과**  
누락·일반 변조·DB/헤드 불일치·결과/사본 해시 오류는 열기·사용을 차단한다. 긴 이력의 화면 미리보기는 일부 생략될 수 있으나 원래 이벤트와 출력 증적JSON은 별도 보존한다.

**조서·원장 연결**  
같은 조서 ID·요청 ID의 여러 저장 이벤트를 조회해 이전 내용과 상태를 확인한다. 검사 실행에는 입력자료 ID·결과·해시·시각이 있어 조서 근거 버전과 연결된다. 조서 저장·검토요청·검토결과는 각각 개정 이력으로 남는다.

AI는 생성·적용·사람 수정·내용 승인을 별도 이벤트로 남긴다. 모델·프롬프트 버전·응답 원문·근거 패킷과 해시를 보존하고, 승인에는 해당 개정·내용 해시·자료 버전·입력한 승인자·판단 메모를 고정한다. 적용하지 않은 초안도 실제 저장된 응답이면 적용된 조서와 구분해 추적한다.

**한계**  
저장 전 키보드 입력, 모든 화면 클릭, 실제 이메일 발송 로그를 수집하는 기능은 아니다. 자료요청에는 인증된 요청자 필드가 없고 실행시각은 로컬 환경에 의존한다. DB·헤드·코드를 모두 관리하는 사용자를 상대로 한 외부 불변 로그·제3자 증명이 아니다. Excel 출력 자체도 별도 업무 이벤트로 자동 추가하는 기능은 아니다.

## 24. Excel 조서 출력·증적 보존

**목적**  
검토중 자료와 요건을 갖춘 선택조서를 사람이 읽을 수 있는 정적 Excel로 출력한다.

**필요 로우데이터**  
현재 업무 기본정보, 자료·분석 이력, 현재 모듈/TB 연결, 조서·검토의견·자료요청·후보와 절차 카탈로그를 사용한다.

**실제 검사·계산**  
**초안 Excel 내보내기**로 XLSX 초안을 출력하고, 별도의 **검토완료본**과 상태를 구분한다. v1.7.0의 초안 출력 버튼 이름은 **검토중 저장**이었다. 표지·실행목록·모듈TB연결·증거등록부·요청/수령·수행검토조서·개별 조서·예외·계산표·변경이력·증적JSON을 생성한다. 지원 계산 조서에는 실행/자료 ID·정책·계산값·TB 비교·상세표 링크가 포함된다. 출력 중 자료 버전이나 사본이 바뀌었는지도 확인한다. 문자열은 수식으로 실행되지 않게 정적으로 저장한다.

AI 초안이 있는 업무는 AI초안목록·AI근거참조·AI적용이력·AI최종내용승인 4개 시트를 더한다. 전체 응답·근거 패킷·이력은 증적JSON에도 보존하며 미승인 초안의 상태를 숨기지 않는다.

**예외 결과**  
원본·DB를 출력으로 덮어쓰지 못한다. 검토완료본은 차단·미확인 원장 연결, 필수 조서 누락/미검토, 미완료 요청, 미해결 의견, 자료변경 후 재검토 등을 검사한다. TB 차이 자체를 자동으로 없애지는 않으며 해당 차이·예외 조사와 필수 조서 검토가 필요하다.

AI 적용 조서의 현재 내용 승인이 유효하지 않으면 기존 별도 검토기록이 있더라도 검토완료본을 차단한다. 자료·조서 변경 후 과거 내용 승인으로 통과하지 않는다.

**조서·원장 연결**  
출력은 당시 실행·자료·조서와 해시를 보존하는 스냅샷이다. 화면 필터·페이지에 보인 일부 행만 출력하는 것이 아니라 선택한 업무의 전체 보존 범위를 출력한다. 증적JSON은 Excel 셀 한도 때문에 여러 조각으로 담는다.

**한계**  
검토완료본은 선택 조서의 검토기록 상태이며 전체 감사 완료·감사의견 발행이 아니다. Excel은 정적 사본이라 입력을 바꿔도 자동 갱신되지 않는다. Excel 하나로 업무 DB·원본 전체를 복구할 수 없어 DB·이력헤드·원본을 함께 백업한다.

## 25. 업종별 검토계획과 아직 자동화하지 않은 절차

**목적**  
업종별로 추가로 확인할 위험·조건·자료를 정리해 자동 수치 검사 이후의 실제 검토로 이어준다.

**필요 로우데이터**  
자회사별 활동조건·위험·관련 조서·기존 수치지원 범위·추가 요청문서 계획을 사용한다. 실제 활동이 있다면 보증/클레임, 로트·사용기한·보관, BOM·수율·공정재고, 개발 프로젝트·계약 등 추가 근거를 요청해야 한다.

**실제 검사·계산**  
4개 자회사에 각 5개씩 총 20개 주제·60개 요청문서 템플릿을 관련 조서의 계획으로 연결한다. 12개 주제는 기존 기능 일부와 연결할 수 있고 8개는 전용 자동 계산이 없는 수동계획이다. 적용조건과 필요한 자료를 조서 범위에 보여준다. JS 모회사에는 업종계획을 적용하지 않는다.

**예외 결과**  
자료가 없으면 실제 수행·결론·검토를 자동 채우지 않는다. 해당 활동이 없다면 적용 여부와 사유부터 기록한다. 요청문서 목록이 있다는 이유로 수령·검사 완료를 표시하지 않는다.

**조서·원장 연결**  
예를 들어 전자·자동차의 재고/보증/장비/R&D, 반도체의 조건부 공정재고/NRV/장비/검수, 바이오의 사용기한/조건부 개발계약/연구비/용역귀속 계획을 A11·A19·A12·A13·A04 등 관련 수동조서에 연결한다. 숫자 계산이 없는 계획은 TB 합계에 억지로 더하지 않는다.

**한계**  
보증·리콜·공정수율·개발비 인식·위탁개발 수익·투자평가·연결제거 등이 모두 구현된 통합 계산기라는 뜻은 아니다. 공개 기준·업종 자료는 설계 참고이며 해당 기간 적용 기준과 실제 증거는 감사인이 확인한다.

## 기능을 시연하는 순서

1. JS를 선택해 모회사에 업종·매출·재고 자료가 없고 축소 현금/투자/자본 원장만 있음을 보여준다.
2. JS전자 등 자회사 하나를 선택해 로우데이터의 최초 입력과 원천 Excel을 연다.
3. 원장·리드에서 독립 행수·차대 총액·GL/TB 연결과 계정 리드를 설명한다.
4. 매출의 송장/원장 양방향 대사, 감가상각의 월별 계산, 재고 A11과 급여 A16의 별도 결과를 보여준다.
5. 원천의 선택32행·32대상·32배부와 미확인8 범위, 재무제표의 TB/본문/주석 차이를 구분한다.
6. GLA/FIA/현금 후보에서 원문·조건·정상 사유와 추가 자료요청으로 이동한다.
7. **조서초안 작성**에서 관련 절차를 고르고 실제 수행·판단을 기록하거나 AI 근거 초안을 확인·적용한다. 사람이 수정·저장·내용 승인하고, 작업 이력에서 생성·적용·개정·승인 이벤트가 구분되는지 확인한다.
8. 아직 실제 수행·결론·검토가 없는 조서는 검토완료본을 만들 수 없음을 보여준다.
9. **초안 Excel 내보내기**로 XLSX를 출력해 조서·계산표·근거·변경이력을 확인한다.

## 구현 근거와 검증 읽는 법

기능 설명의 근거는 입력 연결부(adapters), 원장(ledger), 기존 금융·매출·자산 계산기, 확장검사, 리스/ECL/재고/급여/비용귀속 계산기, 원천/재무제표 연결부, GLA/FIA/현금 분석기, 업무/조서/요청 저장부, 검토후보 연결부, Excel 출력부다. 실제 기준 준수나 고객감사를 수행했다는 외부 인증으로 제시하지 않는다.

검증은 정상 입력뿐 아니라 누락·중복·반대부호·과배부·다른 회사·다른 기간·현재 원장 변경·사본 변조·미검토 조서의 검토완료본 차단 등을 구분해 확인한다. 다만 소스 검사, 실제 창의 소스 실행, EXE 독립 실행, 원격 자동검사는 다른 검증 범위다. 최종 통과 수치와 배포 상태는 해당 버전 검증·릴리스 기록을 따른다.
