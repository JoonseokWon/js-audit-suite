# 통합 회계감사 v1.4 사용안내

이 프로그램은 자료를 등록하고 재계산·대사한 다음, 회계사가 원인과 근거를 검토하여 조서를 작성하는 로컬 도구다. 데이터가 일치한다는 결과와 감사 결론을 구분한다. 처음에는 합성 더미업무로 흐름을 확인한 뒤 별도의 업무 폴더에서 본인 자료를 사용한다.

## 통합 더미업무로 시작하기

프로그램을 실행하고 상단 **통합 더미업무**를 누른다. 저장할 상위 폴더를 선택하면 새로운 더미업무 폴더가 생긴다. 기존 10개 계산 모듈과 원천증빙, 재무제표·주석을 순서대로 실행한다. 검사 중에는 완료 또는 취소를 기다린 뒤 업무나 자료를 바꾼다.

**자료·검사** 탭에는 모듈별 실행 시각, 차단·검토 건수와 사용한 입력이 표시된다. 정상 더미에서도 수행내용·검토자·감사 결론은 자동 확정되지 않는다. 다음 순서로 내용을 살펴본다.

1. **원장·리드**: 59개 계정의 기초·변동·기말, 조정 전후 리드, 기존 계산과 TB의 32개 연결을 확인한다. 잔액은 차변 `+`, 대변 `-`다.
2. **결과 상세 → 재무제표·주석**: `재무제표대사`에서 94개 비교, `TB본문매핑`에서 전체 계정 매핑, 원장 연결과 JSON 원본 위치를 확인한다. 정상 샘플의 선택 주석은 8개다.
3. **결과 상세 → 원천증빙**: 원천표, 선택 모집단, 배부, 행별 대사, 현재 원장 연결과 미확인 범위를 확인한다. 원문 행의 위치와 금액을 함께 읽는다.
4. **절차·조서**: `R01 원천증빙·거래배부 검토`, `F01 재무제표·본문·주석 대사`를 선택하면 연결된 실행과 자료 범위를 확인할 수 있다. 실제 수행내용과 판단은 직접 작성한다.
5. **검토중 저장**: 저장 위치를 골라 Excel 조서 초안을 만든다. 현재 화면 검색이나 페이지 이동으로 가린 행도 전체 내보내기에는 포함된다.

원천 114표를 보존한 것과 114표의 모든 거래를 대사한 것은 다르다. 정상 공통팩은 선택한 원천 32행·대상 32행의 32개 배부를 검사하며, 확인하지 못한 8개 범위를 따로 남긴다.

## 본인 업무 만들기와 입력

**새 업무**를 누르고 회사코드·회사명·기간·회계체계·감사기준·작성자를 입력한다. **빈 폴더 선택 후 생성**으로 보관 폴더를 정한다. 기존 업무는 **업무 열기**에서 `업무.sqlite3`가 있는 폴더를 고른다.

**자료 복사**는 선택한 위치에 `통합감사_v1.4_입력자료` 폴더를 만들고 입력양식과 더미자료를 복사한다. 같은 이름의 폴더가 이미 있으면 다른 위치를 고른다. 빈 양식을 채울 때에는 시트명·헤더 순서를 유지하고 수식 대신 확정값을 입력한다. 빈칸은 필요한 값이 없다는 뜻이며 0으로 대신하지 않는다.

**자료·검사**에서 모듈을 고르고 **파일 선택 → 등록·검사 실행**을 누른다. 원장·리드를 먼저 실행하고 계정별 입력을 등록한 뒤 원천증빙·재무제표를 실행한다. 모듈을 잘못 선택하면 입력 구조가 맞지 않아 차단될 수 있다.

| 입력 형태 | 등록 위치 | 준비 방법과 범위 |
|---|---|---|
| `.xlsx` | 원장·리드 및 기존 9개 계산 모듈 | 배포 양식과 같은 시트·열에 확정값과 독립 추출통제를 입력 |
| `financial.json` 형식 `.json` | 재무제표·주석 | 회사·기간·버전·단위, 본문/주석 문서, 항목, 명시적 합계 관계, 계정 매핑, 필수 선택 주석 연결을 입력 |
| `.auditpack` | 원천증빙 | 원문 XLSX와 spec으로 생성한 카탈로그 및 선택 모집단·금액 산식·배부표를 함께 제출 |
| `account-evidence-1` 형식 `.json` | 계정별증빙연습 | 포함된 독립 합성 사례를 사용. 실제 업무용 임의 문서의 범용 입력 규격으로 보지 않음 |

앱에 등록하는 자료는 파일당 25MB 이하다. 각 모듈은 별도 행·열·내용 한도도 검사한다. 입력 문서 안의 문구는 증빙 내용으로 다루며 프로그램의 지시로 실행하지 않는다. PDF·사진을 증거 파일로 보관할 수 있으나 계산 입력을 자동 추출하지는 않는다.

## 기존 PBC 목록과 원천 명세 찾기

기존 전체 더미세트를 가지고 있다면 `통합감사 원천자료/2026-10-23/배포/00_남은절차_자료요청목록.xlsx`에서 48개 절차, 자료요청, 필드사전, 관계와 대사 등을 확인한다. 같은 원본 묶음의 `통합감사_원천자료_더미세트_20261023.zip`에도 해당 파일이 있다. 이 행정용 PBC 책자는 v1.4 앱의 **자료 복사** 대상이라고 가정하면 안 된다.

소스 묶음만 있어도 `testdata/raw_source_baseline/spec.json`과 그 아래 `배포/`의 16권으로 원천 자료별 파일·시트·헤더·행을 확인할 수 있다. 이 baseline은 기존 원본을 보존한다. `raw_input_seed/spec.json`은 현재 v1.3 원장·리드 1권만 맞춰 교체한 통합용 명세다. 나머지 15권의 바이트는 baseline과 같다. 원장 구버전과 신버전의 차이를 확인하려면 두 spec과 `raw_input_seed/preparation.json`의 교체 이력을 비교한다.

JSON 명세는 검사 규격이므로 엑셀에서 임의로 열어 다시 저장하기보다 텍스트 편집기에서 확인한다. 실제 회사 자료로 바꾸려면 파일·시트·헤더 매핑, 문맥과 배부 범위를 함께 설계해야 한다. 원본 파일만 바꾼 뒤 예전 카탈로그를 계속 사용하면 원문 대조에서 차단된다.

## 자료요청·수령 관리

먼저 **증거·검토의견 → 증거 파일 등록**에서 받은 파일을 등록한다. 파일은 업무 폴더 안에 사본으로 보존되고 등록 시 SHA256이 기록된다. 그다음 **자료요청** 탭에서 요청자료, 요청처, 기한과 요청범위·처리내용을 입력하고 상태를 선택한다. 수령 사본은 목록에서 여러 개 선택할 수 있다.

| 상태 | 기록할 내용 |
|---|---|
| 요청 | 필요한 자료와 기간·범위, 요청처, 기한 |
| 부분수령 | 받은 사본을 연결하고 남은 자료·범위를 기록 |
| 수령 | 등록한 수령 사본을 연결하고 수령 범위를 기록 |
| 검토완료 | 등록한 사본을 연결하고 검토한 범위·처리내용을 기록 |
| 취소 | 취소한 이유와 범위를 기록 |

**요청·수령 기록 저장**으로 변경 이력을 남긴다. 부분수령·수령·검토완료는 등록된 증거를 연결해야 저장할 수 있다. `검토완료`는 사용자가 기록하는 처리상태이며 자료 내용의 충분성·적합성을 프로그램이 판정했다는 뜻은 아니다.

요청·부분수령·수령으로 남아 있는 항목이 있으면 **검토완료본** 출력이 차단된다. 받은 자료를 검토한 뒤 상태를 바꾸거나 취소 사유를 기록한다. 자료요청 목록은 Excel의 `자료요청·수령`과 전체 변경이력에 포함된다. 기존 PBC 책자를 앱 요청 목록에 자동으로 전부 수입하는 기능은 포함하지 않는다.

## 차단·차이·미확인 읽기

**차단**은 입력의 필수값·형식·문맥·매핑·원장 완전성 등 선행 조건이 충족되지 않은 상태다. 원본과 규격을 보완하여 다시 실행한다. 전표 차대가 맞더라도 독립 추출통제와 차이가 나면 원장 누락을 의심할 수 있다. 원본과 통제값을 같은 자료에서 다시 더한 것만으로 독립성이 생기지는 않는다.

**검토 또는 차이**는 비교한 두 값이 다르다는 뜻이다. 허용오차 안에 있는 비영 차이도 남긴다. 차이의 사유·추가 증거·회계처리 영향을 조서에서 검토한다. 하나의 잘못된 소계가 상위 합계와 TB 비교에 반복하여 나타날 수 있으므로 차이 행을 단순 합산하여 전체 왜곡표시 금액으로 사용하지 않는다.

**미확인**은 연결할 자료가 부족하거나 선택 범위 밖이거나 현재 원장과 연결되지 않았다는 뜻이다. 0이나 일치로 바꾸지 않는다. 원천배부의 미배부·부족배부도 곧바로 미기록부채로 확정하지 않는다.

**결과 상세**에서 모듈과 표를 선택하고 행을 누르면 원본 위치·조건·계산값을 자세히 볼 수 있다. 예외를 더블클릭하면 관련 예외 조서를 작성할 수 있다. 선택 모집단과 금액 부호는 배부표에 명시하며 절댓값으로 억지로 맞추지 않는다.

## 원장이나 입력을 바꿨을 때

입력 재등록은 새 사본과 실행 이력을 남긴다. 실패한 최신 실행을 이전 정상 실행으로 숨기지 않는다. 원장·리드를 바꾸면 원천증빙과 재무제표 검사는 이전 원장 실행에 묶여 있으므로 두 모듈을 다시 실행해야 한다. 값이 같더라도 실행 버전이 달라졌으면 다시 확인한다.

현재 원장과 연결되지 않은 R01·F01 조서는 검토 요청을 할 수 없다. 자료나 검사가 바뀌면 기존 조서는 **자료변경·재검토** 상태가 될 수 있다. 다시 수행 근거를 확인하고 조서를 저장한 뒤 검토를 요청한다. 검토된 문구를 새 자료에 그대로 유효한 것으로 취급하지 않는다.

## 조서 작성·검토와 Excel 저장

**절차·조서**에서 절차를 선택하고 작성자, 실제 수행일, 목적·주장, 위험·기준, 모집단·선정 범위, 실제 수행내용·예외 조사, 판단·추가절차를 작성한다. 연결할 증거 사본을 선택하고 **조서 저장·개정**을 누른다. 자동으로 표시된 계산 범위는 실제 수행기록을 대신하지 않는다.

48개 기존 절차의 수동 조서를 작성할 수 있으며 R01·F01·W01 및 발생한 예외·TB 연결차이 조서도 별도로 다룬다. 목록에 있다는 이유만으로 해당 절차의 계산과 감사 판단이 모두 구현된 것은 아니다.

검토 순서는 **조서 저장·개정 → 검토 요청 → 작성자와 다른 검토자 및 검토내용 입력 → 검토기록 완료**다. 보완이 필요하면 **보완 의견**을 남긴다. **증거·검토의견**에서 등록한 의견은 후속조치와 해결 기록을 남긴다. 이름 입력과 상태 변경은 인증된 전자서명이 아니다.

**검토중 저장**은 초안을 보관하는 용도다. **검토완료본**은 등록한 검사·선택 조서의 검토기록 완료 상태를 저장한다. 다음 조건이 남으면 출력할 수 없다.

- 등록된 원본 사본이 누락되거나 변경됨
- 현재 원장 실행 없음, 계산 차단 또는 모듈-TB 연결 미확인
- 원장 변경 후 원천증빙·재무제표를 다시 실행하지 않음
- 필수 계산·수동절차·예외 조서 누락, 필수 조서의 범위 제외
- 작성된 조서의 현재 버전 검토 미완료 또는 미해결 검토의견
- 자료요청의 처리 미완료

숫자 차이가 있어도 충분한 추가절차와 검토기록을 남길 수 있으므로, 출력상태를 곧바로 모든 차이가 해소되었다는 뜻으로 읽지 않는다. 출력에는 등록한 조서와 검사 범위가 명시된다. 전체 감사를 완료했다거나 감사의견을 발행했다는 뜻은 아니다.

Excel에는 조서표지, 검사실행목록, 모듈TB연결, 증거등록부, 자료요청·수령, 개별 조서, 상세 계산표·원문 위치, 예외, 변경이력과 전체 증적 JSON이 포함된다. 정적인 확정값을 내보내므로 입력을 고쳤다고 이미 저장한 Excel이 자동으로 갱신되지는 않는다. 다시 실행·검토하고 새로 저장한다.

## 계정별 독립 증빙연습

상단 **계정별 증빙연습**에서 사례를 고르고 **새 독립 업무에서 실행**을 누른다. 현금·금융상품, 매출·채권, 매입·재고, 유형·무형자산, 리스, 급여, 차입·세금, 자본·공시, 재무제표·현금흐름의 9개 계정군에 33개 제한된 합성 사례가 있다.

결과의 `계정별검사`와 `원천증빙원문`에서 구조화된 가상 문서의 필드와 재계산을 확인한다. 기대 결과 300개는 검증용 기준이며 앱은 입력의 기대값을 계산 결과로 사용하지 않는다. 이 문서들은 실제 계약서·공적 장부·직접 조회 회신이 아니다.

각 사례는 서로 독립된 거래 묶음이다. 회사코드가 같아도 전체 TB에 합산하지 않으며 현재 통합업무와의 원장 대사가 완료되었다고 표시하지 않는다. 연습 업무는 **검토중 저장**으로 출력한다. 이 연습이 세금·자산 처분·손상·DB 등 해당 계정 전반의 실무 기능을 완성했다는 의미는 아니다.

## 현재 계산 범위와 남은 절차

|---|---|---|
| 원장·리드 | 독립 통제·전표 차대·계정 매핑·조정 전후 리드 | ERP 추출 범위와 통제 근거의 독립 확인 |

| 미기록부채·비용이연 | 확정 KRW 용역의 후속송장/지급 귀속과 제한된 선급 배분 | 외화·부가세·재고/자산 취득·변경/환불·추정충당 |

재무제표 모듈이 승인조정 금액을 자동 반영하지 않는 점에 유의한다. 리드에 조정 전후를 표시하는 기능과 재무제표의 조정전 대사는 서로 다른 기능이다. 승인조정이 있으면 조정전 기준의 검토사항을 확인하고, 조정후 입력이라고 선언한 자료는 지원하지 않아 차단한다. 원장 양식으로 ERP의 연결구분을 독립 확인할 수 없으므로 재무제표 통합은 KRW 별도 업무에 한정한다.

## 소스 실행과 재현 검사

Windows Python/Tk 환경에서 프로젝트 폴더를 연다. 현재 단위·소스 UI 검증은 Python 3.14.8에서 수행했다. 의존성은 `requirements.txt`에 있다.

```powershell
python -m pip install -r requirements.txt
python app.py
```

입력 재생성과 검사 명령은 다음과 같다. baseline은 프로젝트 안에 포함되어 개인 PC의 외부 폴더를 참조하지 않는다.

```powershell
python tools/prepare_raw_seed.py --build-pack
python tools/prepare_v14_samples.py
python -m unittest discover -v
python tools/verify_headless_v14.py --output-dir 검증/직접재현_headless
python app.py --self-test-v14 --report 검증/직접재현/report.json
```

원천팩 재현은 baseline의 원장·리드 1권만 현재 샘플로 교체하고 나머지 15권의 원문 보존을 확인한다. 이어 정상 재무제표와 공통 거래 10사례를 재생성한다. 단위 검사는 입력 통제·계산·통합 상태를 검사한다. 화면 없는 검사는 새 폴더 또는 빈 출력 폴더가 필요하고 이전 증적을 덮어쓰지 않는다. 마지막 명령은 창을 띄워 합성 업무, Excel 초안, 화면 캡처와 보고서를 만든다. 검증 명령이 만드는 수행·검토 기록은 테스트용 합성 문구다. 사용자의 실제 수행·수동 검증으로 보지 않는다.

현재 로컬 소스·EXE 검사 결과는 다음과 같다. 서로 다른 검사 단위를 합쳐 하나의 검사 건수처럼 표현하지 않는다.

| 구분 | 확인 결과 | 근거 |
|---|---|---|
| 단위 테스트 | 376개 통과 | `검증/단위검사.txt` |
| 파일 단위 더미사례 | 기존 213 + 독립 계정 33 + 재무제표 14 + 공통 거래 10 = 270개 | 소스 및 EXE 보고서의 사례별 결과 |
| 독립 계정 기대 결과 | 33사례·300개 일치 | 독립 연습 사례별 비교 |
| 화면 없는 회귀 검사 | 파일 270사례·확인 항목 1,665개 통과 | `검증/headless_v14_ci_3.14_20261023/report.json` |
| UI 회귀 | 새 통합 항목 1,288개, 기존 UI 항목 45개 통과 | `검증/소스통합_3/report.json`, `검증/독립실행_2/report.json` |
| 소스↔EXE | 관찰 결과 56개 동일 | `검증/빌드결과.json` 및 두 보고서 |
| EXE 독립 폴더 실행 | 통과, 20,797,505바이트 | `검증/빌드결과.json` |

검증한 **통합 회계감사 v1.4.exe**의 SHA256은 `e3fdea51099fa8640fd734fb31bfab089f8129cdc0ba33338f74099ff1e2a80b`다. 소스 보고서의 `frozen:false`는 Python 실행, EXE 보고서의 `frozen:true`는 EXE 실행이다. Windows 개발 PC의 별도 폴더에 EXE만 복사하고 실행 경로를 System32로 제한하여 확인했다. 창 내부 기능을 호출한 검사이며 다른 PC·깨끗한 OS·운영체제 파일선택창 조작까지 확인한 것은 아니다.

원격 검증 결과는 해당 태그의 [GitHub Actions](https://github.com/JoonseokWon/for-ax-node-project/actions) 및 [v1.4.0 릴리스 기록](https://github.com/JoonseokWon/for-ax-node-project/releases/tag/audit-suite-v1.4.0)에서 확인한다. 로컬 빌드 통과와 원격 CI·릴리스 게시의 확인은 구분한다.

## 보관과 역할

업무 폴더의 `업무.sqlite3`, `이력헤드.json`, `원본/`을 함께 백업한다. 일부 파일만 옮기거나 원본 사본을 수정하면 이력·해시 검증이 실패한다. Excel 출력만으로 업무 폴더의 모든 보관 기능을 대체하지 않는다.

회계 요구사항과 검증 관점은 사용자가 담당하고 AI가 코드 구현과 자동 검사를 보조했다. 자동 검사 통과가 회계감사기준 준수, 실무 도입 승인 또는 사용자의 실제 수동 검증을 뜻하지 않는다. 동일 생성기의 합성 원장·증빙은 독립된 외부 감사증거가 아니다. 최종 회계 판단, 충분한 감사증거의 평가, 조정 승인과 감사의견은 담당 회계사가 수행해야 한다.
