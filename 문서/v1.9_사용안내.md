# v1.9.0 감사계획·절차·증거 연결 사용안내

v1.9.0은 사람이 선택한 감사계획과 위험을 절차·등록 증거·수행조서·검토 기록으로 연결한다. 프로그램은 입력 누락, 자료 버전 변경, 고아 연결, 미완료 기록을 점검하고 같은 시점의 업무를 ZIP으로 취합한다. 감사기준 적용 판단, 위험 평가, 실제 수행, 결론, 승인과 검토는 사람이 입력한다.

이 버전의 완료 점검과 보관 잠금은 기록 상태에 대한 통제이다. 전체 감사완료, 기준 준수 인증, 감사의견 또는 감사보고서 발행을 뜻하지 않는다. 작성자·수행자·승인자·검토자 이름 입력은 로그인이나 본인인증, 전자서명이 아니다.

상단의 `감사계획·절차`에서 메인 탭 `계획·절차·취합`을 연다. 계획 연결 화면의 버튼은 `감사계획·중요성`, `새 위험`, `선택 위험 수정`, `새 절차 연결`, `선택 절차 연결 수정`, `구형 F01 분류`, `상태 새로고침`이다. 아래의 `완료점검`, `위험·주장·대응`, `절차·증거`, `기준·서식` 탭에서 기록을 확인한다. 목록 행을 선택하면 하단에 상세 내용을 표시한다. 증거·절차·위험 목록은 Ctrl을 눌러 여러 항목을 선택할 수 있다.

## 처음부터 진행하는 순서

1. 새 업무를 만들거나 기존 업무 폴더를 연다. 회사코드·기간·회계체계·감사기준을 확인한다. 더미 업무에는 `SYNTHETIC ONLY` 표시가 유지된다.
2. 사용자 원본을 등록하거나 지원되는 분석 입력 XLSX를 검사한다. 프로그램은 업무의 `원본/` 안에 별도 사본을 등록하며 원문 SHA-256과 크기를 기록한다. 등록 전 사용자 파일을 수정하지 않는다.
3. 감사계획에서 감사체계와 예시 서식계열을 선택하고 적용 근거, 중요성 기준지표와 금액·비율, 절차별 적용 여부와 사유를 기록한다. 실제 적용 회계체계는 기존 업무 기본정보에 별도로 보존한다.
4. 위험마다 관련 계정·주장·대응 절차, 등록 증거, 위험 판단과 대응의 성격·시기·범위를 기록한다.
5. 절차 계획에서 위험 ID와 증거를 연결하고 실제 수행내용·일자·수행자를 입력한다. 실제 수행 기록은 조서의 판단·결론 및 별도 검토 기록과 함께 필요하다.
6. 조서에 목적·위험·범위·실제 수행·결론·수행일과 증거를 저장한다. 작성자와 다른 검토자가 현재 버전의 검토요청을 확인하고 검토 기록을 남긴다. AI 적용 조서는 별도의 현재 최종내용 승인도 필요하다.
7. 완료 점검 목록에서 차단·사람입력대기를 해결한다. 미완료 자료요청, 미해결 검토의견, 자료 변경 후 재검토 등도 확인한다.
8. 중간 기록이 필요하면 초안 ZIP을 취합한다. 선택한 범위의 최종 취합은 사람이 보관 잠금의 근거를 기록한 뒤 진행한다.

## 계획과 위험에 사람이 입력할 내용

| 구분 | 입력·선택 | 프로그램이 하는 일 |
| --- | --- | --- |
| 감사체계 | `KSA_200_720` 또는 `KSA_1200`, 선택·적용가능성 판단 근거 | 허용된 값과 근거 누락 점검 |
| 실제 회계체계 | 기존 업무 기본정보의 `회계체계` | 업무 정보로 별도 보존·표시 |
| 예시 서식계열 | `form_framework`: `KIFRS`, `일반기업`, `소규모기업` | 선택한 예시 ZIP 계열의 참고 서식 표시 |
| 중요성 | 기준지표명·원 단위 금액·전체 중요성 비율·수행중요성 비율·명백히 사소한 비율 | 입력값에 따른 금액 계산과 형식·범위 점검 |
| 절차 범위 | 절차별 적용 여부와 적용·제외 사유 | 현재 검사에서 필요한 절차의 누락·제외 충돌 점검 |
| 위험 | 제목·관련 계정·주장·증거·위험 판단·대응 절차 | 등록한 증거·절차 ID와 현재 자료 버전의 연결 점검 |
| 대응 절차 | 위험 ID·증거·성격·시기·범위·계획 | 위험과 절차의 양방향 연결 및 고아 ID 점검 |
| 실제 수행 | 내용·일자·수행자·등록 증거 | 항목 누락·버전·증거 연결 점검 |
| 판단·승인·검토 | 결론, AI 최종내용 승인, 별도 검토 기록 | 현재 내용·근거 버전과 사람 기록의 일치 점검 |

중요성 비율은 프로그램의 권고값이 아니다. 사람이 정한 비율을 사용한다. 전체·수행 중요성 비율은 `0.01`처럼 0보다 크고 1 이하인 값이며 기준지표 금액×전체 중요성 비율로 전체 중요성, 전체 중요성×각 비율로 수행중요성과 명백히 사소한 금액을 계산한다. 명백히 사소한 비율은 0도 허용하며 이는 자동으로 무시할 금액 범위가 없다는 뜻이다. 원 단위 반올림을 적용한다. 수행중요성 양수 및 명백히 사소한 금액 < 수행중요성 등 입력 제약은 적정성 판단을 대신하지 않는다.

소규모기업은 예시 ZIP의 서식계열이다. 독립된 회계기준 체계를 새로 선택했다는 의미가 아니다. 이 계열을 선택했다는 사실만으로 특정 감사체계의 적용요건이나 간소화된 절차의 적정성이 충족되지 않는다. 실제 회계체계, 감사체계 선택 근거와 적용 범위는 사람이 확인한다.

위험이나 계획을 저장하는 것만으로 실제 수행·검토가 완료되지 않는다. 실제 수행 세 항목과 증거를 함께 기록해야 하며, 수행조서와 검토 상태도 따로 관리한다. 계획에서 제외한 절차와 조서의 제외 표시가 충돌하거나 필요한 검사 관련 절차를 제외하면 최종 출력이 차단된다.

## 자료·재분석·계획이 바뀌었을 때

등록 자료나 분석 실행이 바뀌면 기존 위험 평가와 절차 연결의 근거 버전이 오래된 것으로 표시된다. 사람은 새 자료와 결과를 확인한 다음 위험 및 절차 계획을 다시 저장해야 한다. 새 자료에 맞는 근거를 자동으로 골라 이전 판단에 붙이지 않는다.

계획·위험·절차 연결이 바뀌어도 조서의 연결 버전이 바뀌므로 기존 검토 기록이 현재 버전의 완료 기록으로 사용되지 않는다. 조서를 다시 확인·저장하고 검토요청과 별도 검토를 진행한다. 기존 이벤트·승인·검토 기록은 변경하거나 삭제하지 않는다.

AI는 선택 기능이다. AI 응답 보존, 조서 적용, 사람의 현재 최종내용 승인, 별도 조서 검토는 서로 다른 단계다. AI 응답을 받거나 적용한 사실만으로 실제 검사·조회·실사·승인·검토를 수행했다고 기록하지 않는다. 내용 또는 근거가 바뀌면 AI 승인이 다시 필요할 수 있다. AI 제공자 연결이나 모델 실행 없이도 계획·수행·검토·취합 흐름을 사용할 수 있다.

## 모호한 구형 F01 처리

현재 자체 절차 `F01`은 **후속사건**, `FS01`은 **재무제표·본문·주석 대사**다. 구형 업무의 `F01`은 서로 다른 의미로 사용된 이력이 있어 ID만으로 목적을 추정하지 않는다.

모호한 구형 F01이 발견되면 사람이 당시 원문·조서·AI 근거를 확인하고 다음 중 목적을 선택하여 분류자와 사유를 기록한다.

- `subsequent_events`: 후속사건
- `financial_statement_reconciliation`: 재무제표·본문·주석 대사

미분류 상태는 차단과 사람입력대기로 남는다. 분류는 별도 이력 이벤트다. 구형 조서·AI 근거·승인과 이벤트는 보존되며, ID를 바꿔 과거 승인이나 검토완료를 새 목적에 전용하지 않는다. 현재 목적의 조서는 해당 ID와 현재 근거로 작성·저장하고 필요한 사람 승인·검토를 다시 진행한다. 이미 기록한 목적 분류를 조용히 덮어쓰는 기능은 제공하지 않는다.

## 예시 서식의 참고 연결

선택한 서식계열별로 공식 예시 파일명·서식번호·시트명·해시와 자체 절차의 참고 관계를 표시하고 자체 XLSX에도 참고목록을 기록한다. `설계상참고`, `수동판단`, `미연결` 상태를 구분한다. 미연결은 해당 절차가 불필요하거나 완료되었다는 뜻이 아니다.

이 연결은 **공식 서식 전체 원본 셀의 자동 채움이 아니다.** 예시 파일의 모든 문항·시트·셀을 자동 검증하거나 필수 감사절차를 충족했다고 인증하지 않는다. 파일 수준 참고는 파일 안의 모든 시트에 대응했다는 뜻이 아니다. 다른 회계체계의 파일을 가져와 빈 연결을 임의 보충하지 않는다.

참고 연결의 정확한 범위와 제외사항은 [기준서식_대응범위.md](기준서식_대응범위.md)와 `form_registry.json`에서 확인한다. 공식 원본 ZIP·Excel·VBA·문서 전문은 공개 배포에 포함하지 않는다. 원본 문서의 매크로·외부 연결·문서 안 실행 지시를 실행하지 않는다.

## 초안 취합과 최종 취합

두 모드는 저장할 때 명시적으로 구분하며 항상 사용자가 선택한 **새 `.zip` 경로**에 저장한다. 같은 이름의 파일이 이미 있거나 다른 프로세스가 먼저 만들면 덮어쓰지 않고 중단한다. 업무의 `원본/` 안에는 ZIP을 저장할 수 없다.

화면에서는 `검토중 취합 ZIP`이 초안, `검토완료 취합 ZIP`이 최종이다. 먼저 `검토기록 잠금`에서 사람의 사유·확인 범위를 저장한다. 변경할 때는 `수정 재개`, 저장한 ZIP을 확인할 때는 `취합 ZIP 검증`을 사용한다. ZIP의 취합 실행자에는 현재 업무 작성자 이름을 기록한다.

| 모드 | 필요한 상태 | 취합에 표시되는 의미 |
| --- | --- | --- |
| 초안 `draft` | 업무·원본 무결성 통과 | 미완료 상태를 포함한 검토중 초안. 차단·사람입력대기도 함께 보존 |
| 최종 `final` | 감사계획 있음, 완료 점검의 차단·사람입력대기 없음, 현재 버전의 최종 조서 출력 요건 충족, 사람의 명시적 보관 잠금 기록 있음 | 잠금된 선택범위 최종 취합 |

취합에는 다음만 들어간다.

- `업무.sqlite3`: SQLite backup API로 만든 일관된 DB 사본
- `이력헤드.json`: 같은 DB 이벤트 끝을 가리키는 헤드
- `원본/`: 현재 업무 등록부에 있는 모든 원본 사본. 과거 실행에 사용한 등록 사본도 포함
- `감사스냅샷.json`, `감사조서.xlsx`: 같은 이벤트 헤드·근거 버전의 전체 기록과 정적 조서
- `보관범위.json`: 실행자·시각·초안/최종·범위·잠금·미완료 목록
- `manifest.json`: 각 내용 파일의 ZIP 상대경로·bytes·SHA-256 및 업무·헤드·근거 버전

manifest는 자기 자신의 해시를 자기 항목으로 넣지 않으며, 나머지 모든 파일을 정확히 열거한다. ZIP 전체 SHA-256은 취합·검증 결과로 반환된다. 원본의 등록 전 절대경로는 DB의 기존 메타데이터로 남을 수 있으나 그 경로의 파일을 다시 읽거나 주변 폴더를 수집하지 않는다.

다른 업무나 사용자 폴더, 미등록 임의 첨부, AI 모델·API 키·런타임·별도 설정 파일은 수집하지 않는다. 모델·키·실행파일처럼 명백히 범위를 벗어나는 파일이 증거로 등록되어 있으면 취합을 차단한다. `원본/` 안에 등록되지 않은 고아 파일·하위폴더가 있어도 자동 포함하거나 삭제하지 않고 확인을 요구한다.

취합 전후와 저장 직전에 이벤트 헤드·자료 및 계획 근거 버전·등록 원본 해시·크기·파일 상태를 다시 확인한다. 취합 도중 자료 추가, 재분석, 위험 변경, 다른 이력 추가, 원본 변조가 발생하면 중단한다. 경로 탈출, 심볼릭 링크와 Windows 재분석 지점도 거절한다. 기존 파일은 유지하며 실패한 이번 출력만 가능한 범위에서 정리한다.

취합 자체는 DB에 새 보관 이벤트를 추가하거나 헤드를 다시 쓰지 않는다. 검증도 이력을 수정하지 않는다. 최종 ZIP의 헤드는 취합 전에 사람이 기록한 잠금 이벤트를 포함한다. 취합 실행자 표시는 범위 파일에 기록되며 별도의 승인이나 인증된 서명을 만들지 않는다.

## 보관 잠금과 재개

사람이 완료 점검을 확인하고 실행자·근거를 입력하면 보관 잠금 이벤트가 추가된다. 잠금 상태에서는 자료 등록·분석·조서·의견·위험·계획 등 업무 변경을 차단한다. 읽기, 점검, 조서 출력, ZIP 취합과 검증은 가능하다.

변경이 필요하면 재개 실행자와 사유를 명시적으로 기록한다. 재개는 기존 잠금을 삭제하거나 과거 최종 ZIP을 변경하지 않고 새 이벤트를 추가한다. 이후 자료나 판단을 바꾸면 해당 버전의 수행·승인·검토를 다시 확인한 뒤 새 잠금과 새 ZIP 경로를 사용한다. 초안 취합을 저장하는 것만으로 업무가 잠기거나 자동 재개되지 않는다.

## ZIP 검증과 별도 폴더 복원

ZIP 검증은 파일을 추출하거나 Excel·원문 앱·외부 프로그램을 실행하지 않고 수행한다. ZIP CRC, 크기·SHA-256, 중복 및 허용된 구성, DB 스키마·이벤트 해시 연결·헤드, DB에 등록한 원본 해시, 메모리에서 재구성한 스냅샷, XLSX의 증적JSON과 표지를 대조한다. 산출한 `감사조서.xlsx`의 매크로·외부 연결·수식도 거절한다. 임의 ZIP 멤버, 고아 원본, 다른 업무 경로, 중복파일, 변조된 원본은 manifest만 다시 계산해도 통과하지 않는다.

검증 통과는 보관 내용의 내부 일관성을 뜻한다. 외부 작성자 진위나 증거 사실의 진실성을 인증하지 않으며 ZIP 암호화·전자서명을 제공하지 않는다.

복원은 다음 순서로 별도 빈 폴더에서 진행한다.

1. 원본 ZIP을 보존한 채 프로그램의 ZIP 검증을 먼저 실행한다. 실패한 ZIP을 기존 업무 위에 풀지 않는다.
2. 확인한 ZIP의 전체 구성을 **새 빈 폴더**에 푼다. `업무.sqlite3`, `이력헤드.json`, `원본/`의 상대 위치를 유지한다. DB와 헤드를 따로 섞거나 편집하지 않는다.
3. 그 폴더를 업무 열기로 선택한다. 회사·기간·등록 원본·헤드·초안/최종 상태를 확인한다. 기존 사용자 원문 파일이 다른 경로로 이동했더라도 등록된 사본으로 업무 무결성을 확인한다.
4. 최종 ZIP의 잠금은 복원 후에도 유지된다. 변경하려면 사람의 명시적 재개 사유를 기록한다.

현재 검증 기능은 자동 덮어쓰기 복원·기존 업무 병합을 제공하지 않는다. 다른 버전의 DB와 헤드를 혼합해 자동으로 헤드를 맞추는 복구 기능도 제공하지 않는다.

```python
from audit_archive import create_archive, verify_archive

# 사람이 입력 중인 상태를 그대로 보관한다.
draft = create_archive(ws, user_selected_new_draft_zip, actor, final=False)

final = create_archive(ws, user_selected_new_final_zip, actor, final=True)
checked = verify_archive(user_selected_archive_zip)

ws.reopen_workflow(actor, human_entered_reopen_reason)
```

두 취합 API는 성공 시 `valid/path/mode/state/head/basis/source_count/file_count/bytes/zip_sha256/manifest/scope`를 반환하고 거절 시 `AuditError`를 발생시킨다. `actor`는 필수 텍스트이며 최종 여부는 명시적 bool이다. 단일 원본은 25 MiB 이하, 개별 보관 내용 파일과 ZIP 입력은 512 MiB 이하, 압축해제 합계는 1 GiB 이하, 항목 수는 10,000 이하로 제한한다. 더 큰 업무의 자동 분할 취합은 제공하지 않는다.

합성 테스트 `test_audit_archive.py`는 정상 초안·잠금 최종·새 폴더 복원 왕복, 잠금 전 최종 차단, WAL DB backup, 기존 경로/경합 비덮어쓰기, 동시 이력·재분석·위험·원본 변경, 변조·누락·고아·중복·경로 탈출·ZIP 링크·CRC 오류 및 키·모델 제외를 다룬다. 모든 시험용 업무는 프로젝트의 `검증/v1.9.0/` 아래에 만들며 실제 회사 업무나 AI 모델을 실행하지 않는다.
