# GLA: 현재 원장의 설명 가능한 검토후보 분석

`analyze(path, context, ledger_result=None, event=None)`는 공통 원장 7시트에 `GLA설정` 시트를 추가한 확정값 XLSX를 읽습니다. `analytics_support.read_bound`가 입력 통제·실제 현재 업무 원장·조정전 리드를 다시 비교합니다. 연결이 유효하지 않으면 분석을 완료하지 않고 차단하며 `현재원장연결` 표와 원문 SHA를 보존합니다.

GLA설정은 `항목, 값` 열이며 `DEFAULT_SETTINGS`의 규칙버전·주말검토·월말검토·월말범위일·고액검토·고액기준원·반복검토·반복최소횟수를 빠짐없이 한 번씩 입력합니다. 사용/미사용은 명시값입니다. 월말범위일 0은 마지막 날, 고액은 전표 차변합계가 기준 이상, 반복은 회사별 동일 계정·차변·대변 구성의 다중집합이 기준 횟수 이상인 경우입니다. 날짜·적요·전표ID가 다른 정기 거래도 반복후보가 될 수 있습니다.

출력 표는 `월별집계`, `계정별집계`, `작성자별집계`, `계정조합`, `전표계정조합`, `검토후보`, `규칙검토범위`, `후속절차`, `현재원장연결` 및 입력 원문입니다. `검토후보`는 후보ID·규칙ID·전표ID·사유·원본행·후속절차·우선순위를 갖습니다. 금액은 차변과 대변을 더해 두 배로 만들지 않습니다. 전체 원장의 월별 차대량은 현금흐름이나 거래 실질을 뜻하지 않습니다.

계정집합 1:1과 개별 행 대응을 구분합니다. 전체 2행 중 활성 차변 1행·대변 1행인 경우만 개별 행 1:1로 표시합니다. 같은 계정으로 나뉜 2개 차변행과 1개 대변행은 계정집합이 1:1이어도 개별 대응 미확인입니다. 복합분개는 계정집합으로 집계하고 임의 차대 계정 곱집합이나 현금 대응을 만들지 않습니다. 0원 TB 계정도 계정별 집계에 남습니다.

반복 후보에는 짧은 사유와 `반복그룹ID`를 기록합니다. 그룹 전체 전표ID·계정금액 구성·원본행은 `반복그룹색인` 표에 한 번만 저장합니다. 각 후보에 같은 전체 목록을 반복 복사하지 않습니다.

가용 필드는 전기일과 작성자 문자열입니다. 실제 입력시각·수동/자동·시스템·승인자 증거는 없으므로 심야·수동·승인 우회를 추정하지 않고 미확인 규칙으로 표시합니다. 주말·월말·고액·동일 구성은 정상 거래에서도 나타납니다. 우선순위는 검토 순서이며 부정확률이나 부정·오류 확정이 아닙니다. 사람의 수행·결론·검토·조정 승인은 비워 둡니다. 외부 AI 전송이나 실제 AI 추론 없이 오프라인 규칙만 실행합니다.

`write_samples(target)`는 정상 전체 규칙·고액 경계·주말·월말·반복·정상 유사거래·누락·중복·회사/기간·현재 원장 불일치의 12개 입력과 독립 기대 `cases.json`을 만듭니다. 주말/반복 양성 사례에는 순수 원장 7시트 `current_ledger` 파일을 함께 제공합니다. 그 파일을 먼저 현재 원장으로 실행해야 의도한 위험 탐지를 시험할 수 있습니다. 정상 전체 규칙 사례의 24개 후보는 오류 확정이 아니며 검토가 필요한 의도된 결과입니다. 기대값은 계산기 입력에 포함하지 않습니다.
