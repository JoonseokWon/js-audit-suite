# v1.5 읽기 전용 교차검토

GLA 구현 후 FIA·현금분석·현재 원장 연결·검토 도우미를 읽었습니다. 다른 워커 및 PM 소유 코드는 수정하지 않았습니다. 아래는 검토 당시 코드에 대한 재현 결과이며 수정 후에는 다시 확인해야 합니다.

## 현금 배부의 명시 메타 모순을 확인하지 않음

위치: `cash_analytics/__init__.py` 187행 이후 현금배부 처리. 당시 204행은 계좌ID만 비교하고 206행부터 배부합계를 누적했습니다. 은행행과 선택한 원장행에 모두 있는 거래처ID·상대계좌·지급근거ID·거래구분의 모순은 확인하지 않았습니다.

재현: 기존 정상 합성 원장 및 `cash_analytics.samples._tables(base)`를 사용했습니다. 현금원장선택의 첫 행 `(SYNTH01, J-L, N5)`에서 거래처ID·상대계좌·지급근거ID를 각각 `CONTRADICTING-*` 문자열로 바꾸었습니다. 은행거래·배부ID·금액·계좌ID·실제 공통 원장 7시트는 그대로였습니다. 은행거래 `SYN-B001`와 해당 전표행을 -120,000원으로 잇는 명시 배부를 유지했습니다.

관찰: 차단 0, 검토 0, 잔여 0, 후보 0, 미확인 0으로 통과했습니다. 은행 12행·선택원장 12행·배부 12건도 정상처럼 보였습니다. 계좌/금액이 일치하더라도 제공된 지급근거·상대방 정보가 모순되므로 조용히 대사 완료로 볼 수 없습니다. 제공된 양쪽 메타의 모순은 차단 또는 명시 검토 이슈로 남기고, 누락은 해당 규칙 미확인으로 보존하는 통제가 필요합니다.

재현 파일: `verification/cross_cash_gl_metadata.xlsx`, 관찰값: `verification/cross_cash_gl_metadata_result.json`. 둘 다 GLA 패키지 안의 교차검토 자료입니다. PM에게 전달했습니다.

## 그 외 확인 범위

- FIA는 시간대 포함 입력시각·입력자·수동자동·승인 등 명시 메타를 받고, 원장 전기일/적요로 심야·수동을 추정하지 않습니다. 누락·중복 복합키 및 전표 내 메타 충돌을 차단합니다. 같은 입력자의 전체 전표 대비 수동 비율이라는 분모는 README에 설명되어 있습니다.
- 현금 기초+입금-출금=기말을 계좌별로 다시 계산하고, 은행 독립 행수·입출금 및 TB 기초/기말 대사를 수행합니다. 명시 배부의 부호·과배부·잔여를 보존합니다. GL 식별자는 회사·전표ID·행ID 복합키입니다.
- 현재 원장 바인딩은 실제 7시트 의미값과 리드를 다시 검사합니다. workspace는 새 세 모듈에 실행ID/결과 해시를 붙이고, 원장 재실행 시 현재 연결을 미확인으로 표시합니다.
- 검토 도우미는 실제 AI 추론을 사용하지 않는다고 표시하고 원문 위치·SHA·후속자료 요청 초안을 제공합니다. 수행·판단·승인은 사용자 기록으로 남깁니다.

이는 읽기 및 명시된 반례 검증 범위입니다. 모든 규칙·실무 적용·기준 준수 또는 깨끗한 OS의 EXE 실행을 확인했다는 뜻은 아닙니다.
