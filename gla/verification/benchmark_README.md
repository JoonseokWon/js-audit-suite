# GLA 10,000행 상한 실측

v1.5 폴더에서 `python -B -X utf8 gla/benchmark.py`로 실행합니다. 결과 요약은 `gla/verification/benchmark_10000.json`이며, 생성 XLSX는 `gla/verification/benchmark_inputs/` 아래에만 씁니다. 배포에는 생성 XLSX를 제외하고 스크립트·요약 기록만 포함합니다.

기존 합성 원장 82행에 36,400원씩 균형을 이루는 2행 전표를 4,959개 추가하여 정확히 10,000행·4,993전표를 만듭니다. 회사·전표ID·행ID 복합키는 모두 고유합니다. 원장·TB·독립통제 표를 동일 합성 생성기로 재계산하므로 외부 독립 감사증거라고 주장하지 않습니다. 현재 원장은 `ledger.analyze`를 별도로 실행한 실제 결과로 전달하며 GLA가 원장 통제와 연결을 다시 검사합니다.

기본 4개 규칙을 모두 켜서 월말 21·고액 3·반복 4,960개의 후보가 예상됩니다. 반복 그룹 전체 ID·원문행은 색인에 한 번 저장하고 각 후보의 짧은 사유와 그룹ID로 연결합니다. 집계의 총 10,000행·차대 합계·원본 복합키·현재 원장 10,059개 연결행·후보별 원문행·규칙 적용 모집단을 확인합니다.

추가 1행의 0원 전표행을 넣은 10,001행 파일은 차대 균형을 유지하지만 입력 행수 제한에 걸려 위험 집계 전에 차단되어야 합니다. 이 검사는 정수 금액·자료 한도의 확인이며 해당 0원 행의 회계 실질을 확인하는 절차가 아닙니다.

기록된 시간은 해당 환경의 단일 소스 Python 실행입니다. XLSX 읽기·입력검증·현재 원장 재계산·집계·후보 생성을 포함하며, 화면 표시·EXE·조서 내보내기 시간은 포함하지 않습니다. Windows 프로세스 메모리는 같은 프로세스의 관찰값이며 다른 PC의 메모리·성능 보장이 아닙니다. 이 기록으로 10만·100만 행이나 임의 기업 자료의 실무 적용이 검증되었다고 주장하지 않습니다. 원본 소스·샘플은 전후 해시와 의미값을 비교합니다.

실측 환경은 Windows 11 AMD64, CPython 3.14.8 64비트입니다. 최초 기록은 32개 검사를 통과했습니다. GLA 읽기·검증·집계·후보 생성은 2.384934초, 별도 현재 원장 실행은 0.106473초였습니다. 생성용 XLSX 한 파일 쓰기 20.631813초 및 두 파일 생성 등을 포함한 전체 46.277896초와 구분합니다. 반복 후보 4,960개를 포함해 총 4,984개 후보가 있었으며, 후보 사유는 최대 55자·반복 색인은 1행·전체 결과 JSON은 16.774MiB였습니다. 월·계정·작성자·전표 집계는 원장 10,000행과 차대 각 194,649,816원을 보존했고 현재 원장 연결 10,059행에서 누락이 없었습니다. 10,001행 입력은 0.444327초에 차단되어 보고 원장행수와 후보수는 0이었습니다. 상세 수치와 원문 해시는 JSON 기록을 확인합니다.
