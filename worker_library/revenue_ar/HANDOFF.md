# 매출·채권·대손 워커 인계

이 폴더는 PM이 통합하기 전의 독립 합성 자료와 진단 예시다. 기존 원장에 합산하지 않았고 신규 JSON의 EXE 가져오기, TB, 리드스케줄 및 조서 자동 연결도 구현하지 않았다. 실제 회사·고객·은행 거래·조회 발송·조회 회신은 없다.

## 만든 자료와 기존 자료 색인

- `manifest.json`: 계정과 경영진 주장, 기존 6개 XLSX의 20개 시트·범위·헤더·행수·SHA256 및 `spec.json`의 JSON 위치, 추가 요청 자료, 연결키, 자동 검사와 감사인 판단, 조서 필드, 구현 상태를 기록했다.
- `fixtures.json`: 회사 SYNTH01, 2026년, KRW, 별도 기준의 독립 합성 5사례다. 2027년 입금·조회·반품 검색기간은 따로 표시했다. 신규 ID는 REV-로 시작하며 기존 거래에 자동 연결되지 않는다.
- `verify_fixtures.py`: 표준 라이브러리만 사용하는 독립 검증기다. 자료를 수정하거나 전기하지 않고 결과를 출력한다.

기존 자료 색인은 실제 XLSX 압축 내부의 시트·헤더·행수를 읽어 확인했고 파일 해시와 고정했다. spec의 위치·헤더·행수도 비교한다. 모든 셀의 회계적 타당성을 검증했다는 뜻은 아니다.

기존 통합 v1.3의 매출 주문·납품·청구·원장, 확장검사의 채권연령·후속회수, 대손충당금 입력 스키마와 모듈 연결 코드를 확인했다. 이번 워커에서 기존 EXE를 다시 실행하지는 않았다. 계약·반품검색 및 조회 통제대장 보조 XLSX는 변환·신규 검사 연결이 필요하다. 별도 포트폴리오 v1.1과 검증 수를 합산하지 않는다.

## 검증 결과

실행은 이 폴더에서 `python -B verify_fixtures.py`로 한다. Python 3.12.14에서 AI가 자동 검증했다. 사용자 직접 검증 완료를 의미하지 않는다.

| 사례 | 내용 | 고정 기대 결과 |
|---|---|---|
| REV-C01 | 주문 20개 × 5,000원, VAT 10,000원, 채권 110,000원, 후속입금 60,000원 | 10개 진단 값 일치 |
| REV-C02 | 고객 검수일 2027-01-04, 매출은 2026년에 기장 | 해당 계약 검수 조건 가정에서 매출 100,000원 과대 가능성 |
| REV-C03 | 반품 대변메모 11,000원 기장 누락 | 기장 채권감소 0원 − 기대 11,000원 = −11,000원; 공급가 10,000원과 VAT 1,000원 별도 추적 |
| REV-C04 | 직접 조회 회신 미수령, 후속입금은 60,000원 존재 | 조회 진단 INPUT_BLOCKED, 회신·차이 값 null 유지; 후속입금 일치가 회신을 생성하지 않음 |
| REV-C05 | ECL 가정은 같고 장부충당금만 1,000원 | 필요액 1,430원 대비 −430원. 내부 롤포워드가 맞아도 ECL 재계산 차이는 검출 |

50개 고정 기대 비교가 일치했다: PASS 46개, 의도한 EXCEPTION 3개, 의도한 INPUT_BLOCKED 1개. 오류를 발견한 결과까지 기대대로 나온 것이며 50개 모두 회계적으로 정상이라는 뜻은 아니다. 추가 방어 검사 17개도 통과했다. 송장·반품검색·은행 원본 누락, 만기일 null과 ECL 전파, 충당률 구간 공백, 중복 시나리오·증빙, 확률 합계 오류, 회사 전달 회신, 타 송장 입금 배부, 다른 회사 혼입, 음수 채권, 근거 공란, 잘못된 날짜를 차단한다. 명시된 0 손실률 및 음수 충당금 환입은 보존한다.

ECL 고정 계산은 110,000원 × (1% × 70% + 2% × 30%) = 1,430원이다. 손실률·확률·구간은 임의 합성 가정이며 권장 충당률이 아니다. 원 단위 반올림은 ROUND_HALF_UP이다. 과거 손실, 미래 전망 및 단기 할인 영향의 근거 참조가 있어야 재계산하며 그 근거의 적정성을 기계가 승인하지 않는다.

각 진단은 원본 필드, JSON 위치, 기대 값·실제 값·차이 및 후속절차를 반환한다. 작성자·검토자·결론은 null, 조정 승인·전기는 false다. `evaluate(case, context)`의 결과를 PM이 조서 어댑터에 연결할 수 있다. `case`에 fixtures 배열 순서인 `_index`를 부여한다.

## 감사절차 설계에 확인한 공식 근거

- [IFRS Foundation IFRS 15 소개](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-15-revenue-from-contracts-with-customers/): 수행의무·대가·통제이전 확인이 수익인식의 출발점이다. 이 사례의 고객 검수 조건은 계약 판단을 미리 가정했다. 출고일·검수일·세금계산서일 중 하나를 모든 계약의 수익인식일로 고정하지 않는다.
- [XRB ISA (NZ) 505](https://standards.xrb.govt.nz/standards-navigator/isa-nz-505/), 6·7·10~14 및 A12~A18: 감사인 조회 통제, 직접 회신과 신뢰성, 미회신의 후속절차를 구분했다. 특정 후속입금·출고자료는 대체절차 후보이며 충분성 판단은 별도다. 적극적 조회 회신 자체가 필요한 상황에서는 대체절차로 요구 증거를 얻지 못할 수 있다.
- [XRB NZ IFRS 9](https://standards.xrb.govt.nz/standards-navigator/nz-ifrs-9/), 5.5.15·5.5.17·B5.5.35: 유의적 금융요소 없는 매출채권의 전체기간 ECL, 확률·미래 전망, 충당률표의 조건을 참고했다. 이 예시는 입력 가정의 재계산 범위다.

2026-10-23에 공식 공개 출처를 조사했다. XRB 자료는 뉴질랜드 채택본이므로 한국 회계감사기준 및 K-IFRS의 적용 문구·시행일·해당 법인 방법론을 별도로 확인해야 한다. 기준 전문을 복제하지 않았다. 한국 기준 준수나 감사 완료의 인증이 아니다.

## PM이 다음에 연결할 내용

1. 금융 워커의 은행거래ID, 재고 워커의 출고·반품입고ID와 매출 송장·행ID 연결표를 정한다. 다대다 입금 배부, 수수료·환율·상계·선수금, 중복배부를 공통 통제로 검증한다.
2. 기존 SI01·AR01 등과 신규 REV- 독립 사례를 섞기 전에 승인된 공통 거래·분개·TB를 만든다. 기간귀속과 반품 누락이 해결되지 않은 원장의 AR/ECL 수치를 최종 조서 금액으로 승격하지 않는다. 여기의 PASS는 해당 수치 진단만 통과한 상태다.
3. 송장별 기초·변동·기말, 매출원장, AR 통제계정, VAT 및 충당금 연결을 검증한다. 현재 예시의 AR_TIE는 이 독립 거래의 기장값끼리만 비교한다. 원장 전체의 완전성이나 두 계정의 총액 일치를 입증하지 않는다.
4. 고객별 거래조건·기말 전후 거래·전체 반품검색·제각·손상 징후 및 ECL 과거 자료를 추가한다. 양도·팩토링·담보·외화·계약자산·용역 기간인식·변동대가와 반품충당은 별도 구현 대상으로 둔다.
5. 실제 조회는 검증된 조회처, 감사인 발송·직접 회신, 회신 진위, 차이조사, 미회신과 대체절차의 근거를 따로 저장한다. 합성 boolean 필드가 true여도 실제 외부증거로 취급하지 않는다.
6. 문서 누락·수치 예외는 미검토 조서의 후속절차로 연결한다. 같은 거래의 매출·채권·VAT·충당금 차이를 단순 합산해 총왜곡표시로 만들지 않는다. 분개 승인·전기 및 최종 결론은 감사인에게 남긴다.
