# 매입·재고·매입채무 워커 인계

이 폴더의 자료는 합성자료 설계·검증 패키지이다. 기존 통합 앱 v1.3 또는 별도 포트폴리오 v1.1에 이번 JSON의 가져오기 기능을 추가한 결과는 아니다. PM 공통 원장에 아직 편입하지 않았으며 `integrated=false`이다.

## 산출물과 실행

- `manifest.json`: 계정·경영진 주장, 기존 실제 파일/시트/셀과 SHA256, 현행 spec 위치, 추가 PBC, 연결키, 구현/미구현, 판단 및 조서 필드.
- `fixtures.json`: 동일 독립 거래의 정상·오류 변형 5개. 각 결과에 원본 값, 기대 값, 차이·단위, 문서ID/JSON pointer와 후속 절차를 기록했다.
- `verify_fixtures.py`: 표준 라이브러리만 사용한다. 원본 Excel 및 fixture는 읽기만 하고, 결과 JSON을 화면에 출력한다.
- `HANDOFF.md`: 범위·검증·제약 및 PM 후속 과제.

이 폴더에서 `python -B verify_fixtures.py`를 실행한다. 통합 앱 설치나 외부 패키지는 필요하지 않다. 작업 시 Python 3.12.14로 실행했다.

## 검증 결과

2026-10-23 실행 결과는 PASS이다. 이는 오류가 없다는 뜻이 아니라, 넣어둔 정상·예외·입력차단의 고정 기대 결과를 모두 재현했다는 뜻이다.

| 독립 사례 | 검사 결과 | 의미 |
|---|---|---|
| INV-01-NORMAL | 정상 12 | 수량100, 세전100,000원, 세액10,000원, 채무 -110,000원, 후속출금 -110,000원. 실사100, NRV1,100원 ≥ 원가1,000원 |
| INV-02-MISSING-AP | 정상8·예외1·차단3 | 입고·송장·후속출금은 존재하지만 원장 전표 전체 누락. 기록 건수0은 확인하되 원장 채무금액은 null 유지 |
| INV-03-CUTOFF | 정상6·예외6 | 2027-01-02 검수시 소유권 이전인데 2026년에 채무·재고 선계상. 공급자 명세·수불·실사에서도 같은 원인을 추적 |
| INV-04-COUNT-NRV | 정상10·예외2 | 실사95와 장부100 차이5개. NRV=750-50-100=600원, 장부수량 기준 충당금40,000원 후보 |
| INV-05-NULL-NRV | 정상11·차단1 | 판매가격 null을 0원으로 대체하지 않고 평가 비교 차단 |

합계 **5개 사례의 고정 결과 60개**를 비교했다. 결과는 정상47·예외9·입력차단4이다. 별도로 문서ID 중복, 회사 불일치, 소수 금액, 입고증 누락, 잘못된 날짜, 입고 모집단 누락, 단위 불일치 **7가지 변형을 메모리에서 만들어 차단을 확인**했다. 파일을 변경하지 않는다.

**원천 색인 검증은 위 사례 검증과 별도다.** 실제 기존 XLSX 4개 파일 SHA256, 시트 목록, 선택한 13개 표의 정확한 셀 범위·337개 값과 현행 spec 정의 일치를 확인했다. 상대경로를 실제 경로로 해석한 뒤 spec 및 파일 존재도 검사한다. 이는 원천을 추적할 수 있다는 검사이며 실제 ERP 모집단의 독립적인 완전성 검증은 아니다.

## 기존 자료를 재사용한 범위

기존 `2026-10-23/배포`의 확장검사 파일에 발주·입고·매입송장·장부재고·실사가 있고, 재고평가 파일에는 재고명세·NRV·원장이 있다. 추가 원천자료 파일의 현행 D020~D024는 매입송장잔액·후속미청구용역·수불·권리/보관·단위환산이다. 정확한 위치는 manifest의 source_tables에 보존했다.

CSV 폴더에는 동일 시트명에 이전 D번호가 붙은 파일이 함께 남아 있다. 현재 spec과 실제 XLSX를 기준으로 색인했고 기존 파일은 수정하지 않았다. 같은 이름의 CSV를 자동으로 전부 합쳐 읽으면 중복될 수 있으므로 PM의 어댑터는 현행 자료ID·파일 경로·해시를 명시해야 한다.

기존 확장검사의 발주/입고 표에는 거래일·납품조건이 부족하다. 이 표만으로 결산일 전후 귀속을 판단할 수 없다. 별도 계약·검수·창고 번호대장·후속은행 출금·공급자 명세를 보강했다. 원장 밖 입고 및 후속출금에서 당기 원장으로 추적하는 검사를 넣어, 원장끼리 금액이 맞는 경우에도 균형 전표 전체 누락 후보가 남도록 했다.

## 기준 출처와 적용 한계

- [IFRS Foundation IAS 2 설명](https://www.ifrs.org/issued-standards/list-of-standards/ias-2-inventories/): 원가와 NRV 중 낮은 금액으로 평가하고, 예상판매가에서 완성·판매필요원가를 차감하는 원칙을 단일 품목 사례에 적용했다. 원가계산 정책·추정치 적정성 전체를 검증한 것은 아니다.
- [XRB ISA (NZ) 501, 4·5·8·A7·A8](https://standards.xrb.govt.nz/standards-navigator/isa-nz-501/): 실사 결과와 최종 재고기록 연결, 실물→기록·기록→실물 검사의 방향을 참고했다. 프로그램의 수량 일치는 감사인의 실사입회·실물 상태 관찰·제삼자 보관 확인을 수행한 것으로 취급하지 않는다.
- [XRB ISA (NZ) 500, 6·7·9·A60·A61](https://standards.xrb.govt.nz/standards-navigator/isa-nz-500/): 자료 신뢰성·정확성·완전성 평가를 참고했다. 입고와 후속지급에서 원장으로 추적하는 것은 이러한 목적에 따른 설계자의 절차 선택이다. 특정 후속 검색기간이나 이 코드가 기준서의 필수 절차라고 주장하지 않는다.

출처는 2026-10-23 확인한 공식 공개자료다. 뉴질랜드판 ISA와 IFRS 공식 개요를 참고한 것이며 국내 감사기준·K-IFRS 원문 전체 대조 또는 실무 적합성/준수 인증은 아니다.

## 판단 필요 및 미구현

검수시 소유권이 이전되는 단순 거래라는 합성 계약 조건을 명시했고 해당 조건에서만 cutoff를 계산한다. 운송조건·미착품·위탁·분쟁·상계·선급·부분입고·분할지급·기말 이전 결제는 별도 판단/배부 로직이 필요하다. 같은 기간 안에서 실제 검수일과 전기일이 며칠 다르다는 이유만으로 오류를 확정하지 않는다.

NRV 가정이 기말 상태를 반영하는지, 거래처 명세의 진위와 회신 통제가 적정한지, 현금 흐름과 전표가 승인되었는지는 자동 판단하지 않는다. 예시의 창고/은행 통제 자료도 동일 합성 작성자가 만든 자료이므로 독립된 실제 증거가 아니다. 제조 원가·FIFO·평균법, 음수 NRV/별도 의무, 샘플링·투영 및 OCR은 미구현이다.

수량차이와 NRV는 같은 재고를 포함하므로 자동 합산하지 않는다. 사례4의 충당금40,000원은 장부수량100개 기준 잠정 계산이다. 실사95개가 확정되면 순서에 따라 재계산해야 하며, 조정 후보를 기계적으로 더하면 중복 왜곡이 생길 수 있다. 사례3의 여러 채무/재고 예외도 같은 cutoff 원인을 지니므로 합산하면 안 된다.

## PM 다음 연결 과제

1. 공통 거래ID·증빙ID와 전체 원장/TB를 승인한 뒤에만 워커 거래를 편입한다. 이 다섯 사례는 동일 거래의 대안이므로 서로 합산하지 않는다.
2. 은행 워커와 `거래ID↔송장ID` 지급 배부표를 연결하고, 매출 워커의 출고ID를 재고 수불 원천ID와 연결한다. 부분 지급/분할 납품은 별도 다대다 연결표가 필요하다.
3. 공급자 명세·후속 지급·입고 모집단의 전체 추출범위와 독립 통제·취소/반품을 검증한다. 단순 원장 행수와 차대일치만으로 누락을 제거하지 않는다.
4. 기존 v1.3 Excel 입력 및 비용 모듈 변환을 별도로 개발·검증한다. 포트폴리오 v1.1의 CSV/financial.json 입력과 혼동하지 않는다.
5. 확정된 재고/채무 잔액을 GL·리드스케줄·본문/주석 대사와 연결한다. 조서에는 source_refs, 원본/기대/차이·단위·후속 절차와 예외 중복 관계를 보존한다.
6. 작성자·검토자·결론·수정분개 승인 값은 null이다. 현재 상태는 미검토 초안이며 자동 전기나 감사 결론 확정을 하지 않는다. PM은 통합 검증 후에만 EXE·릴리스를 발행한다.
