# 유형·무형자산 워커 인계

현재 상태: 초기 계정 자료 설계와 독립 JSON 검증을 완료했다. 기존 통합 프로그램 및 EXE에 새 자료 가져오기·원장·조서 연결은 아직 구현하지 않았다. 모든 자료는 합성 테스트용이며 법적 효력이 없다. 공문서 이미지, 기관 로고·인감, 실제 개인정보는 생성하지 않았다.

## 이번 범위와 산출물

- `manifest.json`: 기존 자료의 파일·시트·범위·카탈로그 위치·SHA256, 추가 자료 요청, 연결키, 자동 검사와 감사인 판단, 조서 필드 및 미구현 기능.
- `fixtures.json`: 동일한 가상 취득 거래를 바탕으로 한 독립 대안 3개. 회사 SYNTH01, 2026년, KRW, 별도. 사례 간 거래를 합산하거나 기존 A01·IA01에 추가하지 않는다.
- `verify_fixtures.py`: 표준 라이브러리만 쓰는 검증기. 기대값을 읽어 계산하는 대신 원천 문서에서 재계산하고 고정 기대값과 비교한다.

기존 `../../../2026-10-23/spec.json`의 `/books/4` 감가상각 자료와 `/books/13` 자산·비용·손상 자료를 색인했다. 관련 XLSX의 실제 시트와 값도 ZIP/XML로 확인했다. 기존 파일은 수정하지 않았다. 기존 자산 A01은 원가 1,200,000원, 당기상각 240,000원, 기말누계 480,000원이다. 기존 토지·건물·건설중인자산 자료는 거래없음 선언만 있어, 토지 증거는 이번 독립 사례에 새로 설계했다. 무형·손상 보조 XLSX는 변환이 필요한 추가 원천자료이며 기존 EXE 직접 입력이라고 표시하지 않았다.

## 고정 사례와 검증 결과

2026-10-23, 번들 Python 3.12로 아래 검증기를 실제 실행했다.

```powershell
python -B .\verify_fixtures.py
```

| 사례 | 의도와 기대 결과 | 실제 검증 결과 |
|---|---|---|
| ASSET-NORMAL | 7월 1일 사용가능 기계: (1,320,000−120,000)/60×6 = 120,000원. 유한 소프트웨어: 240,000/24×6 = 60,000원. 통상적인 무한 내용연수 토지 상각 0원. 재계산 순액 3,380,000원. | 9개 비교 모두 PASS |
| ASSET-EARLY-DEPRECIATION | 매입일이 속한 6월부터 기계상각을 잘못 계산해 장부 140,000원. 자산대장과 GL은 서로 맞아도 상각비 20,000원 과대, 순자산 20,000원 과소를 발견해야 한다. | 상각 재계산 +20,000원, 리드 재계산 −20,000원 EXCEPTION |
| ASSET-MISSING-TITLE | 토지대장은 있지만 등기 추출자료가 없다. 소유권 관련 증거 검토를 0원 또는 정상으로 통과시키면 안 된다. | ASSET-TITLE INPUT_BLOCKED, 나머지 수치 비교 PASS |

총 3개 사례, 27개 고정 기대값 비교와 추가 누락 방어 3개가 통과했다. 추가 방어는 취득원가 null, 당기상각 null, 매입송장 자체 누락을 거부하는지 확인한다. 이것은 현재 EXE의 테스트 건수와 별개다. 상각 차이와 리드 차이는 같은 오류가 전파된 결과이므로 40,000원으로 합산하지 않는다.

## 원천자료와 연결

기계의 자산대장, 매입송장, 은행지급, 입고·설치완료·사용가능 승인자료를 `company_code + transaction_id + document_id`와 `asset_id`로 연결했다. 은행 출금 −1,320,000원의 부호를 유지하고 결제 비교에서 명시적으로 한 번 반전한다. 소프트웨어는 라이선스 계약과 사용가능 승인자료를 별도로 두었다.

토지대장의 지목·면적·필지 식별정보와 등기의 소유권·담보 등 권리정보를 구분했다. 정상 사례의 ASSET-TITLE PASS는 가상 필드의 회사·필지·기준일 일치만 뜻한다. 등기 진위, 실제 권리, 현장 실재성, 담보·신탁·후속 변동 및 법적 판단까지 완료했다는 의미가 아니다. 등기자료가 없으면 토지대장으로 대체하지 않는다.

처분 검토 요청 자료에는 승인서, 매매·폐기 및 인도 증거, 입금, 원가·누계 제거, 처분손익을 넣었다. 손상 검토 요청 자료에는 징후 점검, CGU, 예산·실적, 현금흐름·할인율, 시장견적·처분원가를 넣었다. `ASSET-DISPOSAL-SEARCH`, `ASSET-IMPAIRMENT-INPUTS`는 아직 수행하지 않은 검토 입력 자리다. 회수가능액·현금흐름·결론을 null로 유지했고 처분·손상 엔진을 구현했다고 표시하지 않았다.

## PM의 후속 연결 작업

1. 신규 사례는 기존 통합 TB와 분리된 상태로 유지한다. 기존 기계 계정 1500/1590/5000 매핑을 참고하되 소프트웨어·토지의 계정코드는 PM이 배정한다. 기존 1600은 리스 사용권자산이고 5500은 급여이므로 임의 재사용하지 않는다.
2. 취득·지급·자산등록 및 원장 전표/행 ID를 연결하고 다대다 배부 금액·부가세·정산 차이를 검사한다. 이번 단순 지급 비교를 전체 은행·매입 대사로 확대 해석하지 않는다.
3. 독립 ERP 추출통제와 기초+증가−처분=기말 원가, 기초누계+상각−처분누계=기말누계를 확인한 후 리드스케줄로 연결한다. 이번 GL은 같은 합성 자료의 요약이므로 독립 완전성 증거가 아니다.
4. 조서에는 모집단/표본 기준, 증빙 ID·해시·위치, 원본값·기대값·차이·후속 절차를 넣는다. 작성자·검토자·최종 결론은 null, 상태는 미검토 초안으로 시작한다. 조정 승인·전기는 자동 확정하지 않는다.
5. 공통 가져오기 변환기와 원장·리드·조서 통합 검사를 만든 후에만 EXE와 GitHub 릴리스에 포함한다.

## 적용 가정과 남은 판단

기계와 소프트웨어는 7월 1일 사용가능, 정액 월할, 기초잔액 0, 변경·처분 없음이다. 월할은 사례의 명시적 가정으로, 회계기준이 항상 한 달 전체 상각을 요구한다는 뜻이 아니다. 일부 월·일할, 원 미만 반올림, 잔존가치·내용연수 변경, 구성요소 상각, 생산량·정률법, 건설중인자산·차입원가, 매각예정 분류, 개발비·영업권, 세무상 감가상각은 이번 검증 범위 밖이다.

자본적 지출 여부, 라이선스 자산 인식과 SaaS 구분, 잔존가치·내용연수·방법, 부가세, 토지·건물 배분, 권리·증거 신뢰성, 중요성 및 손상 추정은 감사인 판단으로 남긴다. 사용자 역할은 회계 요구사항·검증이며, 본 코드와 이번 자동 실행은 AI가 수행했다.

## 확인한 공식 출처와 적용 범위

- [XRB NZ IAS 16](https://standards.xrb.govt.nz/standards-navigator/nz-ias-16/): 50~55항의 상각대상금액·내용연수/잔존가치·사용가능일, 58항의 토지와 건물, 67~72항의 제거를 참고했다. 사용가능일 이전 상각 오류와 통상적 토지 분리에 제한 적용했다. 월할 방식 자체를 기준의 명령으로 간주하지 않는다.
- [IFRS Foundation IAS 38 개요](https://www.ifrs.org/issued-standards/list-of-standards/ias-38-intangible-assets/): 인식 요건, 유한·비한정 내용연수와 상각/손상 구분을 참고했다. 이번 소프트웨어의 자산 인식은 사례 가정이다.
- [IFRS Foundation IAS 36 개요](https://www.ifrs.org/issued-standards/list-of-standards/ias-36-impairment-of-assets/): 회수가능액과 CGU, 징후 및 연간 평가 대상에 필요한 추가 요청자료를 설계했다. 이번에 추정 적정성이나 손상차손을 검증한 것은 아니다.
- [세종시 부동산포털 중개업무 안내](https://www3.sejong.go.kr/sjrp/tradeGuide): 표제부·갑구·을구의 확인 대상 구분을 참고했다. 이는 공식 행정 안내의 자료 분류 참고이며 개별 토지 소유권의 법률 의견이 아니다.

모두 2026-10-23 확인했다. 해외 공개 기준과 공식 개요를 한정 참고했으며 한국 회계·감사기준 전체 준수 인증을 의미하지 않는다.
