# 종업원급여 워커 인계

2026-10-23 작성. 사용자 역할은 회계 요구사항·검증, AI 역할은 자료 설계·구현·자동 검증이다. 아래 결과는 AI가 실행한 합성 테스트다. 실제 회사의 감사 수행이나 사용자의 최종 검토를 뜻하지 않는다.

## 작성 범위

`manifest.json`에 계정·경영진 주장·자료 요청·연결키·자동 검사·감사인 판단·조서 필드·구현 상태를 정리했다. 기존 파일은 수정하지 않았다.

| 기존 위치 (`../../../2026-10-23/` 기준) | 재사용 위치 | 상태 |
|---|---|---|
| 배포/01_현재프로그램입력/09_종업원급여_합성자료.xlsx | 설정·인사명부·급여명세·급여원장·급여지급·연차명세·급여잔액·독립통제 | 기존 통합 앱 입력 양식의 색인. 이번 워커는 EXE 실행을 재검증하지 않음 |
| 배포/02_절차별원천자료/05_인사_급여_DB.xlsx | 근태_수당승인·종속회사_DB가입자·DB_계리변동·DC_연차정책 | 보조 원천자료. EXE 직접 입력 미지원 |
| 배포/03_오류시나리오/현재EXE/04_급여중복.xlsx | 위 입력 양식과 같은 8개 시트 | 기존 중복 오류 예시 색인 |

정확한 `spec.json` 위치는 각각 `/books/9`, `/books/14`, `/books/20`이다. manifest에 각 시트의 JSON 포인터·머리글·행수·파일 SHA256을 저장했다. 검증기는 실제 XLSX의 시트와 머리글을 읽어 색인을 확인한다. CSV에는 오래된 중복 이름이 있어 CSV 이름만으로 원천자료를 선택하지 않았다.

`종속회사_DB가입자`, `DB_계리변동`은 **SYNTH_SUB** 자료이므로 **SYNTH01 별도 재무제표**의 이번 사례와 합산하지 않는다. 기존 E01/E02와 신규 PAY-EMP-001도 별개의 모집단이다.

## 초기 더미자료

가상 사번만 사용했다. 실명·주민번호·계좌번호·인감·기관 로고는 없다. 각 문서에 합성·테스트 전용·법적 효력 없음 표시가 있다.

자료는 근로계약, 근태·수당 승인, 급여명세, 원천세 승인금액, 사회보험 승인금액, 은행지급, 미지급급여 원장, 연차명세, DC 기여금 승인, DC 납입이다. 연차·DC 문서는 원천필드 예시이며 이번 검증기에서 권리·부채·의무금액을 계산하지 않는다. 2027-01-10 DC 납입은 `subsequent_period=true`인 후속자료로 표시했다.

| 사례 | 고정 기대 결과 |
|---|---|
| PAY-001 | 기본급 3,000,000 + 승인 시간외 10×15,000 + 상여 300,000 + 기타수당 50,000 = 총급여 3,500,000원. 승인 원천세 200,000 + 사회보험 150,000 = 공제 350,000원. 순급여·당기 지급 모두 3,150,000원으로 7개 검사 PASS |
| PAY-002 | 동일한 순급여 3,150,000원과 미지급원장 0원에 대해 은행 지급이 3,100,000원. PAY-PAYMENT에서 -50,000원 EXCEPTION, 나머지 6개 PASS |
| PAY-003 | 기본월급 `null`. PAY-REQUIRED에서 INPUT_BLOCKED. 급여·공제·지급 대사 결과를 생성하지 않음 |

사례는 같은 거래의 대안 테스트다. 서로 더하거나 한 TB에 적재하지 않는다. 시간외 단가·상여·공제금액은 독립 승인 자료에 들어 있는 **합성 고정값**이다. 법정 가산율·세액·사회보험 요율 권고가 아니다.

## 실행·검증 결과

Python 3.12 이상에서 해당 폴더를 기준으로 실행한다. 외부 라이브러리는 필요 없다.

```text
python -B verify_fixtures.py
```

현재 PC에서는 번들 Python 3.12.14로 실행했고 종료 코드 0을 확인했다. 결과는 표준 출력 JSON이다. 검사 결과를 새 파일로 자동 저장하거나 기존 배포물을 수정하지 않는다.

- 독립 사례 3개, 고정 기대값 검사 15개 모두 일치.
- 추가 통제 검사 4개 통과: 동일 사번·기간 복수 급여명세 발견 후 합산 중지, 중도 입사자를 전월 급여로 처리하지 않음, boolean 금액 차단, 은행지급 문서 누락을 0으로 대체하지 않음.
- 기존 XLSX 3개 파일 SHA256 및 시트·머리글·카탈로그 행수 20개 위치 확인.
- 금액 차이는 실제 값-기대 값 부호를 유지하며 원천 위치와 함께 출력.

검사 결과는 조서의 미검토 입력으로 사용할 수 있는 형태다. 자동 조서 파일 작성, 작성자·검토자·결론 확정, 수정분개 승인·전기는 구현하지 않았다.

## 기준 참고와 한계

[IFRS Foundation의 IAS 19 공식 개요](https://www.ifrs.org/issued-standards/list-of-standards/ias-19-employee-benefits/)를 2026-10-23 확인했다. 용역 제공에 따른 급여 비용·미지급 의무와 단기급여 및 DC/DB의 구분을 참고했다. DB에는 계리적 측정이 필요하므로 월급 단순 계산으로 대신하지 않는다. 이 공개 개요 참고는 한국 노동·세무 규정이나 K-IFRS·한국감사기준 준수 인증이 아니다.

이번 검증기는 명시된 전월 고정급·한 사번·한 거래·당기 단일 지급을 위한 초기 예시다. 분할지급·급여 선급·후속지급·소급 인상·외화·중도 입퇴사 일할·휴직·급여 자산 배부·DB 계리평가·법정 세액/보험료·실제 연차권리는 구현하지 않았다. 후속 지급을 당기 지급으로 섞지 않으며 지원 밖 지급 시점은 차단한다. 전체 인사 모집단의 존재·완전성이나 증빙 진위는 이 사례만으로 검증되지 않는다.

## PM 후속 과제

1. 실제 추출용 인사·급여·세무·은행 자료의 독립 행수·합계·ID 해시와 추출 조건을 수집한다.
2. 회사·사번·급여ID·기간·거래ID·증빙ID를 기존 통합 원장/TB 및 현금 워커와 연결한다. 한 이체에 여러 사번이 포함되면 명시적 배분표가 필요하다.
3. 과소 지급 50,000원이 실제 미지급누락인지, 이체 누락인지, 은행 자료 추출 누락인지 후속 확인하고 분개를 판단한다.
4. 연차권리·DC 약정/의무금액·기한·사업주/종업원 부담을 검토한다. DB는 계리보고서·기초 자료·외부 적립자산·전기/당기 변동을 별도 검토한다.
5. 신규 JSON→앱 입력 변환기, 여러 사번/기간에 대한 연결 통제, 조서 출력·검토 상태 및 교차 계정 테스트를 구현·검토한다.

신규 JSON과 기존 EXE 연결은 **미구현**이다. 기존 통합 앱 v1.3과 포트폴리오 v1.1의 검증 건수·기능 범위를 이번 워커 결과와 합치지 않는다. EXE·GitHub 릴리스는 PM 소유다.
