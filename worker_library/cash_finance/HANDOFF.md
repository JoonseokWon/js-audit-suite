# 현금·금융상품 워커 인계

기준일 2026-12-31, 회사 SYNTH01, KRW, 별도 재무제표를 대상으로 한 합성 원천자료 설계와 독립 검증기다. 기존 원장·EXE·조서를 변경하지 않았다. 사용자는 회계 요구사항·검증을 맡고, 이번 코드 구현과 자동 검증은 AI가 수행했다.

## 산출물과 실행

- `manifest.json`: 계정·주장, 기존 자료의 정확한 파일/시트/셀/JSON 위치와 파일 해시, 추가 자료 요청, 연결키, 검사와 판단, 조서 필드, 구현 상태.
- `fixtures.json`: 정상 1건, 오류·누락 4건. 모든 사례가 동일 거래 구조를 바탕으로 한 독립 테스트이므로 사례끼리 합산하지 않는다.
- `verify_fixtures.py`: 표준 라이브러리만 사용하는 자동 검증기. 이 폴더에서 `python -B verify_fixtures.py`로 실행한다. 원래 원천자료 폴더와 상대 배치를 유지해야 기존 자료 색인 검증도 실행된다. 파일은 생성하거나 수정하지 않는다.

2026-10-23, 번들 Python 3.12.14에서 **5개 사례, 30개 고정 검사 비교, 경계 검사 5그룹, 기존 XLSX 3개·시트 위치 14개를 모두 통과**했다. 기존 파일 SHA-256, 시트 범위/행수/헤더와 spec.json의 위치를 확인했다. 이 숫자는 앱 v1.3 또는 포트폴리오 v1.1의 검증 건수에 합치지 않는다.

## 고정 사례와 계산 근거

| 사례 | 고정 기대 결과 | 후속 조치 |
|---|---|---|
| CASH-01 정상 | 은행 990,000 + 미입금 20,000 - 미결제 지급 10,000 = 장부 1,000,000. 예금 이자 9,100. 6검사 PASS | 원본·독립성·권리와 공시 검토는 별도 필요 |
| CASH-02 수수료 누락 | 은행 수수료 -500이 장부·조정표에서 누락. 조정 은행 999,500 대비 장부 1,000,000, 차이 +500, EXCEPTION | 거래 근거·원인 검토 후 분개 필요성 판단 |
| CASH-03 이자기간 오류 | 장부 92일분 9,200 대비 계약 91일분 9,100, 차이 +100, EXCEPTION | 초일·말일 포함과 계약 원문 확인 |
| CASH-04 허용오차 내 차이 | 장부 9,101 대비 계산 9,100, 차이 +1. 허용오차 10 이내여도 EXCEPTION 유지 | 중요성과 별도로 차이 원인·처리 검토 |
| CASH-05 조회 회신 누락 | 조회금액과 조회통제 2검사 INPUT_BLOCKED, 회신금액과 차이는 null | 조회 후속 요청·대체절차·증거 충분성 판단 |

새 이자 사례는 **1,000,000 × 36,500/1,000,000 × 91/365 = 9,100원**이다. 2026-10-01은 제외하고 12-31은 포함한다. 원 단위 사사오입이며, 원금 변동·복리·변동금리·수수료/할인할증이 있으면 이 작은 계산기는 차단한다. 세전/세후 이자, 유효이자율, 공정가치, 상각후원가 전반을 구현한 것이 아니다.

은행조정 후속 거래는 2027-01-02 입금 20,000, 2027-01-03 지급 -10,000이다. `as_of_date`는 감사대상 기준일 2026-12-31을 뜻하고, 원천자료의 실제 수록 기간은 `coverage_start`/`coverage_end`, 조회 발송·회신일 등으로 구분한다. 모두 합성이고 실제 금융기관·계좌번호·발송·회신은 없다. 조회 통제 플래그가 참인 정상 사례도 실제 감사인 통제 수행을 입증하지 않는다.

별도 경계 검사는 이자금액 null, 은행문서 누락, 증빙 중복, 통화 불일치를 검사하며, 91일/9,100원과 1,000,000원 은행조정 합계 고정값도 확인한다. null이나 누락 문서는 금액 0으로 바꾸지 않는다.

## 기존 원천자료 재사용 결과

기존 `2026-10-23/spec.json`의 `/books/2`는 금융상품 입력이다. D001의 2026-01-01 제외~12-31 포함 **364일 이자 36,400원**을 새 91일 사례와 구분한다. `/books/5`는 은행장부·은행거래 등 확장검사 입력이고, `/books/11`은 자금·금융·차입 보충자료다. 정확한 셀 범위와 해시는 manifest에 기록했다.

원천자료 CSV 폴더에는 같은 시트 이름에 서로 다른 자료번호를 가진 파일이 함께 있다. 이번 색인은 임의의 첫 번째 CSV를 고르지 않고 spec.json에 해당하는 실제 XLSX와 시트를 사용한다. 기존 CSV·XLSX는 수정하지 않았다.

`은행장부`의 L1~L12와 `은행거래`의 B1~B12는 별도 ID다. 기존 `계좌+참조(J-*)`와 금액/일자를 검토하여 공통 거래 ID에 연결해야 한다. `조회_통제대장`의 CONF01은 은행, CONF02는 매출채권, CONF03은 차입금이므로 각 담당과 구분한다. 기존 null 발송일·회신일 및 ‘미수행/미확인’을 조회 완료로 해석하면 안 된다. 독립통제 시트도 동일 생성기의 합성 통제이므로 독립 원본 증거로 볼 수 없다.

## 기준을 참고한 범위

[XRB ISA (NZ) 500 문단 9와 A23](https://standards.xrb.govt.nz/standards-navigator/isa-nz-500/)을 참고하여 기업 작성 자료의 정확성·완전성 확인과 수학적 재계산을 분리했다. 계산이 맞더라도 원천자료의 신뢰성과 모집단 완전성이 입증되는 것은 아니다.

[XRB ISA (NZ) 505, 2021 적용판 문단 7·10·12~14](https://standards.xrb.govt.nz/assets/Uploads/ISA-NZ-505-Dec-21.pdf)를 참고해 조회의 감사인 통제, 회신 신뢰성, 미회신·차이 후속조치 필드를 설계했다. 미회신은 금액 0이나 자동 완료로 바꾸지 않는다. 긍정적 조회 회신 자체가 필수인 상황인지와 대체절차의 충분성은 감사인이 판단한다.

공식 XRB 페이지는 [2026 개정판의 적용 시작기간을 2026-12-15 이후](https://www.xrb.govt.nz/standards/assurance-standards/auditing-standards/isa-nz-505/)로 표시한다. 이 사례는 2026-01-01 시작기간이므로 2021 적용판을 참고했다. 이는 뉴질랜드 공개 기준을 활용한 설계 근거이며, 대한민국 회계감사기준 준수 인증이나 실제 개별 감사의 적정성 판단을 의미하지 않는다. 한국 적용 기준, 보고기간, 회사별 위험과 계약 원문은 PM·감사인이 확인해야 한다.

## 구현 상태와 PM 연결 과제

기존 native XLSX는 기존 통합 앱 v1.3 모듈의 입력 양식을 재사용한 것이다. 보충 원천자료와 새 JSON을 읽는 EXE 어댑터는 이번에 추가하지 않았다. 포트폴리오 v1.1 재무제표 대사 데모와도 미연결이다. 이번 조서 산출 범위는 필드 명세·원천 추적 결과이며, 조서 작성/검토 UI 연결이나 감사 결론 생성은 없다.

PM의 다음 작업은 다음과 같다.

1. 기존 계좌·금융기관 모집단과 공통 회사/계정/계약/거래/증빙 ID 연결표를 검토한다. CASH- 사례는 기존 원장에 합산하지 않는다.
2. 매출 워커의 회수와 고객 ID, 매입·재고 워커의 지급과 거래처 ID를 은행 거래 ID에 연결한다. 동일 입출금의 중복 사용과 지급/수금 총액·기간을 통합 검증한다.
3. 새로운 은행조정·조회통제 원천자료를 앱에 변환하는 어댑터를 구현한다. 거래 종류, null, 중복, 통화, 보고기간, 후속기간, 계좌·증빙 연결 및 실제 IPE 추출통제를 확인한다.
4. 원본 값·기대 값·차이·허용오차·문서 위치·후속절차를 조서 초안에 연결한다. 작성자·검토자·결론·분개승인 값은 자동 확정하지 않는다.
5. 해당 어댑터와 원장 대사·조서 상태를 통합 검증한 뒤 PM이 EXE와 GitHub를 배포한다.
