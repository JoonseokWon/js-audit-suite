# 재무제표·현금흐름 담당 인계

이 폴더의 자료는 `SYNTH01`, 2026-01-01~2026-12-31, KRW, 별도 문맥을 따르는 독립 합성 사례다. 기존 원장이나 다른 계정 워커 자료와 합산하지 않는다. 기존 앱이나 게시된 포트폴리오 v1.1은 수정하지 않았다.

## 산출물과 범위

- `manifest.json`: TB·분개·본문·주석·현금흐름·비현금 변동·자본변동·승인조정에 필요한 자료, 연결키, 자동 검사, 감사인 판단, 조서 필드 및 미구현 범위.
- `fixtures.json`: 정상 1개, 금액 오류 1개, 근거 누락 1개의 대안 사례. 정상은 12개 합성 문서, 8개 전표, 17개 원장행, 11개 TB 계정이다.
- `verify_fixtures.py`: 표준 라이브러리만 사용하는 읽기 전용 검증기. 고정 기대값과 계산 결과를 비교하고 JSON 위치·원본 값·기대 값·차이·후속 절차를 출력한다. 실제 증빙의 진위나 적합성을 판정하지 않는다.

자료 요청은 ERP TB/원장 및 추출 통제, 본문/주석 버전과 매핑, 현금성자산 구성/은행조정, 현금흐름 거래별 분류와 배분, 비현금 투자·재무 거래, 차입부채 증감, 자본변동·배당 결의, 승인 조정 및 원장 포함 로그를 포함한다. 구체적인 필드와 조인 키는 manifest의 `additional_requests`, `join_contract`에 있다.

## 고정 수기 기대값

금액 단위는 정수 원이며 대변 잔액의 부호를 보존한다. TB는 **조정 후 미마감**으로, 당기손익 계정의 기초는 0이고 손익의 이익잉여금 대체 전이다. 본문 이익잉여금에 당기손익을 한 번 연결한다.

| 항목 | 기대값 및 산식 |
|---|---:|
| 매출·급여·감가상각비·법인세비용 | 30,000 − 10,000 − 6,000 − 2,000 |
| 당기순이익 | 12,000 |
| 현금·채권·유형자산 순액 | 17,000 + 10,000 + 33,000 |
| 자산 총계 | 60,000 |
| 부채 + 자본 | 31,000 + 29,000 = 60,000 |
| 영업현금흐름 | 20,000 − 10,000 − 2,000 = 8,000 |
| 투자현금흐름 | −5,000 |
| 재무현금흐름 | 7,000 − 3,000 = 4,000 |
| 현금 기초 + 영업 + 투자 + 재무 | 10,000 + 8,000 − 5,000 + 4,000 = 17,000 |
| 차입금 기초 + 현금차입 + 비현금 취득 | 20,000 + 7,000 + 4,000 = 31,000 |
| 자본 기초 + 당기손익 − 배당 | 20,000 + 12,000 − 3,000 = 29,000 |

감가상각비 6,000원과 차입을 통한 자산취득 4,000원은 비현금 명세에서 원장과 연결한다. 후자의 4,000원은 현금흐름에 포함하지 않고 유형자산과 차입금 증감에 포함한다. 이 합성 사례는 현금성자산을 가상 보통예금 하나로 제한한다.

## 검증 결과

2026-10-23, Python 3.12.14로 검증기를 실행하여 종료 코드 0을 확인했다.

| 사례 | 고정 기대값 비교 | 결과 |
|---|---:|---|
| FS-01 정상 | 23 | 23 PASS |
| FS-02 주석·현금흐름 기말 오류 | 23 | 20 PASS, 의도한 EXCEPTION 3건 |
| FS-03 조정 승인 근거 누락 | 1 | 의도한 INPUT_BLOCKED 1건, 금액 비교 중단 |

고정 기대값 비교 47건과 입력 통제 확인 7건이 통과했다. 입력 통제는 회사 불일치, bool 금액, null 금액, 문서 중복, TB 매핑 누락, 현금행 분류 누락, 알 수 없는 활동을 거부하는지 확인한다. 기존 XLSX **5개 파일의 15개 실제 시트명**과 카탈로그 연결, 기존 v1.1 JSON의 6개 참조 위치도 읽기 전용으로 확인했다. 실파일의 전체 행·셀 값 검증이나 기존 v1.1 재검증을 했다는 뜻은 아니다.

FS-02는 현금 주석의 17,250원과 기대 17,000원 차이 **250원**, 현금흐름표 기말현금 17,400원과 기대 17,000원 차이 **400원**을 잡는다. 같은 400원이 현금흐름 기초·기말 연결 및 BS 대사에서 각각 발견되므로 예외 3건을 왜곡 금액 합계 1,050원으로 합산하면 안 된다.

FS-03은 이미 TB에 들어 있는 감가상각 수정분개를 뒷받침하는 `FS-AJEAPPROVAL` 문서를 제거한 사례다. 원본 값과 차이는 null이며 누락을 0원으로 치환하지 않는다. 정상 사례의 `SYNTHETIC_ASSUMED_APPROVED`도 테스트 가정이며 실제 승인 행위가 아니다.

## 기존 자료와의 연결 경계

manifest에는 실제 파일 경로, 시트명, `spec.json`의 정확한 `/books/…` 위치가 있다. `../../../2026-10-23/배포/`의 기존 원천자료를 재사용하되 쓰지 않았다. `07_결산_공시_종결.xlsx`의 `현금흐름_분류`와 `재무제표_계정연결`은 기초 설계 자료이고 현금흐름·전체 공시 검증의 완료를 의미하지 않는다.

기존 포트폴리오 v1.1의 `financial.json`은 **조정전 기말잔액**을 기준으로 하는 별도 입력 규격이다. 본 폴더의 **조정후 미마감** TB를 그 입력에 바로 대입하면 안 된다. 조정의 승인 상태·전기 여부·TB 버전을 보존하는 변환기를 PM이 설계하고 중복 반영을 검증한 뒤 편입해야 한다.

## 미구현과 PM 후속 과제

1. 새 JSON을 EXE 입력·원장·리드스케줄·조서 화면에 연결하는 기능은 미구현이다. 독립 워커 사례를 기존 총계정원장에 합산하지 않는다.
2. 현금흐름 분류 적정성, 이자·배당 정책 선택, 전체 공시의 완전성, 연결재무제표 및 제거분개는 미구현이다. 공개된 현금흐름 기준에 IFRS 18 관련 개정도 표시되어 있으므로 실제 적용 체계·연도와 적용 여부는 감사인이 별도 판단해야 한다.
3. 복합 전표의 다대다 배분, 외화 환산, 제한예금, 현금성자산 범위, 기업결합·중단영업·리스의 상세 분류와 간접법 전체 재작성은 미구현이다. 현금행당 하나의 명시된 분류를 산술 집계한다.
4. 추출 통제·문서·승인 근거가 모두 같은 합성 자료에서 만들어졌다. 실제 회사의 ERP 독립 추출, 문서 진위·신뢰성, 미제출 자료까지 포함한 모집단 완전성을 입증하지 않는다.
5. 이 검증기는 고정된 작은 사례 전용이다. 임의 사용자 데이터의 전체 합계 그래프 순환·중복 계정 표현을 다루는 범용 운영 검증기가 아니다. v1.1의 기존 검증 로직을 대체하지 않는다.
6. PM은 공통 거래ID·현금 원장행·현금흐름 배분·계정매핑·증빙ID·조정ID의 연결표와 중복 방지 검증을 먼저 만든다. 특히 매출 회수, 매입 지급, 자산 취득, 리스, 차입·세금, 배당을 다른 담당 자료와 연결해야 한다.
7. 통합 시 원천 해시와 위치, 원본/기대/차이, 후속 요청 및 판단 근거가 조서에 이어지도록 한다. 작성·검토·결론·조정 승인·전기는 감사인에게 남긴다. EXE·GitHub 릴리스는 PM의 별도 통합 검토 이후다.
