# 원천자료 가져오기

`build_pack(target, source_root, links=None)`은 `source_root/spec.json`과 `source_root/배포/`의 현행 XLSX를 읽어 `.auditpack`을 만든다. 원본 파일은 수정하지 않는다. 같은 원문과 연결표로 만든 패키지는 바이트 단위로 동일하다. 기본 연결표는 `raw_accounts.build_links(catalog)`가 제공한다.

`load_pack(path, context, event=None)`은 `catalog`, `links`, `manifest`, `source`를 반환한다. source는 패키지 원래 파일명·bytes·SHA256이다. 문맥은 회사코드, 시작일, 기준일, 통화, 연결구분을 정확히 맞춘다. 기존 spec에 없던 통화와 연결구분의 기본값 KRW·별도는 manifest의 정책에 명시한다.

패키지 구성:

- `manifest.json`: 파일별 SHA256·크기, 선택 원천, 정규화 정책
- `catalog.json`: 원문 파일·시트·헤더·실제 Excel 행번호와 헤더순 값, 변환기록
- `links.json`: 선택 모집단과 거래 배부표. 연결의 회계적 검증은 `raw_accounts`가 수행한다.
- `sources/spec.json`: 선택 근거인 원본 명세
- `sources/01_현재프로그램입력/*.xlsx`, `sources/02_절차별원천자료/*.xlsx`: 원문 그대로 보존

기존 dataset의 파일·시트가 정확히 일치하면 D001~D098을 사용한다. dataset에 없는 native 설정·추출통제 시트는 `N01_설정`처럼 책 번호·시트명으로 식별한다. 과거 CSV, 오류사례, 행정용 PBC 책자를 중복 모집단으로 포함하지 않는다. 현재 원본 묶음은 16권·114표이며, 여기에는 다른 회사·후속기간의 참고자료도 포함된다. 이 전체 표가 현재 감사대상 회사의 모집단이라는 의미는 아니다.

가져올 때 해시를 확인한 뒤 원본 XLSX에서 카탈로그 전체를 다시 산출한다. 카탈로그 값을 바꾸고 manifest 해시까지 다시 계산해도 원문과 헤더·행번호·값·변환기록이 다르면 차단한다. null·0·숫자·문자열·bool을 구분한다. 작은따옴표가 붙은 ISO8601 timestamp는 원문과 정규값을 기록하고 작은따옴표 1개만 제거한다. 모두 null인 행은 데이터행으로 계산하지 않고 원문 행번호·값과 처리 내역을 기록한다.

ZIP은 외부 경로로 풀지 않는다. 경로 이탈, 절대/드라이브/역슬래시 경로, 대소문자·유니코드 중복, symlink·특수파일, 암호, 미지원 압축, 미등록 파일, 해시·크기 오류, 중복 JSON 키·비유한 수, 수식·오류 셀, 외부 참조·매크로·첨부를 차단한다. 한도는 패키지 40MB, 개별 파일 20MB, 해제 합계 100MB, 파일 128개, 압축률 200배, 시트당 데이터 10,000행·80열, 전체 200표이다.

SHA256은 같은 패키지 내부의 변경 여부를 확인하는 장치다. 제출자의 신원, 외부 증빙의 진위, 회사 제출자료의 완전성을 증명하지 않는다. 원장 대사·원천 추출범위 확인·감사인 검토는 별도 단계이다. 같은 생성기로 만든 더미자료를 독립된 감사증거로 보지 않는다.

검증: `python -m unittest test_raw_sources -v`. 기존 원문 왕복과 36개 입력 통제 테스트가 Python 3.14.8에서 통과했다. 다른 PC의 Excel에서 직접 연 수동 검증을 뜻하지 않는다.
