# JS Audit Suite — 통합 회계감사 v1.8.1

회사별 합성 로우데이터로 계산·원장 연결·예외 검토·조서 작성 흐름을 연습하는 Windows 로컬 감사 지원 프로그램이다. **JS는 업종 없는 모회사**, JS전자·JS자동차·JS반도체·JS바이오는 업종별 자회사로 구분한다.

회계 요구사항과 검증 관점은 사용자가 설계하고 AI가 코드 구현과 자동 검사를 보조했다. 수치 계산·대사는 입력과 명시적 정책에 따라 수행한다. v1.8은 별도로 실제 로컬 AI가 원문·계산 근거에 연결된 조서 초안을 제안하고, 사람이 내용을 확인·수정·승인하는 기능을 추가한다. 선택 OpenAI API는 사용자가 제공자와 전송 근거를 확인한 경우에만 호출한다. 계산 결과나 AI 내용 승인은 감사의견·기준 준수 인증이 아니다.

v1.8은 AI 조서 엔진·제공자·전용 런타임을 포함한다. v1.8.1은 이 기능을 이어받아 조서 본문·승인 메모의 한글 편집기를 교체하고, 실행파일·데이터·소스를 한 프로젝트 폴더에서 관리하도록 정리한다. 실제 모델·화면·EXE·공개 릴리스의 완료 상태는 해당 버전의 검증 기록을 확인한다. 고정 문구를 AI 응답처럼 제공하는 대체 경로는 없다. 계산 정책·회사별 합성자료·업무 저장 계약 1.7과 v1.7.0·v1.7.1·v1.8.0의 배포 기록은 보존한다.

## v1.8.1 변경과 보관 구조

조서의 목적·위험·범위·수행내용·결론 5개 본문과 **AI 내용 최종 승인**의 검토 메모는 Windows Rich Edit 일반 Unicode 텍스트 편집기를 사용한다. 한글 조합·선택·실행 취소는 Windows 편집 컨트롤이 처리하며, 앱이 IME 메시지를 가로채 조합 문자를 직접 넣지 않는다. 작성자·승인자 등 짧은 단일행 입력란은 기존 Tk 입력란이다. 구체적인 입력·저장·승인 순서는 [v1.8.1 수정안내](문서/v1.8.1_한글입력_수정안내.md)를 따른다.

프로젝트 상위 폴더는 `For ax node Project/통합감사 프로그램/`이며, 포터블 실행본의 구조는 다음과 같다.

| 폴더 | 용도 |
| --- | --- |
| `실행파일/` | `통합 회계감사 v1.8.1.exe`와 `portable-config.json`. 로컬 AI를 준비하면 전용 런타임·모델 폴더도 이 실행 환경에서 관리 |
| `데이터/회사별업무/` | 회사별 연습 목록과 업무 DB·원본·조서·요청 이력. 현재 포터블 설정이 지정한 업무 저장 위치 |
| `데이터/AI조서_시연/` | 별도로 보관한 JS전자 A04 AI 초안 연습 업무와 검토 전 Excel 사본 |
| `소스/v1.8.1/` | 코드·설정·내장 합성 모본·테스트·소스 문서 |
| `문서/` | 실행·자료 보관·기능 안내 |
| `검증/` | 해당 버전의 실제 검증 기록 |
| `보관/` | 기존 버전·이전 작업 자료 |

폴더 이동만으로 모든 기존 업무가 새 경로에 연결된다고 가정하지 않는다. 기존 AppData 업무를 새 저장 위치로 가져오는 절차와 원본 위치·무결성 검증 결과는 이관 기록을 따른다. 현재 JS전자 회사 선택은 `데이터/회사별업무/companies/JS_ELEC/e5abf99579424fe4bf30c6c82d300e93/업무`의 저장 업무를 다시 연다. `데이터/AI조서_시연/`의 예전 별도 사본과 구분한다. 이동이 제한된 이전 자료는 원본 백업을 남기고 보관 사본을 검증한다. 이전 업무를 삭제하거나 비정상 자료를 새 더미자료로 덮어 복구하지 않는다. 공개 ZIP에는 로컬 사용자가 저장한 업무·개인 자료·API 키·모델 가중치·런타임 캐시를 넣지 않는다.

앱 아이콘은 내장 ImageGen으로 이번 프로젝트용으로 새로 생성한 문서·체크 표시다. Windows ICO에는 16·20·24·32·40·48·64·128·256px의 9개 해상도를 포함한다. 사용자 첨부 stock 이미지는 사용하지 않았으며, 인증도장이나 감사의견을 뜻하지 않는다. 생성 방법과 파일 검사는 아이콘 출처·검증 기록을 따른다.

한글·줄바꿈·Unicode 저장 왕복 검사와 실제 키보드의 IME 조합 검증은 구분한다. 최종 EXE의 JS전자 A04 결론란에서 사용자가 한글 모드로 전환한 뒤 실제 키 입력으로 `ㄱ → 거 → 검`, Backspace로 받침 삭제, 다시 받침 입력, `검토` 완성, 공백·줄바꿈·숫자와 `가` 입력을 확인했다. 마지막 `가`를 조합 중인 상태에서 저장해도 해당 음절이 남았고 GUI의 Excel 내보내기를 실행했다. 승인 메모는 네이티브 단위·통합검사 범위이며, 승인 메모에서도 실제 IME 키 입력을 시험했다고 주장하지 않는다. DB·Excel의 별도 대조와 파일 해시 등 최종 결과는 해당 검증 기록을 따른다. 검증한 EXE SHA-256은 `660615ae0bffd08c4b9db853fb713b746409b26ddd378fcb9560455eb47f3071`이다.

JS전자 시연의 실제 로컬 AI 초안은 v1.8.0에서 생성한 기준 자료를 재사용했다. 이번 편집기 변경에서 모델 재추론은 없으며 A04는 AI 내용 미승인 상태로 남겼다. 내용 승인과 별도 검토는 사용자가 직접 수행한다.

## 근거 기반 AI 조서 흐름

**계정/절차 선택 → AI 초안 생성 → 초안 보기·적용에서 근거·인용 검토 → 사람이 수정·저장 → AI 내용 최종 승인 → 별도 조서 검토 → Excel 출력** 순서다. OpenAI를 선택하면 실제 요청 전에 전송할 근거를 보여주고 이번 요청의 동의를 확인한다. 구체적인 버튼과 설정은 [v1.8 사용안내](문서/v1.8_사용안내.md), 로컬 AI 설치는 [로컬 AI 설치안내](문서/로컬AI_설치안내.md)를 따른다.

| 단계 | 저장·확인하는 것 |
| --- | --- |
| 근거 패킷 | 현재 회사·절차·자료/실행 버전, 원문 발췌·계산·원장 대사 참조와 생략 범위 |
| 실제 AI 응답 | 목적·위험·범위·수행내용·결론 5개 초안, 필드별 참조 ID, 모델·프롬프트·응답 원문 |
| 사람의 적용·수정 | AI 초안 적용 이력과 조서 개정. 실제 수행일·수령·실사·조회 완료 사실은 사람이 기록 |
| 최종내용 승인 | 승인한 조서 내용 해시·개정·자료 버전과 승인자·판단 메모 |
| 별도 조서 검토 | 기존 작성자와 다른 검토자의 필수 수행·증거·예외·검토 조건을 함께 확인 |

AI 초안은 미승인 상태로 시작한다. 자료·계산 실행이 바뀌면 새 근거로 AI 초안을 다시 생성하고 사람이 검토해야 한다. 조서를 다시 저장·수정하면 최종내용 재승인이 필요하다. AI 내용 승인과 별도 조서 검토 통제를 모두 충족해야 검토완료본을 출력할 수 있다. 이름 입력은 본인인증·전자서명이 아니다.

근거는 전체 문서를 무제한 전송하지 않는다. 화면은 12,000자·참조40개 이내, 표당3행·자료/실행별 최대8표·셀300자와 원문자료 최대2개 발췌로 패킷을 만든다. 선택 모듈·원장 실행을 우선하며, 미선택 자료·실행은 건수와 명세 해시를 남기고 전체 업무 버전에 포함한다. 엔진 직접 호출의 기본 한도24,000자·70참조·표5행·원문자료5개와 구별한다. 절단·생략 범위와 해시를 보존한다. 원문의 명령문은 비신뢰 데이터로 취급하며, 구조·인용 검증을 통과해도 모든 문장의 정확성이나 회계 판단을 보장하지 않는다.

로컬 실행환경은 사용자가 최초 준비를 실행할 때만 다운로드한다. 전용 폴더·프로필·루프백 서버를 사용하고 전역 Ollama·사용자 설정은 수정하지 않는다. 모델과 런타임은 공개 ZIP에 포함하지 않는다. OpenAI 키는 앱 실행 중 메모리로만 전달하며 설정·조서·이력에 저장하지 않는다. **실제 OpenAI 호출은 검증하지 않았으며**, 요청·응답·오류 통제의 모의 HTTP 검사와 구별한다.

## 조서 초안은 여기서 작성한다

**회사 선택 → 상단 조서초안 작성 → 계정/절차 선택 → 실제 수행·판단 작성 또는 AI 제안 검토·적용 → 조서 저장·개정 → 초안 Excel 내보내기** 순서다. **조서초안·작성** 탭에서도 같은 작성 화면을 열 수 있다.

목적·위험·범위·연결된 계산근거는 초안의 출발점이다. AI 제안을 사용할 때에도 실제 수행·판단·결론은 사용자가 확인하고 최종 내용을 승인한다. **조서 저장·개정**은 업무 DB에 저장하고, **초안 Excel 내보내기**는 그 내용을 정적 XLSX로 출력한다. v1.7.0의 **검토중 저장**에 대응하는 초안 출력이며, **검토완료본**과는 구분한다.

조서 입력영역은 오른쪽 스크롤로 아래의 증거·검토 항목까지 이동하고 저장·검토요청 버튼은 하단에 둔다. 폭이 충분하면 하단에도 초안 출력 버튼이 보이며, 좁아지면 **상단 초안 Excel 내보내기**를 사용한다. 화면이 작게 보이면 상단 화면 배율 90~175%를 조정한다. 구체적인 작성 경로·AI 설정·배율 사용법은 [v1.8 사용안내](문서/v1.8_사용안내.md)를 따른다.

좁은 창이나 큰 배율에서는 새 업무·업무 열기·계정별 증빙연습·로우데이터·자료 복사·검토완료본을 **기타 기능 ▾** 메뉴에서 찾는다. **조서초안 작성·초안 Excel 내보내기·화면 배율**은 상단에 남는다. 탭 제목이 잘려 보이면 **기타 기능 → 화면 이동**에서 전체 8개 화면을 선택할 수 있다.

## 실행과 회사 선택

1. [Releases](https://github.com/JoonseokWon/js-audit-suite/releases)에서 해당 버전의 Windows 묶음을 풀고 `실행파일/통합 회계감사 v1.8.1.exe`를 실행한다. EXE와 `portable-config.json`은 함께 둔다. 소스 이용자는 필요한 패키지를 설치한 뒤 `python app.py`를 실행한다.
2. 상단 **모회사·자회사**에서 연습할 회사를 고른다. 처음에는 내장 합성자료로 업무를 준비하고, 다시 선택하면 해당 회사의 최근 저장 업무를 연다.
3. **로우데이터**에서 선택한 회사 연습의 최초 더미 입력과 확인용 원천 Excel을 연다. **자료·검사 → 원장·리드 → 결과 상세** 순서로 입력 범위와 연결 결과를 확인한다. 이후 다시 등록·검사한 자료는 업무의 `원본/`에서 구분한다.
4. **조서초안 작성** 또는 **조서초안·작성**에서 실제 수행과 판단을 기록하고 **조서 저장·개정**으로 저장한다. 요청·수령 내역은 **자료요청**, 저장 이력은 **작업 이력**에서 확인한다.
5. 처음부터 반복하려면 **새 연습**을 누른다. 기존 업무·조서·요청·검토기록을 보존한 채 별도 폴더를 만든다.

새 화면 경로·AI·배율은 [v1.8 사용안내](문서/v1.8_사용안내.md), 계산·자료·보관의 공통 범위는 [v1.7 사용안내](문서/v1.7_사용안내.md)를 따른다. 준비·검사 도중에는 완료 또는 취소 안내를 기다린다. 회사 전환 전 미저장 입력의 저장·버리기·취소를 확인하며, 전환에 실패하면 기존 업무를 유지한다.

## 모회사와 자회사의 자료

| 회사 | 역할·자료 범위 | 예시 |
| --- | --- | --- |
| JS | 업종 없는 모회사, 축소 별도 원장 1개 모듈 | 현금·자회사투자주식·자본 |
| JS전자 | 전자부품·소재, 15개 모듈 | 전원제어모듈·솔더페이스트·SMT 검사장비 |
| JS자동차 | 자동차부품·가공소재, 15개 모듈 | 차량용제어센서·가공용 윤활제·가공검사장비 |
| JS반도체 | 검사용 합성 반도체·소재, 15개 모듈 | 패키지반도체·고순도실리카·검사장비 |
| JS바이오 | 연구용 시약·배지, 15개 모듈 | 연구용시약키트·분말배지·소분검사장비 |

JS 원장은 가상 납입 1,000만원, 각 자회사에 대한 투자 200만원씩 총 800만원, 잔여 현금 200만원으로 구성한다. 이는 별도 원장 동작을 위한 합성 가정이다. **지분율·투자주식 평가·실제 취득증빙·연결제거·연결재무제표 계산은 설정하거나 검사하지 않았다.** JS에 자회사 판매·재고·급여·제조업 자료를 복제하지 않는다.

자회사 자료는 동일 검사용 모본의 금액·수량·일자·단위·정책을 유지하면서 품목·자산·거래처·부서·적요를 업종에 맞춘 축소 시나리오다. 실제 시장가격·제조원가·수율을 추정한 데이터가 아니다. 판매 포장품 EA와 벌크 보관품 KG를 자동 환산한 것으로 보지 않는다.

## 대사는 어디까지 하는가

차대변 일치 외에도 다음을 검사한다. 검사마다 입력 범위와 단위가 다르므로 건수를 합쳐 전체 거래 검증률로 표현하지 않는다.

| 검사 단계 | 확인하는 것 | 남는 한계 |
| --- | --- | --- |
| 원장·리드 | 독립 통제값과 추출 행수·차대합계, 전표 차대, 계정별 GL 변동·TB 기말 연결 | 제출한 통제값 자체의 신뢰성·추출 완전성 |
| 계정별 계산 → TB | 이자·매출·감가상각·리스·대손·재고·급여·비용이연의 지원 지표와 연결 계정 비교 | 계산 가정·계약 실질·추정 판단 |
| 선택 원천 → 대상·원장 | 원문 위치·행·부호 금액, 명시 배부의 중복·누락·과배부, 현재 업무 GL/TB와 원천팩 비교 | 선택 밖 모집단·단위환산·증빙 진위 |
| 재무제표·주석 | 합계·소계·TB 매핑·선택 본문 및 주석 비교 | 조정후 마감본·모든 공시·PDF/OCR/XBRL 전반 |
| GLA·FIA·현금 | 현재 원장과 분석 모집단 연결, 명시 메타·정책·선택 은행거래의 검토후보 | 없는 메타·미제출 계좌·실제 행위와 부정 판단 |

자회사 정상 모본은 회사별 **15개 모듈·35개 원장 연결**, 원천팩의 **선택 원천 32행·대상 32행·명시 배부 32건**을 검사하도록 구성했다. 원문 16권·114표를 보존한 사실이 전체 표의 모든 거래를 대사했다는 뜻은 아니다. **원천 연결 미확인 범위 8개**도 결과에 남긴다. 세부 범위는 사용안내와 **결과 상세 → 원천증빙 → 연결범위**에서 확인한다.

원천과 원장·은행·통제값은 같은 생성기로 만든 합성자료다. 서로 다른 입력 사이의 수치·구조 검사를 시험하지만 **독립된 실제 감사증거는 아니다**. 일치만으로 실재성·완전성·권리·의무·진위나 감사 결론을 확정하지 않는다. 위험후보도 오류·부정 확정으로 분류하지 않는다.

## 재고와 급여는 별도 절차

**재고평가와 종업원급여는 별도 모듈·입력 파일·계산·조서**다. 재고는 A11, 급여는 A16에서 작성한다. 파일 탐색이나 예전 공통자료에 함께 보이는 항목이 있어도 같은 감사절차로 합치지 않는다. 현재 회사 입력과 구형 `samples/` 공통 모본의 과거 적요도 구분한다.

자회사 공통 모듈은 원장·리드, 금융상품, 매출, 감가상각, 확장검사, 리스, 대손충당금, 재고평가, 종업원급여, 미기록부채·비용이연, 원천증빙, 재무제표·주석, GLA, FIA, 현금분석이다. 별도 **계정별 증빙연습** 9개 계정군·33개 사례는 회사별 TB에 합산하지 않는다.

4개 자회사에 각 5개씩 총 20개 업종 검토주제와 60개 요청문서 템플릿을 연결한다. 그중 12개는 기존 수치 기능과 일부 연결되는 계획이며 8개는 전용 자동 계산이 없는 수동계획이다. 보증·리콜·공정재고·수율·개발비·위탁개발 수익 등을 이미 검사한 것으로 표시하지 않는다. JS 모회사에는 이 업종 계획을 적용하지 않는다.

## 자료요청·조서의 작업 이력

업무별 로컬 DB에 다음 저장 시점의 이벤트가 누적된다. **작업 이력**에서 시각·유형·대상과 저장 내용을 확인할 수 있다.

| 작업 | 기록되는 시점·내용 |
| --- | --- |
| 자료 등록·검사 | 등록한 원본 사본·SHA256과 검사 실행·결과 해시 |
| 자료요청 | **요청·수령 기록 저장**을 누른 요청처·기한·범위·상태·연결 증거. 상태를 바꿔 다시 저장하면 그 개정도 남음 |
| 조서 | **조서 저장·개정**의 작성자·내용·근거, 검토요청과 검토결과의 개정 |
| 검토의견 | 의견 저장·해결 상태를 저장한 내용과 입력한 이름 |
| AI 조서 | 실제 응답·근거 패킷 저장, 적용, 조서 개정, 사람의 최종내용 승인. 미완료·차단 응답은 유효 초안으로 저장하지 않음 |

저장 전 타이핑·요청 초안만 생성한 상태는 저장 이력이 아니다. 요청을 저장해도 이메일을 실제 발송하거나 자료를 받은 것으로 자동 처리하지 않는다. 자료요청에는 별도의 인증된 요청자 계정이 없고, 조서 작성자·검토자 이름도 사용자 입력값이다.

이력은 순서·이전 해시·DB 헤드와 원본 해시로 무결성을 검사한다. **로그인 본인인증·인증 전자서명·외부 불변 로그를 제공하는 것은 아니다.** DB·헤드·프로그램 모두를 관리하는 사용자를 상대로 한 독립 증명으로 표현하지 않는다. AI 제안의 생성·적용은 실제 감사 수행·최종내용 승인·별도 검토를 자동 완료하지 않으며 새 조서는 미검토 초안이다.

## 로우데이터와 기록의 위치

- **로우데이터**: 회사 선택으로 만든 v1.7 연습 폴더를 연다. `inputs/`에 최초 더미 입력, `metadata/`에 회사 설정, 자회사의 `원천엑셀/`에 원천 16권이 있다. JS 모회사는 모회사 원장과 범위 설정을 제공하며 자회사 원천팩을 포함하지 않는다. 일반 수동 업무·구버전 업무는 등록 원본 위치를 확인한다.
- **원본/**: 실제 검사·증거 등록 시 보관한 해시 고정 사본이다. 확인용 Excel을 수정해도 이미 실행한 결과는 바뀌지 않는다. 수정 파일을 다시 등록·실행하고 조서를 다시 저장·검토해야 한다.
- **내장 `sector_resources/companies/`**: 회사별 읽기 전용 모본이다. EXE에서는 내부 리소스로 포함될 수 있으므로 앱의 자료 열기·복사 기능을 사용한다.
- **구형 `samples/`, `raw_input_seed/`, `testdata/`**: 회귀 검사·독립 사례·과거 모본이다. 폴더명이 현재 회사 원문을 뜻하지 않는다.

v1.8.1 포터블 실행본의 회사별 업무 위치는 `portable-config.json`이 지정하는 `데이터/회사별업무/`다. 기존 v1.8.0과 별도 포터블 설정이 없는 실행 환경의 기본 위치는 `%LOCALAPPDATA%\JSAudit\sector-demos\v1.7`이다. 회사별 최근 연습 목록과 이전 연습을 모두 보존하려면 해당 보관 위치 전체를 백업한다. 개별 업무를 옮길 때는 `업무.sqlite3`·`이력헤드.json`·`원본/`을 포함한 업무 폴더 전체를 함께 보관하고 이관 검증을 따른다. 이미 출력한 Excel은 정적 사본이다.

## 검증 재현과 공개 범위

소스 실행과 화면 없는 검사의 기본 절차는 다음과 같다. 검증 출력은 새 폴더 또는 빈 폴더를 사용한다.

```powershell
python -m pip install -r requirements.txt
python app.py
python -m unittest discover -v
python tools/verify_headless_v17.py --output-dir 검증/직접재현_v17_headless
```

검증 완료 수치·소스 UI와 EXE의 결과·EXE SHA256은 해당 배포의 검증 기록을 따른다. 이전 버전의 통과 수치로 새 버전의 실행 확인을 대신하지 않는다. 현재 배포 대상은 [v1.8.1 릴리스](https://github.com/JoonseokWon/js-audit-suite/releases/tag/v1.8.1)이며 이 링크의 작성만으로 게시 완료를 뜻하지 않는다. [v1.8.0 릴리스](https://github.com/JoonseokWon/js-audit-suite/releases/tag/v1.8.0)는 실제 AI 조서 기준 자료와 이전 배포 이력으로 보존한다. [GitHub Actions](https://github.com/JoonseokWon/js-audit-suite/actions)와 [릴리스 기록](https://github.com/JoonseokWon/js-audit-suite/releases)에서 원격 검사와 실제 배포 상태를 확인한다.

이 공개 저장소에는 감사 프로그램과 합성자료를 담는다. 기존 개인 프로젝트 저장소의 메일·지원 이력은 공개 대상이 아니다. 실제 고객자료를 추가해 공개하지 않는다. 공개된 회계·업종 자료는 기능 설계의 참고이며 실제 적용 여부와 해당 기간의 기준·정책은 감사인이 확인한다.
