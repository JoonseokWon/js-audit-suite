# JS Audit Suite — 통합 회계감사 v1.7

회사별 합성 로우데이터로 계산·원장 연결·예외 검토·조서 작성 흐름을 연습하는 Windows 로컬 감사 지원 프로그램이다. **JS는 업종 없는 모회사**, JS전자·JS자동차·JS반도체·JS바이오는 업종별 자회사로 구분한다.

회계 요구사항과 검증 관점은 사용자가 설계하고 AI가 코드 구현과 자동 검사를 보조했다. 앱 자체는 입력과 명시적 정책을 사용하는 로컬 규칙 기반이며 외부 AI 추론·자료 전송을 수행하지 않는다. 계산 결과가 감사의견이나 기준 준수 인증을 뜻하지 않는다.

## 실행과 회사 선택

1. [Releases](https://github.com/JoonseokWon/js-audit-suite/releases/tag/v1.7.0)에서 Windows 묶음을 풀고 EXE를 실행한다. 소스 이용자는 필요한 패키지를 설치한 뒤 `python app.py`를 실행한다.
2. 상단 **모회사·자회사**에서 연습할 회사를 고른다. 처음에는 내장 합성자료로 업무를 준비하고, 다시 선택하면 해당 회사의 최근 저장 업무를 연다.
3. **로우데이터**에서 선택한 회사 연습의 최초 더미 입력과 확인용 원천 Excel을 연다. **자료·검사 → 원장·리드 → 결과 상세** 순서로 입력 범위와 연결 결과를 확인한다. 이후 다시 등록·검사한 자료는 업무의 `원본/`에서 구분한다.
4. **절차·조서**에 실제 수행과 판단을 기록하고 저장한다. 요청·수령 내역은 **자료요청**, 저장 이력은 **작업 이력**에서 확인한다.
5. 처음부터 반복하려면 **새 연습**을 누른다. 기존 업무·조서·요청·검토기록을 보존한 채 별도 폴더를 만든다.

자세한 화면 순서와 자료 위치는 [v1.7 사용안내](문서/v1.7_사용안내.md)를 따른다. 이전 버전 문서와 다른 내용은 이 안내를 우선한다. 준비·검사 도중에는 완료 또는 취소 안내를 기다린다. 회사 전환 전 미저장 입력의 저장·버리기·취소를 확인하며, 전환에 실패하면 기존 업무를 유지한다.

## 모회사와 자회사의 자료

| 회사 | 역할·자료 범위 | 예시 |
| --- | --- | --- |
| JS | 업종 없는 모회사, 축소 별도 원장 1개 모듈 | 현금·자회사투자주식·자본 |
| JS전자 | 전자부품·소재, 15개 모듈 | 전원제어모듈·솔더페이스트·SMT 검사장비 |
| JS자동차 | 자동차부품·가공소재, 15개 모듈 | 차량용제어센서·가공용 윤활제·가공검사장비 |
| JS반도체 | 검사용 합성 반도체·소재, 15개 모듈 | 패키지반도체·고순도실리카·검사장비 |
| JS바이오 | 연구용 시약·배지, 15개 모듈 | 연구용시약키트·분말배지·소분검사장비 |

JS 원장은 가상 납입 1,000만원, 각 자회사에 대한 투자 200만원씩 총 800만원, 잔여 현금 200만원으로 구성한다. 이는 별도 원장 동작을 위한 합성 가정이다. **지분율·투자주식 평가·실제 취득증빙·연결제거·연결재무제표 계산은 설정하거나 검사하지 않았다.** JS에 자회사 판매·재고·급여·제조업 자료를 복제하지 않는다.

자회사 자료는 동일 검사용 모본의 금액·수량·일자·단위·정책을 유지하면서 품목·자산·거래처·부서·적요를 업종에 맞춘 축소 시나리오다. 실제 시장가격·제조원가·수율을 추정한 데이터가 아니다. 판매 포장품 EA와 벌크 보관품 KG를 자동 환산한 것으로 보지 않는다.

## 대사는 어디까지 하는가

차대변 일치 외에도 다음을 검사한다. 검사마다 입력 범위와 단위가 다르므로 건수를 합쳐 전체 거래 검증률로 표현하지 않는다.

| 검사 단계 | 확인하는 것 | 남는 한계 |
| --- | --- | --- |
| 원장·리드 | 독립 통제값과 추출 행수·차대합계, 전표 차대, 계정별 GL 변동·TB 기말 연결 | 제출한 통제값 자체의 신뢰성·추출 완전성 |
| 계정별 계산 → TB | 이자·매출·감가상각·리스·대손·재고·급여·비용이연의 지원 지표와 연결 계정 비교 | 계산 가정·계약 실질·추정 판단 |
| 선택 원천 → 대상·원장 | 원문 위치·행·부호 금액, 명시 배부의 중복·누락·과배부, 현재 업무 GL/TB와 원천팩 비교 | 선택 밖 모집단·단위환산·증빙 진위 |
| 재무제표·주석 | 합계·소계·TB 매핑·선택 본문 및 주석 비교 | 조정후 마감본·모든 공시·PDF/OCR/XBRL 전반 |
| GLA·FIA·현금 | 현재 원장과 분석 모집단 연결, 명시 메타·정책·선택 은행거래의 검토후보 | 없는 메타·미제출 계좌·실제 행위와 부정 판단 |

자회사 정상 모본은 회사별 **15개 모듈·35개 원장 연결**, 원천팩의 **선택 원천 32행·대상 32행·명시 배부 32건**을 검사하도록 구성했다. 원문 16권·114표를 보존한 사실이 전체 표의 모든 거래를 대사했다는 뜻은 아니다. **원천 연결 미확인 범위 8개**도 결과에 남긴다. 세부 범위는 사용안내와 **결과 상세 → 원천증빙 → 연결범위**에서 확인한다.

원천과 원장·은행·통제값은 같은 생성기로 만든 합성자료다. 서로 다른 입력 사이의 수치·구조 검사를 시험하지만 **독립된 실제 감사증거는 아니다**. 일치만으로 실재성·완전성·권리·의무·진위나 감사 결론을 확정하지 않는다. 위험후보도 오류·부정 확정으로 분류하지 않는다.

## 재고와 급여는 별도 절차

**재고평가와 종업원급여는 별도 모듈·입력 파일·계산·조서**다. 재고는 A11, 급여는 A16에서 작성한다. 파일 탐색이나 예전 공통자료에 함께 보이는 항목이 있어도 같은 감사절차로 합치지 않는다. 현재 회사 입력과 구형 `samples/` 공통 모본의 과거 적요도 구분한다.

자회사 공통 모듈은 원장·리드, 금융상품, 매출, 감가상각, 확장검사, 리스, 대손충당금, 재고평가, 종업원급여, 미기록부채·비용이연, 원천증빙, 재무제표·주석, GLA, FIA, 현금분석이다. 별도 **계정별 증빙연습** 9개 계정군·33개 사례는 회사별 TB에 합산하지 않는다.

4개 자회사에 각 5개씩 총 20개 업종 검토주제와 60개 요청문서 템플릿을 연결한다. 그중 12개는 기존 수치 기능과 일부 연결되는 계획이며 8개는 전용 자동 계산이 없는 수동계획이다. 보증·리콜·공정재고·수율·개발비·위탁개발 수익 등을 이미 검사한 것으로 표시하지 않는다. JS 모회사에는 이 업종 계획을 적용하지 않는다.

## 자료요청·조서의 작업 이력

업무별 로컬 DB에 다음 저장 시점의 이벤트가 누적된다. **작업 이력**에서 시각·유형·대상과 저장 내용을 확인할 수 있다.

| 작업 | 기록되는 시점·내용 |
| --- | --- |
| 자료 등록·검사 | 등록한 원본 사본·SHA256과 검사 실행·결과 해시 |
| 자료요청 | **요청·수령 기록 저장**을 누른 요청처·기한·범위·상태·연결 증거. 상태를 바꿔 다시 저장하면 그 개정도 남음 |
| 조서 | **조서 저장·개정**의 작성자·내용·근거, 검토요청과 검토결과의 개정 |
| 검토의견 | 의견 저장·해결 상태를 저장한 내용과 입력한 이름 |

저장 전 타이핑·요청 초안만 생성한 상태는 저장 이력이 아니다. 요청을 저장해도 이메일을 실제 발송하거나 자료를 받은 것으로 자동 처리하지 않는다. 자료요청에는 별도의 인증된 요청자 계정이 없고, 조서 작성자·검토자 이름도 사용자 입력값이다.

이력은 순서·이전 해시·DB 헤드와 원본 해시로 무결성을 검사한다. **로그인 본인인증·인증 전자서명·외부 불변 로그를 제공하는 것은 아니다.** DB·헤드·프로그램 모두를 관리하는 사용자를 상대로 한 독립 증명으로 표현하지 않는다. 계산·수행·결론·검토 승인을 자동 완료하지 않으며 새 조서는 미검토 초안이다.

## 로우데이터와 기록의 위치

- **로우데이터**: 회사 선택으로 만든 v1.7 연습 폴더를 연다. `inputs/`에 최초 더미 입력, `metadata/`에 회사 설정, 자회사의 `원천엑셀/`에 원천 16권이 있다. JS 모회사는 모회사 원장과 범위 설정을 제공하며 자회사 원천팩을 포함하지 않는다. 일반 수동 업무·구버전 업무는 등록 원본 위치를 확인한다.
- **원본/**: 실제 검사·증거 등록 시 보관한 해시 고정 사본이다. 확인용 Excel을 수정해도 이미 실행한 결과는 바뀌지 않는다. 수정 파일을 다시 등록·실행하고 조서를 다시 저장·검토해야 한다.
- **내장 `sector_resources/companies/`**: 회사별 읽기 전용 모본이다. EXE에서는 내부 리소스로 포함될 수 있으므로 앱의 자료 열기·복사 기능을 사용한다.
- **구형 `samples/`, `raw_input_seed/`, `testdata/`**: 회귀 검사·독립 사례·과거 모본이다. 폴더명이 현재 회사 원문을 뜻하지 않는다.

기본 업무 보관 위치는 `%LOCALAPPDATA%\JSAudit\sector-demos\v1.7`이다. 회사별 최근 연습 목록과 이전 연습을 모두 보존하려면 이 위치 전체를 백업한다. 개별 업무를 옮길 때는 `업무.sqlite3`·`이력헤드.json`·`원본/`을 포함한 업무 폴더 전체를 함께 보관한다. 이미 출력한 Excel은 정적 사본이다.

## 검증 재현과 공개 범위

소스 실행과 화면 없는 검사의 기본 절차는 다음과 같다. 검증 출력은 새 폴더 또는 빈 폴더를 사용한다.

```powershell
python -m pip install -r requirements.txt
python app.py
python -m unittest discover -v
python tools/verify_headless_v17.py --output-dir 검증/직접재현_v17_headless
```

검증 완료 수치·소스 UI와 EXE의 결과·EXE SHA256은 해당 배포의 검증 기록을 따른다. 이전 버전의 통과 수치로 새 버전의 실행 확인을 대신하지 않는다. [GitHub Actions](https://github.com/JoonseokWon/js-audit-suite/actions)와 [릴리스 기록](https://github.com/JoonseokWon/js-audit-suite/releases/tag/v1.7.0)에서 원격 검사와 배포 상태를 확인한다.

이 공개 저장소에는 감사 프로그램과 합성자료를 담는다. 기존 개인 프로젝트 저장소의 메일·지원 이력은 공개 대상이 아니다. 실제 고객자료를 추가해 공개하지 않는다. 공개된 회계·업종 자료는 기능 설계의 참고이며 실제 적용 여부와 해당 기간의 기준·정책은 감사인이 확인한다.
