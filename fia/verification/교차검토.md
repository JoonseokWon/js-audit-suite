# GLA·현재원장·검토 흐름 교차검토

FIA 워커가 `gla/`, `analytics_support.py`, `workspace.py`, `review_support.py`를 읽기 전용으로 확인했다. 아래 반례는 정상 샘플을 임시 폴더에 복사·변형하여 Python 3.14.8에서 재현했다. 원본과 다른 담당 코드·테스트는 수정하지 않았다. FIA 단위 테스트 수는 25개 그대로다.

## 1. 여러 원장 행을 개별 대응 확인으로 표시

정상 J-I의 차변 36,400원을 같은 계정의 18,200원 두 행으로 나누고 새 행ID를 부여했다. TB·차대총액은 그대로이고 독립통제의 해당 계정 행수만 1 늘렸다. 원장과 GLA 모두 차단 0으로 적법하게 분석한다.

그러나 `전표계정조합`은 원장행수 3인데 `대응구분=단순 1:1`, `개별대응확인=true`다. 구현은 차변 계정집합과 대변 계정집합의 원소 수가 각각 1인지만 검사한다. 계정 집합의 1:1과 실제 행의 1:1 대응을 구분해야 한다. 적법한 분할 전표를 차단할 필요는 없으나 개별행 대응 확인으로 표시해서는 안 된다.

제안: 개별 대응을 정말 확인한다면 양쪽에 실질 행이 하나씩인지도 검사한다. 계정 단위 집계만 의미한다면 필드·표시명을 계정집합 관계로 바꾸고 행별 대응은 미확인으로 유지한다.

## 2. 다른 업무 인스턴스의 원장 갱신 후 옛 후보로 요청 초안 생성

재현 순서:

1. 같은 업무 폴더를 연 ws1에서 정상 원장과 GLA를 실행하고 후보키를 보관한다.
2. ws2로 같은 폴더를 열어 동일 원장 파일을 다시 실행한다. 값은 같아도 현재 원장 실행ID는 바뀐다.
3. ws2의 후보 연결상태는 `차단·재실행 필요`다.
4. 갱신하지 않은 ws1에서는 `collect_candidates`가 `현재원장 연결`로 표시하고 `candidate_request_draft`도 성공한다.

`collect_candidates`와 `request_draft`는 처음에 DB를 refresh하지 않아 오래된 ws1의 실행 캐시를 현재 실행으로 취급한다. 원본 사본의 해시 확인만으로 실행 버전 변경을 확인할 수는 없다. 최종 snapshot과 조서 검토의 별도 refresh·차단을 우회한 것으로 확인한 것은 아니며, 후보 안내와 추가자료 요청 초안의 현재 버전 표시가 잘못되는 반례다.

제안: 후보 수집·요청 초안을 만들기 전에 업무를 갱신하고 현재 원장·분석 실행을 다시 확인한다. UI의 자체 refresh에만 의존하지 않는다.

## 3. 반복 후보 사유가 그룹 전체 ID를 후보마다 중복 보존

같은 계정·금액의 서로 다른 전표들을 구성하고 TB·독립통제를 정확히 갱신했다. 반복 규칙만 켰으며 각각 원장·GLA 차단은 0이다.

| 입력 | 후보 수 | 후보 사유 UTF-8 바이트 합계 | 후보 하나의 최대 글자 수 | 분석 시간 |
|---|---:|---:|---:|---:|
| 원장 200행·전표 100건 | 100 | 305,000 | 3,025 | 0.081초 |
| 원장 800행·전표 400건 | 400 | 4,820,000 | 12,025 | 0.205초 |

GLA_REPEAT가 같은 반복 그룹의 전체 전표ID 목록을 그 그룹의 모든 후보 사유에 다시 연결한다. 이 부분은 전표 수의 제곱에 비례하여 늘어나며 issue 메시지에도 내용이 복제된다. 10,000행 전체 실행은 기기 메모리를 불필요하게 압박하지 않기 위해 하지 않았다. 동일 코드와 ID 길이를 그대로 확장하면 5,000건 반복 그룹에서 사유 문자열만 수백 MB가 되는 계산상 위험이 있다. 이는 측정한 10,000행 성능이라고 주장하지 않는다.

제안: 반복 그룹 ID·총건수와 짧은 사유를 후보에 남기고 전체 구성원은 별도 그룹/원문 표에 한 번 보존한다. 각 후보의 원본행은 그대로 유지한다. 표시 문자열을 잘라내기만 하고 원문 연결까지 버려서는 안 된다.

## 추가 확인한 정상 통제

- 원장 행 순서만 뒤집고 실제 값·복합키를 보존한 입력은 차단 0, 현재원장 연결 true, 같은 24개 후보를 유지했다. 원문 행 위치는 새 입력 위치로 연결한다.
- J-I 차대에 각각 1원을 더하고 TB·독립통제까지 갱신한 자체 일관 입력도 현재 업무 원장과는 다르므로 `AN_LEDGER_DIFF` 3개로 차단되었고 후보는 0개였다. 숫자 차이를 무시하는 반례는 찾지 못했다.
- 같은 복합키 원장 행을 복사한 입력은 `AN_INPUT_LEDGER`, `AN_LEDGER_DIFF`로 차단되고 후보 0개였다.
- GLA는 입력시각·수동자동·승인 데이터가 없다는 점을 별도의 미확인 규칙으로 표시하며, 전기일·작성자·적요만으로 이를 추정하지 않는다. 위 세 보완점과 별도로 이 기본 범위는 유지되어야 한다.

이 메모는 교차검토 시점의 관찰이다. 수정·재검증 완료 여부는 담당 워커와 PM의 후속 기록으로 확인한다.
